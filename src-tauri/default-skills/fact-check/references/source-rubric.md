# Source Rubric

1. Use the current repository source of truth for project facts: applicable instructions, configuration, code, tests, then current project documentation.
2. Use the governing official source for laws, standards, product documentation, releases, schedules, and public records.
3. Use primary research or the original publication for scientific results, statistics, and quotations.
4. Use package registries and official changelogs for package existence and released versions.
5. Use secondary sources only when the primary source is unavailable, and label the limitation.
6. Match source date, version, jurisdiction, platform, and scope to the claim.
7. Treat silence as unresolved, not contradicted.
8. Treat two applicable authoritative disagreements as a conflict unless a newer or governing source clearly supersedes one.

## Optional memory suggestion

You suggest a fact for later memory only when it is verified, stable across normal releases, reusable beyond the current answer, safe to retain, and backed by a durable project or primary source. You never suggest secrets, personal data, temporary state, predictions, or disputed claims. You never persist the suggestion in this skill.
