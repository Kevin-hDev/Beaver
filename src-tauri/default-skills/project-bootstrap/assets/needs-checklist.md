# Project Bootstrap Checklist

Complete all 24 items. Fill Blocks 1–3 from user input and reserve Block 4 for the audited selection. Use not applicable only with a concrete reason.

## Block 1 - Project and users

- [ ] **Project name** — <name>
- [ ] **One-line value proposition** — <who gains what outcome>
- [ ] **Project type** — <SaaS | web | mobile | desktop | CLI | library | service/API | data/ML | internal tool | other>
- [ ] **Target users or consumers** — <profiles, environments, and estimated six-month volume>
- [ ] **Top three to five capabilities** — <observable outcomes>
- [ ] **External integrations** — <systems, protocols, registries, devices, data sources, or none>
- [ ] **Delivery surfaces** — <browser, mobile OS, desktop OS, terminal, package registry, API, batch, embedded, or other>

## Block 2 - Technical and operational constraints

- [ ] **Interaction and real-time needs** — <request/response, streaming, live sync, events, device I/O, or not applicable with reason>
- [ ] **Isolation or tenancy** — <single user, local, shared, workspaces, customer isolation, process isolation, or not applicable with reason>
- [ ] **Security and data sensitivity** — <public, business, personal, regulated, threat assumptions, region, compliance>
- [ ] **Six-month scale** — <users, requests/day, records, data size, jobs, events, downloads, installations, or calls>
- [ ] **Discovery and distribution** — <SEO, app stores, package registries, enterprise rollout, API discovery, private distribution, or not applicable with reason>
- [ ] **Performance target** — <p95 latency, throughput, startup time, memory, binary or bundle size, job duration, or other measurable target>
- [ ] **Offline and network constraints** — <offline behavior, sync, intermittent links, air-gapped use, local-only use, or not applicable with reason>

## Block 3 - Team and delivery constraints

- [ ] **Team skills and capacity** — <languages, frameworks, operations experience, team size, ownership>
- [ ] **Budget** — <monthly operating ceiling, one-time tooling or distribution budget, support budget>
- [ ] **Deployment or distribution preference** — <managed, self-hosted, cloud, on-device, stores, registries, private package, binary, no opinion>
- [ ] **Deal-breakers** — <excluded technologies, vendors, licenses, regions, operational models, or none>

## Block 4 - Derived and user-approved choices

- [ ] **Architecture pattern** — <monolith, modular monolith, services, event-driven, pipeline, library modules, plugin system, serverless, other>
- [ ] **Client or interface** — <web front end, native UI, desktop UI, CLI surface, public API, library API, notebooks, or none>
- [ ] **Back end or core runtime** — <framework, language, process model, execution environment>
- [ ] **Data or storage** — <database, files, cache, object store, embedded storage, no persistence>
- [ ] **Identity, access, and security** — <authentication, authorization, local trust model, signing, sandboxing, secret boundary>
- [ ] **Final deployment or distribution** — <concrete hosting, runtime, registry, store, package, image, binary, or installation channel>
