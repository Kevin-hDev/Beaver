# Candidate Audit Rubric

Give one isolated reviewer this rubric with one candidate and the complete confirmed needs. Require direct evidence and prohibit access to other candidate reviews or a preferred winner.

## Review dimensions

1. Verify that components, versions, protocols, platforms, deployment or distribution mechanisms, and trust boundaries work together.
2. Verify maintenance status, production maturity, documentation, license, ecosystem, platform support, and team-operability.
3. Search current official documentation, release notes, advisories, limits, and pricing. Use recent primary issue evidence for known blockers when available.
4. Test the candidate against every applicable scale, performance, security, privacy, integration, offline, budget, and ownership constraint.
5. Recalculate monthly operating cost at the six-month scale and relevant one-time or distribution costs from dated assumptions.

## Verdicts

- Use pass only when no known blocker or unresolved material constraint remains.
- Use warning only when every concern has a plausible mitigation that the user can own and verify.
- Use broken when a hard constraint, unsupported combination, inaccessible required evidence, unacceptable risk, or budget boundary prevents a defensible design.

## Required response

Return exactly three bullets:

1. State compatibility and maturity findings with direct evidence.
2. State checklist fit, known risks, and any mitigation preconditions.
3. State cost realism, evidence date, assumptions, and confidence.
