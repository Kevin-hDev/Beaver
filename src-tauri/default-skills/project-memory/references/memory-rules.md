# Memory Rules

Write memory that captures durable, non-derivable project context.

- Capture current decisions, conventions, boundaries, gotchas, and supported rationale.
- Point to source paths instead of copying schemas, code, generated output, or full directory trees.
- Keep one fact in its canonical mapped file and cross-reference it elsewhere.
- Use short bullets, concise tables, and only diagrams that clarify a real relationship.
- Name technologies without volatile versions unless the version itself is a project constraint.
- Include commands only when a repository script, manifest, or project instruction proves them.
- Remove unused sections, template guidance, placeholders, future work, personal notes, and secret values.
- Preserve exact user-authored text until a specific change receives approval.
