# LLM 代理

LLM 从当前对话中驱动 Forecast。它可以准备或检索数据、审核质量、选择获准模型、运行计算并解释结果。

## 必须遵循的流程

针对每个新数据集，请按以下顺序执行：

1. 明确目标、周期、预测范围和请求的置信水平。
2. 读取或构建数据，并区分数据来源。
3. 调用 `forecast_data_audit`。
4. 修复阻塞错误，或向用户解释错误。
5. 使用已验证档案调用 `forecast_models`。
6. 在手动模式中遵守强制模型并检查精确兼容性。
7. 在自动模式中只选择一个返回候选。
8. 使用档案、获准模型和不变的置信水平调用 `forecast`。
9. 使用 `forecast_read` 读取所需页面和分析。
10. 解释预测、不确定性和限制。

数据、目标、频率、范围或置信水平变化时，请重新审核。

## 手动模式

不要修改用户保存的选择。模型缺失、未准备好或不兼容时，请要求用户执行明确操作，不要静默换成其他模型。

## 自动模式

请选择一个返回候选，不要绕过后端排除规则。只有 Forecast 确认用户明确指定的模型仍然安全时，才可以使用它。

请把选择 ID 和允许的简短理由传给 `forecast`。不要把仅基于能力和资源的选择称为最佳模型。

## 评估与比较

用户要求最佳模型或可靠比较时：

1. 对兼容模型运行 `forecast_backtest`。
2. 检查整体状态和单个失败项。
3. 使用 `forecast_compare_models` 读取排名。
4. 与 Naive、Seasonal Naive、Drift 和 ETS 比较。
5. 说明误差、覆盖率、速度和内存之间的权衡。

不要把部分回测描述成完整结果，也不要把未超过可信基准的模型称为最佳。

## 来源与解释

请始终说明数值来自文件、外部来源、计算还是场景假设。不要静默编造重要数据。

请使用现有对话进行解释、比较或重跑，并诚实说明不可用或可靠性较低的高级分析。
