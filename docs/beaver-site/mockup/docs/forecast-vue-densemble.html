Extending a series into the future

Forecast takes a series of dated values and extends it over a number of periods you choose. This page is the section's front door: it says what the workspace is for, where it lives, and tells the full journey of a forecast. Each step then has its own page.

Forecast in four sentences Forecast extends a series of dated values and returns a range, not a single curve. It lives in the side panel of an Agent conversation, next to the file preview, and unfolds into a separate window when it needs room. Your data is checked before the calculation: a blocking flaw stops the forecast instead of producing a misleading result. The result is saved with its data and its provenance record, and can be reopened, annotated and exported later.

What Forecast is for

Revenue month by month, consumption hour by hour, a number of orders per day: you give the series, Forecast gives what comes next. Three things set it apart from simply extending a curve.

  • The result is not a single curve but a range. Every predicted point carries three values — low, median, high — derived from the requested confidence level. Only models capable of producing that range are accepted.
  • The data is audited before the calculation, and a blocking flaw stops the forecast rather than producing a misleading result. See Data and audit.
  • The result is saved with its input data, its data profile and the record of the model chosen. It can be reopened, compared, annotated and exported later.

Where it lives in Beaver

Forecast is not a separate tab in the application. It is one of the modes of an Agent conversation's shared side panel. The button that opens the selector carries the “Panel mode” tooltip.

The side-panel modes of a conversation
ModeAlways offered
File previewYes — it's the default mode
ForecastYes
BrowserNo — the entry disappears when the built-in browser is unavailable
Note The panel mode, the open section and the analysis displayed are remembered per conversation. You can leave a forecast open in one thread while you work on something else in another: opening a second conversation changes nothing about what the first one was showing.

What you need before you start

A data file. The selector accepts six extensions: csv, tsv, xlsx, xls, ods, xlsm. The detail of what it must contain is in Data and audit.

A usable model. Two routes, at least one is needed: an installed local model, downloaded from the Forecast models screen — the calculation refuses to start until it is, with “Model not installed”; or the remote model from the catalog, the only one that requires an API key — with no key saved, the calculation stops with “Nixtla API key not configured”. Every other provider runs on your machine.

Memory room for a local model. Before launching, Beaver checks that the machine can carry the model and refuses otherwise, with “Insufficient resources for this model”. The mechanism is described in Model selection.

Warning No model, no forecast. You need either an installed local model or an API key for the remote model. The calculation stops cleanly in both missing cases.

The journey, end to end

Seven steps. The first five are visible, the last two happen on their own.

1. The home screen. As long as no analysis is open, the panel shows “No analysis in progress” and, as a subtitle, “Ask the agent”. Three buttons follow: Import file (CSV, Excel), active; Paste data and From URL, both inactive, with the “Coming soon” tooltip. Below those buttons, the Recent analyses list lets you reopen an already-computed analysis, with its name, its model, its horizon and its mean error when it exists.

Note Today, importing a file is the only data entry point from the screen. The other two buttons are present and inactive — if you see them greyed out, you haven't done anything wrong. Going through the agent is the second available route.

2. Reading the file. The file is converted into a table of rows, with strict bounds applied before any content check. Exceeding one shows “Import failed. Check the file format.” Two useful gestures are performed automatically at that moment: a column with no header receives a fallback name column_1, column_2… and a number written with a decimal comma is recognised as a number.

3. The Configuration screen. Eight settings, with their starting values.

The eight settings of the Configuration screen and their starting value
SettingWhat it designatesStarting value
TargetThe column to forecastThe file's 2nd column
Date columnThe timestampThe file's 1st column
Series columnWhat separates several seriesNone — “No series column”
CovariatesThe explanatory columnsNone; clickable chips
HorizonThe number of periods to forecast12

The eight frequencies offered are Minute, Hour, Day, Business day, Week, Month, Quarter and Year. The launch button reads “Launch forecast”, then “Calculating…” while the work runs. It stays inactive until a target, a date column, a model and a horizon greater than zero are all filled in.

4. The pre-calculation checks. In order: normalising the request, reading the selection policy, applying that policy, re-reading the file if needed, validating the request, auditing the data, then checking that the requested model is indeed acceptable. A blocking flaw at any of these steps stops everything.

5. The calculation. For a remote model, Beaver retrieves the key and queries the service. For a local model, it checks the installation and the resources, starts the engine, computes, then schedules the engine to stop after a period of inactivity.

6. Saving. The result receives its provenance record — which model, on which data, for what reason, in how much time — then the data profile and the analysis are written to disk.

7. Display. The panel switches to the main view of the new analysis.

On failure, a single generic message appears: “The calculation failed. Check the columns, model, and API key.” — except for one named case, full storage, which shows “Forecast storage is full. Delete older analyses, then try again.”

The panel and the workspace

This is the most important structural point on the page, and it isn't obvious in use.

The side panel is narrow and deliberately tight. It offers only three sections: Main view, the forecast chart and its layers; Comparisons, several analyses set side by side; History, the list of saved analyses.

The “Forecast workspace” window is a separate, resizable window that finds its position again from one time to the next. It offers seven sections, with the description the application gives them.

The seven sections of the Forecast workspace window
SectionDescription shown
Data“Inspect the data, its mapping, and quality checks.”
Forecast“Review the complete forecast and its available layers.”
Evaluation“Measure models with baselines and temporal validation.”
Comparison“Compare model quality, speed, and constraints.”
Scenarios“Create and edit assumptions without losing the reference forecast.”
Notes“Create, organize, and review notes linked to this forecast.”
Report“Collect provenance, notes, and advanced exports.”

Only one window at a time: reopening the workspace while it is already open brings it to the front instead of creating a second one. The analysis shown in the window follows the panel's.

Key point The panel shows, the window works. The panel has only three sections; the raw data, the quality checks, the evaluation, the scenarios and the report are in “Forecast workspace”.

A built-in technical documentation also exists, in its own window, under the title “Forecast documentation”. It covers a dozen topics, including datasets, models, evaluation, uncertainty, covariates, multi-series, scenarios and limits.

A saved analysis weighs at most 64 MB. Analyses are filed by workspace — a project or a conversation: what was computed in one conversation doesn't appear in another one's list.

The same work from the conversation

The empty screen's subtitle, “Ask the agent”, isn't decorative: the agent has seven Forecast tools and can do the whole journey for you. Those tools are off by default and are turned on in the agent's settings — see Forecast, on the tools side.

The agent's seven Forecast tools
ToolWhat it does
forecast_data_auditChecks the data and fixes a reusable profile
forecast_modelsInspects the selection policy and offers the usable models
forecast_runLaunches the forecast
forecast_backtestMeasures models over past windows
forecast_compare_modelsRe-reads the ranking obtained
forecast_analyzeAdds an annotation, a scenario, an ensemble
forecast_readRe-reads a saved analysis

The result the agent produces is the same analysis as the one produced by the screen: it opens in the panel, exports and gets annotated the same way.
