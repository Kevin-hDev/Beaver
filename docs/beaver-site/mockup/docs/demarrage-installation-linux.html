Installation sur Linux

Beaver est distribué en paquet .deb pour Debian et Ubuntu en x64. Le script d'installation vérifie l'empreinte du paquet et ses métadonnées avant de l'installer.

Debian et Ubuntu uniquement Le script d'installation ne prend en charge que les distributions de la famille Debian, en x64. Fedora, RHEL, Arch et openSUSE ne sont pas gérés.

Distributions prises en charge

Debian et Ubuntu, architecture x64 uniquement. Le paquet est construit sur Ubuntu 22.04, ce qui le rend compatible avec 22.04, 24.04 et 25.04 : la bibliothèque C standard étant rétro-compatible vers le haut, construire sur la plus ancienne cible couvre les suivantes. Il n'y a pas de build ARM.

La méthode recommandée : le script

C'est la même commande que sur macOS ; le script détecte le système lui-même.

$ (
    installer="$(mktemp /tmp/beaver-bootstrap.XXXXXXXX)" &&
    trap 'rm -f "$installer"' EXIT &&
    curl --proto '=https' --tlsv1.2 --fail --silent --show-error \
      --output "$installer" \
      https://raw.githubusercontent.com/Kevin-hDev/Beaver/main/install.sh &&
    bash "$installer"
  )

Ce que fait le script

Il demande une élévation de privilèges pour installer le paquet.

  • Il détecte le système et l'architecture, et n'accepte que Linux:x86_64 ou Linux:amd64.
  • Il interroge l'API GitHub Releases, avec une réponse plafonnée à 512 Kio.
  • Il exige l'asset .deb et le fichier update-manifest.json.
  • Il suit trois redirections au maximum, uniquement vers release-assets.githubusercontent.com.
  • Il télécharge le .deb avec un plafond de 2 Gio, et vérifie sa taille et son SHA-256.
  • Il refuse d'aller plus loin si un paquet beaver ou cl-go est déjà installé.
  • Il contrôle les métadonnées du paquet avant installation — c'est inhabituel, et détaillé dans le tableau ci-dessous.
  • Il installe via apt-get install -y, ce qui tire les dépendances manquantes.
  • Il vérifie que /usr/bin/cl-go-dash existe et n'est pas un lien symbolique.
  • Il lance l'application en arrière-plan.

La méthode alternative : le paquet .deb

Le .deb est attaché à chaque release GitHub. L'installation manuelle se fait ainsi :

$ sudo apt install ./Beaver_X.Y.Z_amd64.deb

Utilise apt plutôt que dpkg -i : apt résout les dépendances, dpkg non et laisse un paquet à moitié configuré. Le même .deb sert à la première installation et aux mises à jour intégrées.

Limites connues sur Linux

Le navigateur intégré n'est pas disponible. Toutes les autres fonctionnalités le sont.

Fenêtre au fond transparent — un problème ouvert, sans cause identifiée. Les pistes évoquées sont les réglages de décoration et de transparence de la fenêtre, le compositeur (Wayland contre X11), ou le thème GTK.

GPU AMD — la détection fonctionne, par lecture des identifiants constructeur dans /sys/class/drm/*/device/vendor, et l'archive ROCm est bien téléchargée. Le résultat n'a pas été validé sur une machine réellement équipée.

GPU NVIDIA — pilote 531 ou supérieur requis. CUDA est fourni dans le bundle Ollama, il n'y a rien d'autre à installer.

Navigateur intégré Le navigateur intégré n'est pas disponible sur Linux. Le reste de l'application fonctionne normalement.

Mettre à jour

Le script refuse de mettre à jour : « Une application est déjà installée. Utilise sa mise à jour intégrée. » La détection couvre le paquet beaver et le paquet cl-go, l'ancien nom. Les mises à jour passent par la fonction intégrée, qui installe le même .deb : Mise à jour.

Désinstaller

Le paquet se retire avec sudo apt remove beaver. Les données restent dans ~/.local/share/cl-go-dash/, et la clé maîtresse du coffre reste dans le magasin de secrets du système (Secret Service).
