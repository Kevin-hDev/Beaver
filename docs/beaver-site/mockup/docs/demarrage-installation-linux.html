Installing on Linux

Beaver is distributed as a .deb package for Debian and Ubuntu on x64. The install script verifies the package's fingerprint and its metadata before installing it.

Where Linux is going Beaver 1.2.3 is the last version that brings new features to Linux. After it, the Linux build moves to maintenance only: security fixes, stability fixes and dependency updates. Everything that works on Linux today keeps working and stays maintained — nothing is removed. New features land on macOS and Windows, so that development can be focused on those two systems.
Debian and Ubuntu only The install script only supports distributions in the Debian family, on x64. Fedora, RHEL, Arch and openSUSE are not handled.

Supported distributions

Debian and Ubuntu, x64 architecture only. The package is built on Ubuntu 22.04, which makes it compatible with 22.04, 24.04 and 25.04: since the standard C library is forward-compatible, building on the oldest target covers the later ones. There is no ARM build.

The recommended method: the script

It is the same command as on macOS; the script detects the system itself.

$ (
    installer="$(mktemp /tmp/beaver-bootstrap.XXXXXXXX)" &&
    trap 'rm -f "$installer"' EXIT &&
    curl --proto '=https' --tlsv1.2 --fail --silent --show-error \
      --output "$installer" \
      https://raw.githubusercontent.com/Kevin-hDev/Beaver/main/install.sh &&
    bash "$installer"
  )

What the script does

It asks for elevated privileges in order to install the package.

  • It detects the system and the architecture, and accepts only Linux:x86_64 or Linux:amd64.
  • It queries the GitHub Releases API, with the response capped at 512 KiB.
  • It requires the .deb asset and the update-manifest.json file.
  • It follows three redirects at most, only towards release-assets.githubusercontent.com.
  • It downloads the .deb with a 2 GiB cap, and checks its size and its SHA-256.
  • It refuses to go further if a beaver or cl-go package is already installed.
  • It checks the package metadata before installing — this is unusual, and detailed in the table below.
  • It installs through apt-get install -y, which pulls in the missing dependencies.
  • It checks that /usr/bin/cl-go-dash exists and is not a symbolic link.
  • It launches the application in the background.

The alternative method: the .deb package

The .deb is attached to every GitHub release. Manual installation goes like this:

$ sudo apt install ./Beaver_X.Y.Z_amd64.deb

Use apt rather than dpkg -i: apt resolves the dependencies, dpkg does not and leaves a half-configured package. The same .deb serves both the first installation and the built-in updates.

Known limits on Linux

The integrated browser is not available. Every other feature is.

Window with a transparent background — an open issue, with no identified cause. The leads mentioned are the window's decoration and transparency settings, the compositor (Wayland versus X11), or the GTK theme.

AMD GPUs — detection works, by reading the vendor identifiers in /sys/class/drm/*/device/vendor, and the ROCm archive is indeed downloaded. The result has not been validated on a machine actually fitted with one.

NVIDIA GPUs — driver 531 or later required. CUDA ships in the Ollama bundle, there is nothing else to install.

Integrated browser The integrated browser is not available on Linux. The rest of the application works normally.

Updating

The script refuses to update: “An application is already installed. Use its built-in update.” Detection covers the beaver package and the cl-go package, the former name. Updates go through the built-in function, which installs the same .deb: Updating.

Uninstalling

The package is removed with sudo apt remove beaver. The data stays in ~/.local/share/cl-go-dash/, and the vault's master key stays in the system's secret store (Secret Service).
