Tuning a model to your liking

A local model can be tuned at three depths: its generation parameters, its standing instructions, or a derived version that carries both. The defaults are almost always fine — this page is here for the cases where they are not.

The generation parameters

Eleven parameters, grouped by theme. What is worth remembering:

  • The context length decides how much the model can read at once. By default, Beaver computes it from your machine's memory — that is the setting to leave alone in almost every case.
  • Creativity — the temperature parameter — is the only one most people will want to touch. Low, the model is predictable and repetitive; high, it is inventive and unstable. For code, turn it down; for writing, you can turn it up.
  • The seed makes answers reproducible: with a fixed seed and an identical question, the model answers the same thing. Useful for comparing two configurations, of no interest day to day.
  • The repetition penalties stop the model from looping on the same phrasings.
  • The sampling parameters fine-tune how the model picks each word. They are for people who know what they are doing.
  • The stop sequences tell the model where to break off.

Note Increasing the context length consumes memory. A doubled context asks for more video memory; on a tight machine, it can stop the model from loading. See Hardware and VRAM.

The per-model system prompt

A system prompt is a block of instructions the model receives before any message, in every conversation. Beaver lets you define one per model.

  • The model's original prompt is captured and kept before any customization. So you can always go back to the initial state — the change is never destructive.
  • Four states are possible: the model's default prompt, Beaver's, a custom prompt, or no prompt at all.

The full prompt system — Chatbot and Agentic modes, short and detailed variants — is covered in System prompts. This page only covers the part specific to local models.

Creating your own model

The most advanced level: start from an existing model and derive a version that carries its own settings and instructions. In practice, you write a short recipe declaring the starting model, then what you want to change. Beaver passes it to the engine, which builds the new model.

What it gives you: a ready-to-use model, with its settings built in, selectable like any other — without having to redo the settings every time.

  • The recipe is capped at 2 MB — more than enough, most of them fit in a few lines.
  • Creation is abandoned after 10 minutes.
  • Updating the base model does not destroy the rest. Beaver only replaces the line that names the starting model, keeping every other instruction.

Creation requires an engine started by Beaver: it is refused when Beaver is reusing the system's Ollama engine. See Local engine.

Note A custom model is a real model. It takes up its own space on disk, appears in the list, and is deleted like the others.

What gets checked

  • The model name is validated before any creation.
  • The recipe is validated: not empty, not oversized, and free of forbidden characters.
  • The engine is called without going through a command interpreter, and the recipe is handed to it through a temporary file rather than on the command line. A malicious name or content cannot be executed as a command.
