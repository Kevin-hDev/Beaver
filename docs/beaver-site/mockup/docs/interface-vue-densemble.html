What you are looking at

You have just opened Beaver. This page names every area of the screen and points you to its detailed page. It describes no procedure: it is a map, not a manual.

The main navigation has four destinations, in this order.

How the screen is organized

From left to right:

  • The sidebar — the list of items in the active section: conversations, wakeups, personality files. Its width is adjustable, and it hides with ⌘B.
  • The central area — the conversation, or the section's content.
  • The side panel — file preview, browser or Forecast, as you choose. See Side panel.
  • The terminal — it opens at the bottom with ⌘J. See Integrated terminal.

When the window gets too narrow, the application folds the sidebar away on its own and switches the conversation to a compact display. This is intended, and reversible.

Note Every conversation has its own environment: model, permissions, working directory and active tools all belong to it. Switching conversation changes the working context, not just the discussion thread.

The toolbar

At the top of the window:

  • navigating back and forward through your browsing history;
  • search (⌘G);
  • a new conversation (⌥⌘N);
  • update notifications, with a progress bar during a download;
  • the indicator for a model download in progress.

The settings

Five sections, seventeen tabs out of the box — more if you install extensions. The grouping follows what you configure, not what you use it for.

The seventeen settings tabs shipped with the application
SectionTabs
PreferencesGeneral, Mascot, Keyboard Shortcuts
AgentMemory, System prompt, Tools, Advanced
ModelsOllama, Forecast, LLM
IntegrationsProviders, Connectors, Channels, Extensions
ApplicationUpdates, Archived chats, About

This list is not fixed: an installed extension can contribute its own settings tab. The seventeen tabs above are the ones shipped, not a final total.

Two neighborhoods deserve an explanation. Ollama and Forecast sit next to each other because both are where you install and configure local models, even though one produces text and the other forecasts. Providers, for their part, are filed under integrations because that is where you enter a key and a connection, not a model.

The window controls

The application draws its own window controls, matched to the system.

Warning On macOS, closing the window does not quit the application: it stays in the Dock. Use ⌘Q to genuinely quit. On Windows and Linux, the cross quits the application. The details are in First launch.
