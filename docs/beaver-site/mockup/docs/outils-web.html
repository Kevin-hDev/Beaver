Searching and reading the web.

Two tools make up the Web group, locked and impossible to turn off. One searches, the other opens an address — and the two are not treated the same way.

Two tools, two uses

The Web group
ToolRoleApproval in Ask permission mode
web_searchSearches the web and returns a list of resultsNo
web_fetchOpens an address and extracts its textYes, every time

The difference is intentional: searching exposes nothing, whereas opening an address sends a request out to a specific server, chosen by the model.

Searching the web

  • The agent sends a query, it receives a list: title, address, snippet. At most 10 results, for a query limited to 512 characters.
  • Every field is bounded: 160 characters for the title, 300 for the snippet, 2,048 for the address.
  • The agent does not choose the search engine and cannot filter by site. That is locked into the tool's very definition — an automated test even checks that the names of the services used appear nowhere in what the model sees.
  • A search with no result is not an error: the agent receives an empty list and carries on.

Where the query goes

Beaver tries the sources in this order, and stops at the first one that answers: Brave Search if a key has been entered, then Exa, then Firecrawl, then a local search instance bundled inside Beaver, which requires no key at all.

The fourth option is the important one: web search works without any account or any key being configured. Beaver bundles its own engine, which runs on your machine.

  • No account is tied to the searches, since there is no account to configure.
  • The engines queried downstream see the machine's IP address — the local engine queries them directly, with no anonymising relay. What they do not see is your identity or the link between two searches.
  • Beaver keeps no search history.
  • In exchange, quality and speed are lower than with a dedicated paid service, and the local engine requires Python 3 to be installed on the machine.

When a source fails, Beaver moves on to the next. If all of them fail, the error reported aggregates the causes — and it is scrubbed before display: no key, no token can appear in it.

Privacy Search works with no key and no account. But no account does not mean anonymous: the local engine queries public engines from your machine, which therefore see its IP address. What does not exist is the account, the profile and the history.

Reading a page

web_fetch opens an address and extracts the readable content from it.

  • The response must be text: web page, JSON, XML, plain text. An image, a PDF, a binary file are refused — the tool does not convert them.
  • For a web page, the tool isolates the article's main content and sets aside navigation, menus and footers. When that extraction yields too thin a result — typically a highly interactive page — it falls back to a full conversion of the page into structured text, with scripts and styles removed.
  • For JSON, XML or plain text, the content is returned as is, without transformation.
  • There is no cache. Two reads of the same address in the same conversation trigger two real requests: the agent always sees the page's current state.
  • http:// addresses are accepted as they are; there is no forced upgrade to https://.

The network protections

Every address is validated before the request, and on every redirect. What is checked:

  • The scheme — only http and https. No file://, no ftp://, no exotic scheme.
  • The length — 2,048 characters maximum.
  • Credentials in the address — an address containing a user name or a password is refused.
  • Private addresses — anything pointing at the machine itself or at the local network is blocked: localhost, the private ranges, link-local addresses, their IPv6 equivalents, along with the sneaky octal or hexadecimal spellings.
  • Cloud provider metadata servers — blocked by name. These are the addresses that, on a hosted server, hand out the machine's credentials.
  • Sensitive ports — some thirty internal service ports are refused: databases, file sharing, remote administration, mail, directories.
  • Domain name resolution — the name is resolved, all the addresses obtained are checked, and the request is then pinned to the validated address. A server therefore cannot answer with a public address to the check and an internal address to the request.

Redirects are followed three times at most, and each one goes through all these checks again. A redirect cannot serve as a back door into the local network.

Error messages are deliberately generic: they say a request failed, never why the remote server answered the way it did. A detailed message would map out your network.

Security The local network is out of reach for the agent through this tool: a development server on your machine, an internal service, a database — web_fetch refuses. To query a local service, the agent goes through a shell command, which is subject to the permission mode and to the sandbox.
