The context

The context is everything the model has in front of it when it answers: your message, the history, tool results, memory, instructions. This page explains what takes up the room, why the usable space is smaller than the advertised window, and how to free up space.

What the context is

Its size is set by the model, not by Beaver. A model with a small window will fill up quickly, whatever the settings.

Context or memory? The context is what the model sees right now. Memory outlives the conversation. Filling up your context loses you nothing from your memory. See Persistent memory.

What takes up the room

Beaver breaks usage down into seven categories.

The seven usage categories
CategoryContent
MessagesThe conversation and tool results
System toolsThe descriptions of the available tools
MCP connectorsThe descriptions of connector tools
SkillsThe loaded skills
MemoryThe injected notes
Meta-contextThe catalog of available skills
System promptThe starting instructions

This is the most useful piece of information on the page: a context can be full before you have even written a message, if too many connectors are active and too many skills are available.

Note The descriptions of active tools and connectors take up context permanently. With many connectors enabled, the available room shrinks before the first message.

One detail worth knowing: for one of the remote providers, the model's reasoning is not counted in the usage. The estimate can therefore differ from one provider to another.

The answer reserve

Beaver never fills the window entirely: a share is reserved for the answer.

The share kept for the model's answer
ReserveValue
Share of the window reserved15%
Floor4,096 tokens
Ceiling16,384 tokens

Without this reserve, the model would be cut off mid-answer. That is why the usable space is lower than the window advertised by the provider — the gap is not a bug.

The context usage screen

A dedicated screen shows the breakdown by category for the current conversation. This is the diagnostic tool to favour: rather than guessing what is filling the context, you read it.

When the context is full

The error carries the code context_capacity_exceeded. It occurs when what must be sent does not fit in the model's window once the answer reserve is deducted.

Beaver prunes the history before reaching that point. When pruning is not enough, compression takes over.

Reducing usage

The levers, in order of effectiveness:

  • Switch to a model with a larger window — the most direct lever.
  • Disable unneeded MCP connectors: every active connector adds the description of all its tools.
  • Disable unneeded tool groups, for the same reason.
  • Lighten the injected memory by reducing its budget.
  • Lighten your standing instructions — up to 200 KB can go there.
  • Clone the conversation at an earlier message to start again with a lighter context.
