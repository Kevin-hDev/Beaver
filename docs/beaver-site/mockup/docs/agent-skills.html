The skills

A skill is a set of instructions filed in a folder, which the agent loads on demand when the task matches. It is the way to teach the agent a detailed procedure without it taking up context in all your conversations.

Skill or AGENTS.md?

The difference that decides where to write what
AGENTS.mdSkill
LoadingEvery conversation, alwaysOn demand, when relevant
Context costPermanentOnly when loaded
ContentShort conventions, prohibitionsDetailed procedures

What must always be true goes into AGENTS.md; what is only occasionally useful goes into a skill. A three-page deployment procedure has no business taking up context in all your conversations.

Where to file them

One folder per skill, in the skills/ folder of the data directory. The folder may contain files other than the manifest — scripts, templates, references — which the skill points to.

The format of a skill

The folder must contain a file named SKILL.md or skill.md: both spellings are accepted. It starts with a header framed by --- containing two fields.

$ cat skills/deployment/SKILL.md
---
name: Deployment
description: Publish a release to production. To be used before every go-live.
---

The content of the skill, in free-form Markdown.

name is the displayed name; failing that, the folder name is used. description is 250 characters at most: it is what the agent reads to decide whether to load the skill. Values in single or double quotes are accepted.

Without a header, the file remains usable — the folder name serves as the name. But the absence of a description deprives the agent of its only selection criterion.

How the agent uses them

In two stages. First the catalog: the agent permanently sees the list of available skills, with their name and description, which costs little context. Then the loading: when a task matches a description, the agent loads the full content with the load_skill tool, which belongs to the Skills group, active by default.

The description decides everything The agent chooses to load a skill from its description alone, limited to 250 characters. State what the skill does and when to use it: a vague description gives you a skill that never triggers.

Calling a skill yourself

Each skill gets a command built from its source and its name. In the input area, typing / opens the autocomplete list of available skills; picking one inserts its command into your message.

  • A local skill is invoked with /skill-name.
  • An imported skill is invoked with /source:name.
  • When two skills would produce the same command, a suffix drawn from their identifier tells them apart.

Imported skills, and the ones you do not see

Skills carried over from another assistant appear in the same catalog, with an indication of their original source. Sorting is by name, case-insensitive.

A third source exists, invisible in the catalog: skills provided by an extension. Their identifier is prefixed with extension: and they are deliberately removed from the global catalog — so they do not count towards the 2,048 local skills and do not appear in the permanent list. In other words, the catalog shown is not the totality of skills the agent can load.

Subagents have almost no access to them

Only a subagent of the coder type receives load_skill, and only if the Skills group is enabled. An explorer subagent never has access to skills. See Subagents.

The limits

LimitValue
Local skills2,048
Size of a skill file256 KB

Skill identifier768 bytes

An identifier may contain neither .., nor /, nor \: this is a protection against reading a file outside the skills folder. Three errors are possible at load time: invalid identifier, skill not found, skill unavailable.

Writing a good skill

  • Work on the description before the content. It is what triggers the loading: write what the skill is for and when to use it, in the words you would naturally use.
  • Write in the imperative. “Check X” rather than “X should probably be checked”: an instruction phrased as a suggestion reads as one, and gets skipped.
  • Give the reason for a rule when it is not obvious. A rule without its why only covers the cases you foresaw.
  • One skill, one procedure. Two procedures in the same skill, and the agent loads both to use only one.
