Cloning a conversation

Cloning creates a copy of the conversation stopped at a specific message, and opens it in a tab next to the original. It is neither a full copy nor a plain summary: it is a resumption at a chosen point.

What it is for

Picking a conversation back up from a precise moment, when what followed did not give you what you wanted. The typical case: the agent goes down the wrong path at the tenth message and digs in for twenty more. Rather than starting everything over, you restart from the tenth — keeping, if you want, the memory of what did not work.

The original is not modified Cloning creates a new conversation. The original stays intact, in its own tab.

Where the button is

Under every message in the conversation, except the last. The last one is excluded because there is nothing after it: cloning there would amount to duplicating the whole conversation.

The two modes

Both modes copy the conversation up to the chosen message. They differ in how they treat what followed.

“Cut” mode — everything after the chosen message is dropped. The clone starts exactly in the state the conversation was in at that moment, no model is called, creation is immediate. Use it when what followed brought nothing.

“Summarize” mode — everything after is summarized by a model, and the summary is added to the clone as hidden context. The summary retains the errors encountered and not to be repeated, the decisions taken and the state of progress. The files read and the files modified during the summarized part are recorded and attached to the clone. You can specify a focus for the summary to steer what the model concentrates on, and cancel the generation in progress. Use it when what followed failed but taught something.

“Summarize” mode is refused if there is nothing after the chosen message: the summary would be empty.

What the clone contains

Carried over from the original: all the messages up to and including the chosen message, the model, the provider, the conversation settings.

Reset: the name, which becomes “Clone - ” followed by the original's name; the creation and modification dates; the archive state; the history of stream failures and diagnostics; the Git branch, since a clone starts with no branch attached; and all the subagent attributes.

In “summarize” mode, a hidden context message containing the summary is added. Finally, subagent conversations cannot be cloned: cloning is refused on them.

The tabs

An important point: conversations do not open in tabs. You move from one conversation to another through the sidebar. Tabs exist only for clones — a conversation and its clones form a tab group.

  • Three tabs at most per group: the original plus two clones.
  • A tab can be renamed.
  • A tab can be closed, with an option to clean up the associated Git branch.

Each clone keeps two references: its immediate parent and the root of the group. That is what makes it possible to clone a clone while keeping the group coherent.

The link with Git

A clone starts with no Git branch. Three actions are then possible: create a branch tied to the clone, link an existing branch, or unlink the branch. When a tab is closed, a dedicated command cleans up the associated branch and returns to a fallback branch.

The repository must be a saved project: unauthorized paths are refused. See Working folder.

The summary is generated by the model of the cloned conversation, not by a dedicated model: a slow local model therefore lengthens the operation. If the summary fails, the clone is deleted and its tab removed — you do not end up with a half-built conversation.

Cloning a clone

It is allowed, and it is in fact the intended use: you can iterate on a line of work while accumulating the memory of the errors avoided. Each clone in “summarize” mode adds its own hidden context, which yields a cumulative summary over successive attempts. The chain is bounded to 64 ancestors.
