Making an assumption without losing anything

A scenario is a variant of the forecast, saved alongside it. A note is a dated text, attached to an analysis and filed in a real file on your disk. This page describes both, and what the Report section contains.

The three sections, and where they live

Scenarios, Notes and Report are three of the seven sections of the Forecast workspace window — along with Data, Forecast, Evaluation and Comparison. This isn't Forecast's main menu, which has only three entries: Main view, Comparisons, History.

The three sections are attached to a specific analysis: with no analysis selected, they show “No analysis to evaluate” and “Run a forecast from the conversation first.”

Scenarios: two ways of making an assumption

The section's subtitle says it: “Create and edit assumptions without losing the reference forecast.” Two types exist.

The two scenario types
Type shownReruns the model?Conditions
Global adjustmentNoNone
ContextYesThe analysis must have context variables

The Context button is disabled when the analysis uses no context variable. The interface explains the two under the buttons: “Creates a derived curve from the current forecast without rerunning the model.” on one side, “Reruns the model with the new future values for the selected variables.” on the other.

Common fields: a required name, at most 80 characters, and an optional description, at most 500. Fifty scenarios at most per analysis.

The global adjustment

The simplest, and the fastest: Beaver multiplies the forecast by a factor, without recomputing anything. The percentage runs from −95% to +500%, in steps of 0.1.

What is multiplied: the predictions and the three bounds — low, median, high. The confidence range therefore moves with the curve, and its relative width stays identical. With several series, the adjustment moves them all.

The model isn't called again. No calculation, no network, no engine startup: it's an arithmetic transformation of the forecast already obtained. The button reads “Run scenario” at creation and “Update” when editing.

Note A global adjustment doesn't tell the model anything. It multiplies the already-computed curve, confidence range included. It's immediate and risk-free, but it doesn't answer “what would happen if…”: it answers “what would this curve look like 10% higher”.

The context adjustment

This one really reruns the model with different future values for your explanatory variables.

How you set it up: you add one or more rows, each made of a variable, a mode — “%” or “Value” — and a number. The add button is called “Add variable”, the remove one “Remove variable”. A new row starts at +10%. Twelve adjustments at most.

The “%” mode adjusts the existing value; the “Value” mode replaces it. Careful: the −95 to +500 bound applies to both modes. A variable whose normal values run into the thousands therefore can't be set to its real scale through this field.

Which rows it applies to: only future rows, that is, those whose target column is empty. Historical data is never modified. If no future row matches, the scenario is refused with “No future row modified”.

One series or all of them. When the analysis contains several series, a selector lets you target a specific one; its default value is “All series”.

Four conditions have to be met, otherwise the scenario is refused: the engine has to accept future context variables, the source data has to be available, the analysis has to use at least one variable, and every variable cited has to be among those used.

The rerun goes through the same path as a normal forecast: request validation, data quality check, engine capability check, then local or remote call. All the usual conditions therefore apply — model installed, sufficient resources, API key for a remote model. The button reads “Rerun scenario” when editing, since the calculation is redone.

Warning A context scenario only modifies future rows — those whose target column is empty. If your file contains none, the scenario is refused. And with a remote model, the rerun sends your data to the provider again: see TimeGPT (cloud).

Notes: what they are, where they're written

A note is a dated text, attached to an analysis, filed in a real Markdown file on your disk.

Five types: Context, Risk, Decision, Anomaly, Hypothesis. The default type for a new note is “Context”. Two possible sources: a note written by you, or a note placed by the agent. The interface tells them apart by the color of the dot on the timeline and shows “User” or “LLM”.

Where it's filed. One .md file per note, in a notes folder specific to the analysis, under Beaver's data folder. The interface shows that path under the timeline, and the “Open note” button opens the file in the system's editor.

What the file contains: a header between two lines of dashes — identifier, analysis identifier, date, type, source, creation and update dates — then the title as a level-1 heading, then the content in Markdown.

Writing is safe. Each file is written in two steps — temporary file then rename — and saving the note and saving the analysis form a single transaction: if the analysis can't be saved, the written note is rolled back. A lock prevents two note operations from crossing, and paths are checked at every access: identifier filtered, path canonicalised, membership of the right folder verified, symbolic links refused.

Notes exist in two places at once: the Markdown file, and a copy inside the analysis itself. Beaver brings them back into agreement each time the list is opened — missing files are rewritten, and the copies updated from the files.

Note Your notes are real Markdown files. One file per note, in Beaver's data folder, readable and editable in any editor — without Beaver.

The timeline and the list

The Notes section shows three areas.

  • A timeline — “Annotated timeline” — where each note is a dot placed according to its date, on an axis running from the start of the history to the end of the forecast. Its height is set by dragging it, and a double-click restores its original size. When empty, it shows “No note placed on this forecast.”
  • A list of the notes, sorted by date then by creation order.
  • A detail panel, with the Markdown preview of the selected note and the Edit, Delete and Open note actions. With no note, it shows “Select a note or create a new one.”

The creation button is called “New note”. The list reloads when the window regains focus: if you edit a note file in an external editor, coming back to Beaver is enough to see the change.

The Report section

It contains two things: an export menu at the top, and below it the Analysis section — the seven blocks described in Advanced analysis.

The export menu offers seven entries: CSV, Excel, PNG, SVG, JSON, PDF and copy to clipboard. The files land in the system's downloads folder, and failing that in an exports folder under Beaver's data folder. The file's name is the analysis's, cleaned up, followed by the first eight characters of its identifier.

Notes go out in the export: they are loaded and attached to the analysis before any writing. The detail of what each format contains is in Exports.

What is kept, and what disappears

Everything is saved to your disk, right away. Scenarios and annotations live in the analysis file, notes in their Markdown files. There is no “save the analysis” button: every creation, edit and deletion triggers a write.

Five hundred analyses at most. Beyond that, Beaver deletes the oldest from the same workspace; if there is none, it refuses to save with “Forecast storage is full. Delete older analyses, then try again.”

Deleting an analysis deletes its notes, and the operation is resumable: the notes folder is first set aside, then deleted once the analysis is erased; if the erasure fails, the folder is put back. A folder left pending after an interruption is handled on the next startup.

Scenarios don't survive a new forecast: they belong to the analysis. A new forecast creates a new analysis, and therefore an empty scenario list.

Warning Deleting an analysis deletes its notes. The operation is done so as to leave nothing half-finished, and an interruption in the middle is caught up on the next startup — but the deletion itself is permanent.

Notes and scenarios from the conversation

The agent can create a note, create a scenario, edit it or delete it — that's what explains the “LLM” source on the timeline. These tools are off by default and have to be turned on first in the agent's settings: see Forecast, on the tools side.
