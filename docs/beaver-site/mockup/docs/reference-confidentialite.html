Where your data goes

Beaver is a desktop app: no Beaver server, no Beaver account, no synchronization. Most of what leaves your machine is the data you send to a service you configured yourself — plus a short list of connections Beaver opens on its own, detailed below. This page does not say “nothing goes out without your action”: that would be false, and the nuance is worth reading.

Who sees my conversations

The answer depends on one thing only: the model chosen for the conversation.

  • Local model (Ollama) → the conversation does not leave the machine.
  • Cloud model (API key or web account) → the whole conversation goes to that provider, on every turn.

The choice is made conversation by conversation and can be changed along the way: see Choosing your model.

With a cloud model

A Beaver conversation is not just your messages. It is a list that also contains your attachments — a text file inserted as text, an image as an encoded image —, the result of every tool the agent uses — the content of a file read, the output of a terminal command, a folder listing, a search result — and the system prompt, personality settings and the list of skills included.

That whole set is sent back to the model on every turn, not just the first: a file read once stays in the context and goes out again with each subsequent exchange.

Warning What the agent reads, the provider reads too. If you open a folder containing confidential data to the agent and the conversation uses a cloud model, that data goes to the model's provider. This is not a flaw, it is how an agent works — but you need to know it beforehand, not afterwards. For that kind of work, use a local model.

Apart from the messages, Beaver sends the provider no installation identifier, no machine name, no statistics. The single exception is covered below. What the provider then does with that data — storage, training, retention period — is not up to Beaver: refer to each one's privacy policy, it alone is authoritative on that point.

With a local model

When the conversation uses an Ollama model, the request goes to an address on the machine itself. The engine's address is only ever built in the form http://127.0.0.1:<port>, any other address is refused, and Ollama's “cloud” models are explicitly disabled when the engine starts. No conversation request therefore leaves the machine.

Three nuances, not to be glossed over:

  • the model must first be downloaded, and that download goes through the Internet;
  • a model update check happens automatically and sends the names of the installed model families to ollama.com;
  • the agent's tools, however, can go out. A local agent you ask for a web search opens a connection. The model is local; not all of its tools are.

The automatic net: secrets removed before sending

Beaver removes values that look like secrets from the tools' results before that result enters the conversation — therefore before it goes to a cloud provider. After each call of the bash, bash_control, read_file, grep, glob and list_dir tools, the content goes through a redaction function that replaces the recognized values with [REDACTED].

What is recognized: pairs of the form api_key=…, token: …, password=…, client_secret, access_token, refresh_token, authorization; known token formats — OpenAI, GitHub, GitLab, Slack, AWS, Google, xAI, Hugging Face, Telegram bot tokens, JWT tokens, Slack webhook URLs; Bearer … headers; private key and certificate blocks in PEM format. The same redaction applies to the conversation log saved on disk and to what is shown in the interface.

Note The net catches formats, not meanings. It recognizes technical formats. An ordinary password in a text file, a name, a case number look like no known format: they are not removed. It applies to the six named tools above, not to the result of an external connector or of an extension. This net complements your vigilance, it does not replace it.

Web search: four paths

When the agent uses the web search tool, Beaver tries the configured providers in a fixed order — Brave, then Exa, then Firecrawl — and falls back on local SearXNG if none is configured or if all of them fail.

The three search providers and the address contacted
ProviderAddress contacted
Braveapi.search.brave.com
Exaapi.exa.ai
Firecrawlapi.firecrawl.dev

With one of those three, your query goes to them together with your API key — therefore tied to your account. What exactly goes out: the search query, and nothing beyond the format, result count and snippet length parameters.

Warning “SearXNG is local” needs a clarification. The engine runs on your machine, listens on 127.0.0.1 only, uses no API key and keeps no shared cache: your searches are tied to no account. But SearXNG is a meta search engine: its role is to query public engines for you. The query therefore leaves the machine, from your IP address. What it gives you is the absence of an account and the spreading of your queries — not their confinement.

The list of engines it queries comes from SearXNG's own default settings, not from a choice written into Beaver: SearXNG's documentation is authoritative on that. Setting up the four paths is described in Web.

External connectors and extensions

External connectors (MCP). A connector can be a local program or a remote service. The remote ones receive the arguments of the tools the agent passes them — that is, potentially, content from your work. Nothing is contacted until you have configured and enabled the connector. See MCP connectors.

Extensions. An approved extension runs with the rights of your account and may use the network freely. Beaver does not monitor what it sends: an approved extension falls outside the perimeter described here. See Extension center.

Telegram, Slack and Discord

If you plug in an external channel, your messages and the agent's answers pass through the servers of the platform concerned — api.telegram.org, slack.com, discord.com —, like any conversation on those services.

The local audit log, on the other hand, is solid. Beaver keeps a log of actions in logs/gateway-audit.jsonl. A line contains exactly seven fields: timestamp, channel, account identifier, fingerprint of the user identifier, type of action, decision code, error category. Three consequences:

  • the text of the messages is not in it — actions are labels: message received, message sent, blocked, rate-limited, agent error, channel started, channel stopped, authentication failed;
  • the person's identifier is not in it in the clear: it is an HMAC-SHA256 truncated to 8 bytes, computed with a random key specific to your installation and stored in the encrypted vault;
  • errors are reduced to five categories before writing, so no internal detail ends up in it.

The log is kept for 30 days by default, adjustable between 1 and 365 days, and it can be turned off. See External channels.

Six connections wait for no action from you. Four are update checks, the fifth is a model catalog, and the sixth — the least obvious — is the link preview.

The local SearXNG search engine is started at launch if it is installed, but it is launched and queried on the loopback only: it is not an outgoing connection. The messaging channels only start if you have enabled the gateway and asked for it to start with the app — but once started, that is continuous traffic: a Telegram channel polls in a loop, a Discord channel keeps a permanent connection.

Warning A link displayed is a link visited. As soon as a web address appears in a conversation, Beaver contacts that site to fetch its title, description and preview image — without you clicking. That also holds for addresses quoted by the model: the site then sees your IP address and knows a link to it was displayed on your machine. It is on by default and can be turned off in the advanced settings. If you work on subjects you do not want to signal to anyone, turn link previews off.

Beaver also refuses to contact a private or local address through that path, and the results are cached so the same link is not requested again.

Note The only automatic check that says something about you. Every hour, Beaver asks ollama.com whether a newer version of your models exists, and sends it the names of the families installed on your machine to do so. No account, no key, no identifier goes with it — but ollama.com learns which models you use. The other automatic checks send only Beaver's name and version.

What never goes out without a move from you

  • The Ollama engine is not downloaded at startup: it is downloaded when you click the button on the installation screen.
  • No model is downloaded on its own.
  • No request is sent to a cloud provider until a conversation uses that provider. Configuring an API key sends nothing — unless you click the test button, which calls the provider to check the key.
  • The other on-demand connections: downloading a model, asking the agent to open a web page, browsing in the built-in browser, installing a forecasting model from huggingface.co, using Nixtla TimeGPT on api.nixtla.io, installing an extension, enabling a remote connector, downloading a Beaver update.

The identifiers passed on: the rule and its exception

The rule. Beaver makes no installation identifier and sends none to anyone. The only signature it adds to its own requests is the User-Agent header, which reads Beaver/<version> — the product name and its version number, nothing else.

Warning The Kimi web account passes on your machine's name. That provider's protocol requires a device identity. Beaver therefore sends it an identifier drawn at random on first use and kept on your machine, the name of your computer, your system's version and its architecture, plus Beaver's name and version. It is Beaver's only connection in that case. If that bothers you, use the Moonshot API key rather than the web account.

A second, lighter exception: signing in with an xAI web account passes on your xAI account identifier and a client signature — Beaver's name and version. That is the identity of your account with them, not that of your machine: no computer name appears in it.

Telemetry: an absence, and its method

Beaver embeds no telemetry, usage analytics or crash reporting tool. No statistics, no installation identifier, no crash trace is sent to anyone. An absence cannot be proven the way a line of code can: here, then, is the method, so that you can redo the check.

  • Keyword search across the whole source code, case-insensitive, on the patterns sentry, telemetry, analytics, posthog, crashlytics, mixpanel, amplitude, datadog, bugsnag, rollbar, opentelemetry, gtag, matomo, plausible, umami, google-analytics, segment.io, tracking, beacon.
  • Search in the dependency declarations — Cargo.toml and package.json — on the same patterns. Zero results. That is the decisive check: no tool of that kind can work without being declared as a dependency.
  • Examination one by one of every textual match, to rule out false positives.
The matches found and what they really are

The only thing Beaver does about telemetry is therefore to switch it off in the third-party components it runs for you. This method covers Beaver's code: it says nothing about what the services you configure do, nor about the code of an extension you approve.

Where your data lives on the disk

A single folder, identical on all three systems: ~/.local/share/cl-go-dash/. Beaver does not use each system's usual locations, it imposes a single one.

On macOS and Linux, the files Beaver creates are created as 0600 and the folders as 0700; on Windows, an equivalent access control list is set. At every startup, Beaver restores those rights. The limit: they protect your data from the computer's other accounts, not from a program launched under yours — including an extension you have approved.

The point that surprises people when it is time to erase: the downloaded Ollama models are not in that folder. They go to ~/.ollama/models, and often weigh several tens of gigabytes.

What is written to the traces

Beaver writes a technical log in logs/. It stays on your machine: nothing is sent anywhere. The safeguards: every line goes through redaction before writing; every line is bounded to 2,048 characters; the file is bounded to 2 MiB and 4 files are kept in rotation; the body of the providers' answers is redacted and truncated to 200 characters; the search engines' error messages are redacted and truncated to 240 characters.

Your API keys are never written to the traces, and the interface cannot read them anyway. The detail is in The vault and API keys.

How to erase everything

The procedure is manual. Beaver offers no “erase everything” command: the deletions available are targeted — a key, a conversation, a project, a model, a wakeup, a connector token, a forecasting note or analysis. None of them covers the whole.

Warning Deleting the folder is not enough. Three things live outside it: the key that decrypts your vault, stored in the system keyring; the Ollama models, in ~/.ollama/models; and what you have already sent to third-party services, which is not on your disk. The first two are deleted by hand. The third is handled by revoking your keys at each provider, from its own website.

One last point if you have been using Beaver for a long time: older versions stored each key directly in the keyring, under the same cl-go-dash service and under the provider's name. Check those entries too.

What people wrongly believe

Misconceptions and what is true
What people believeWhat is true
“I use a local model, so nothing ever goes out”The conversation does not go out. The hourly check sends the names of your model families to ollama.com, and a web search tool goes out by definition
“SearXNG is local, so my searches stay on my machine”They go out to the public engines, but with no account and no key
“I only send my messages to the provider”Every file read, every command output and every attachment goes too, and goes again on every turn
“Configuring an API key sends data straight away”No — unless you click the test button, or open the providers screen, which reads your balance
“Beaver only contacts a site if I click its link”A link that is displayed is contacted automatically to build the preview, including a link produced by the model
“I uninstalled, so everything is erased”Uninstalling touches neither the data folder, nor the keyring, nor the Ollama models
“The audit log contains my messages”Seven technical fields and a fingerprint of the user identifier. Never the text
“Beaver redacts everything sensitive”It redacts known secret formats, in the result of six named tools
“My data is protected from other software”The 0600/0700 rights protect from other accounts, not from a program launched under yours
