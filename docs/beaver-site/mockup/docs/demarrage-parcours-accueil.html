The onboarding flow

On first start, Beaver walks you through four or five screens: preferences, import from another assistant, connecting a provider, and installing the local engine if needed. None of it is mandatory.

Nothing is permanent No step in the onboarding flow is mandatory. Everything offered there can be found again in the settings.

Overview

The flow has four or five steps, presented as horizontal slides. The fifth — Ollama — only appears if Ollama is not already available on your machine. No step blocks you: you can go through the whole flow without configuring anything and do it all later in the settings.

Step 1 — Welcome

An introduction screen with the beaver illustration, a title, a description and a button to begin. Nothing to enter.

Step 2 — Preferences

Two settings, and two only: the theme, among those available, and the language, among the interface's seven languages. You find them again afterwards in Settings › General.

Step 3 — Import from another assistant

This step offers to bring over the instructions, skills and rules from another agent application already installed. Nine sources are recognized, detailed in Importing from another agent.

Step 4 — Connecting a provider

A grid of cards, one per model provider, with its icon, its name and a short description. Only providers in the LLM category are shown, 32 at most. Those already configured carry the label “Connected”.

You select a card, you enter the key, you save; a link leads to the provider's key creation page. The key you entered is cleared from the field as soon as you leave the step.

Without an API key You can go through this step without entering anything. Beaver works with a local model, with no account and no key.

Step 5 — Ollama, if needed

This step does not appear if an Ollama daemon is already available, or if the binary is already present in the data folder. Otherwise, it offers to download and install Ollama, and can be skipped: the application stays usable with remote models only. The download is detailed in First launch.

Going back, skipping a step

The Import and Provider steps offer a way back. The sequence adapts: if the Ollama step is not needed, confirming the Provider step ends the flow directly.

The permission mode is not asked for here The onboarding flow does not offer a choice of permission mode: the application starts in Full access, where the agent runs its tools without asking for confirmation. Change it in the settings if you prefer to approve every action.
