Feature tour

Seventeen areas, a few sentences each, and a link to the page that says more. This is a signposting page: it exists to show the scope in one read, not to teach everything.

Agent and tools

The agent works with a local or remote model, and has a catalog of tools: files, shell commands, search by name or by content, web search, Git, office documents, spreadsheets, images, forecasting, external connectors. Tools are grouped by family; some are always available, the rest are enabled manually, with 32 optional tools at most active at the same time. → Agent, Tools

Planning and permissions

Plan mode makes the agent explore in read-only, makes it write a Markdown plan, and waits for your approval before any write. Plans are kept on disk. Separately, every modifying action can be made subject to confirmation, as a global setting or conversation by conversation. → Permission modes

Conversations and projects

Navigation happens through the sidebar. You can attach files, queue messages while the agent is working, archive a conversation. A conversation is born inside a project or outside one, and that never changes afterwards. Cloning lets you start again from a specific message, either dropping what followed or keeping a summary of the errors and decisions. → Conversations, Cloning a conversation

Subagents

The agent delegates part of the work to isolated sessions with their own context. You follow their state live, correct them along the way, inspect the modified files, then apply or reject the changes. Git worktrees are cleaned up afterwards. → Subagents

Persistent memory

Notes kept between conversations, in global or per-project scope, in manual or automatic mode. They are filed by topic, bounded in size, and viewable from the settings. Subagents access them in read-only. → Persistent memory

Integrated browser

Up to ten tabs per conversation, with signed-in sessions kept from one time to the next and detection of local development servers. The browser shares the side panel with previews and Forecast. → Integrated browser

Platform availability The integrated browser is available on macOS and Windows. On Linux it does not appear in the interface: the feature is hidden rather than shown broken. Every other feature is available on all three systems.

Git

Create, switch, merge and delete branches and worktrees. Commit and push. Browse uncommitted changes. Inspect recent or older diffs in the history. → Git branches

Forecast

The time-series forecasting workspace: data quality audit, manual or automatic model selection, local or cloud execution, rolling backtests, comparison, weighted ensembles, advanced analysis, scenarios, notes, report and exports. Ten families of local models are offered, plus one cloud family, eleven in total. → Forecast

Providers and usage

Eleven model providers are supported through an API key, and three of them also accept a web account connection. Beaver shows limits, credits, tokens consumed, requests and a cost estimate whenever the provider exposes that information. → API providers, Usage and costs

MCP connectors and channels

MCP connectors, local or remote, are enabled conversation by conversation and add their tools to the agent. A background gateway links Beaver to Telegram, Slack and Discord, with an audit log. → MCP connectors, External channels

Extensions

Extensions are installable modules that modify the interface itself, distributed and updated from a Git source. An extension contributes its own settings tab, navigation entries, a theme and skills. Three locked tools in the extensions group make them visible to the agent. Not to be confused with an MCP connector, which only adds tools. → Extension center

Wakeups

Instructions scheduled once, every day or every week, triggered by a scheduler internal to the application. Each run lands in a dedicated conversation, and the history is kept.

Managed local engine

The onboarding flow offers to download Ollama into the data folder; you can skip the step and come back to it later from Settings › Ollama. A daemon that is already present is reused instead of downloading one. From the application, you browse and install models, edit modelfiles, adjust the parameters and the system prompts. Models are shared with an existing Ollama installation. → Local engine, Local models

Workspace

A cross-platform multi-tab terminal, a file tree that watches for changes, rich previews — text, images, spreadsheets, office documents, link previews —, a breakdown of context usage, and an interactive beaver. → Interface, Integrated terminal

Guided start and migration

An onboarding flow on first launch, and an import assistant that brings over instructions, skills and rules from nine applications: Claude Code, Codex, Agents, Hermes, Qwen Code, ZCode, OpenClaw, OpenCode and Kimi Code. → Onboarding flow, Importing from another agent

Secure local storage

Credentials live in an encrypted XChaCha20-Poly1305 vault, whose master key is stored in the system keyring. No raw secret ever reaches the graphical interface. → The vault and API keys, Security model

Languages and appearance

The interface exists in seven languages — French, English, Spanish, German, Italian, Chinese, Japanese — and offers six visual themes, plus settings for font size and code syntax theme. → Themes and appearance, Languages
