The software and what it has accumulated

Three tabs that don't change Beaver's behavior: they deal with the software itself, its versions, and the conversations set aside. It's also the only place in the settings where data can be destroyed for good.

Note A setting often looked for here isn't here: file access — the folders opened to the agent — lives in Agent › Advanced, with the other settings of the agent's behavior.

Updates tab

The panel carries the title “Updates” and a framing sentence: “Check and install new versions of Beaver and Ollama.” At the top right, a “Check for updates” button, which becomes “Checking…” during the operation and stays inactive as long as it lasts.

The body of the screen has a fixed section and a conditional one.

“Installed” — always present. Two lines, one per product, each with its logo, its name and its version number in the v1.2.2 format: the version of Beaver itself, and that of the Ollama engine actually installed. When a version isn't known — Ollama not installed yet, for instance — the line shows —.

“Available updates” — appears only if there are any. Each line then carries an “Update” button. During the download, the button gives way to a progress bar with a cancel button, which shows “Cancelling…” while the stop takes effect.

Three facts about the checking rhythm:

  • a check happens when the application starts;
  • then automatically every hour;
  • the screen's button triggers the same check on demand, and that's the only case where a failure produces a visible error message. Automatic checks fail silently.

One update at a time. As long as a download is under way, the other product's button is inactive. And meanwhile, a new check doesn't replace what is being installed — without that, a download could target a version different from the one announced on screen.

Note Beaver looks for its updates on its own, but never installs on its own. A check happens at launch then every hour; the installation always remains a click of yours.

Updates — what isn't there

Two absences, because people look for them in this tab:

  • Ollama model updates aren't listed here. The application detects them, but this screen only shows the application and the engine. Models are updated from Models › Ollama.
  • There is no setting in this tab: no “update automatically” checkbox, no release-channel choice. The check is automatic, the installation always manual.

The full mechanism — where the versions come from, how the installation proceeds, what happens if it fails — is in Updating.

Archived chats tab

The panel carries the title “Archived chats”. At the top, a bar with two controls: a search field “Search archived conversations”, limited to 120 characters, and a filter by project whose first value is “All projects”. At the top right, a “Delete all” button, inactive when there is nothing to delete.

Conversations are grouped by project, and inside each group, from the most recently active to the oldest. An empty group isn't shown. The conversations belonging to no project form a separate group, titled “Beaver”; the filter offers this group as an entry in its own right, between “All projects” and the list of real projects.

Each conversation offers two actions: “Restore” and “Delete”.

A display bound exists: at most 2,000 archived conversations are presented. Beyond that, the oldest don't appear, and the limit isn't signalled on screen. Search remains the way to find a specific conversation.

The tab has its states written: “Loading archives…”, “No archived chats”, and the list itself. Each action produces a message: “Chat restored”, “Could not restore chat”, “Chat deleted”, “Archived chats deleted”, “Could not delete chat”. Archiving a conversation from the main list is described in Conversations.

Deleting, and what that means

Two levels of severity, not to be confused:

  • Restore returns the conversation to the main list. Nothing is lost.
  • Delete erases it. The application's texts are explicit: “Permanently delete this archived chat?” and, for the bulk action, “Permanently delete all archived chats?”

Both deletions ask for a confirmation: the button turns into “Confirm”, which has to be clicked a second time. There is no undo afterwards: a deleted conversation can't be recovered from the application.

“Delete all” deletes the conversations one by one, in parallel. Two consequences: if the operation fails partway through, some of the conversations may already have been deleted; and the error message shown is a single one — it doesn't say how many were erased.

Warning “Delete all” ignores the filters. The button applies to all archived conversations, including those the search or the project filter hides at the moment of the click. Filtering on a project then clicking “Delete all” also erases the other projects' archives.

About tab

The simplest of the seventeen tabs: it has no setting at all. At the top, Beaver's logo, its name in the brand typeface, and its description — “Agentic desktop app for local and cloud LLMs.”

Then a card of three lines:

The three lines of the About screen
LineContent
VersionThe installed Beaver version
TauriThe version of the framework Beaver is built on
SystemmacOS, Windows or Linux, depending on the machine

Each shows — as long as the value isn't known. Finally, a “View on GitHub” button opens the project's repository in the system browser, outside Beaver.

Note This is the screen to open before any request for help. The Beaver version, the Tauri version and your system are the three pieces of information to attach to a report so that a problem is reproducible.
