Ce à quoi Beaver se branche

Quatre onglets, quatre questions distinctes : avec quoi Beaver produit ses réponses, à quels services l'agent peut parler, par où on peut lui écrire, et quel code tiers tourne à l'intérieur. Cette page est une carte : elle dit comment les quatre écrans sont organisés et lequel ouvrir pour quoi.

La distinction entre Connecteurs et Canaux est celle qu'on comprend le moins vite. Elle tient au sens de la conversation : un connecteur est un service que l'agent va consulter — « Permettez aux LLM de se connecter à d'autres applications et services » — tandis qu'un canal est une messagerie depuis laquelle on écrit à Beaver — « Connectez des bots de messagerie pour communiquer avec les LLM. »

Note Connecteur ou canal ? Un connecteur est un service que l'agent va consulter pour toi. Un canal est une messagerie depuis laquelle tu écris à Beaver. Les deux se configurent dans cette section, mais ils ne servent pas du tout à la même chose.

Une organisation commune aux quatre onglets

Les quatre écrans suivent le même schéma, ce qui rend la section prévisible :

  • une liste de ce qui est déjà configuré ;
  • un bouton d'ajout en haut à droite du panneau, qui ouvre un catalogue à parcourir ;
  • une fiche de détail quand on sélectionne un élément, avec un lien de retour vers la liste ;
  • un message d'état vide quand rien n'est configuré.

Les boutons d'ajout portent des libellés parallèles : « Connecteurs API » pour les fournisseurs, « Parcourir les connecteurs », « Parcourir les canaux ».

Note Une liste vide n'est pas une impasse. Le bouton d'ajout est en haut à droite du panneau, présent même quand rien n'est configuré : c'est par lui qu'on parcourt le catalogue.

Onglet Providers

Le seul onglet de la section à porter deux sous-onglets.

Les deux sous-onglets de l'onglet Providers
Libellé affichéCe qu'on y fait
Clés APIEnregistrer une clé chez un fournisseur
OAuthSe connecter avec un compte web existant

Ce sont deux façons de se connecter au même genre de service, et le choix entre les deux est un vrai sujet : voir Fournisseurs API et Connexion par compte.

Le sous-onglet Clés API liste les fournisseurs déjà configurés, chacun avec son icône et son nom. Un bouton « Connecteurs API » ouvre le catalogue complet des fournisseurs disponibles ; en choisir un ouvre une fenêtre de configuration où l'on colle la clé. La fiche d'un fournisseur configuré propose de modifier la clé ou de la supprimer.

Le sous-onglet OAuth liste les comptes web connectés et permet de s'y connecter ou de s'en déconnecter.

Attention Une clé API enregistrée ne peut plus être affichée — y compris par Beaver. Il n'existe aucune commande capable de la relire. Note-la ailleurs si tu en as besoin, ou génère-en une nouvelle chez le fournisseur. La démonstration complète est dans Le coffre et les clés API.

Onglet Connecteurs

La liste des connecteurs MCP configurés, avec un bouton « Parcourir les connecteurs » qui ouvre un catalogue. La fiche d'un connecteur propose trois actions : connecter ou déconnecter — la déconnexion passe par une confirmation —, supprimer le connecteur, et revenir à la liste.

Quand la liste est vide, le message dépend de la cause : « aucun connecteur » si tout va bien, un message d'erreur de chargement si la lecture a échoué. La distinction est utile : une liste vide et une liste illisible ne demandent pas la même action.

Un connecteur configuré est immédiatement disponible pour l'agent. Le groupe d'outils Connecteurs externes fait partie des cinq groupes verrouillés, toujours actifs — sa description le dit mot pour mot : « Permet à l'agent d'utiliser les connecteurs externes que tu as configurés dans l'onglet Connecteurs. »

Le détail est dans Connecteurs MCP, leur autorisation dans Authentification des connecteurs, et la façon dont l'agent s'en sert dans Connecteurs externes.

Onglet Canaux

Même structure : liste des canaux configurés, bouton « Parcourir les canaux », fiche de détail avec configuration et suppression.

Une particularité par rapport aux deux onglets précédents : la fiche affiche l'état de santé du canal, relevé en continu. Un canal peut être configuré et hors service — c'est une information que ni les connecteurs ni les fournisseurs n'exposent de la même façon.

Un canal se configure par compte : plusieurs comptes sur la même messagerie sont donc possibles. Le détail est dans Canaux externes.

Onglet Extensions

Le plus riche des quatre, et le seul protégé par le contrat des extensions : aucune extension ne peut le retirer ni le remplacer. Le raisonnement mérite d'être écrit — on ne peut pas installer une extension qui te priverait du moyen de la désinstaller.

Les trois sections de l'onglet Extensions
Libellé affichéContenu
Plugins« Les plugins officiels de Beaver, distincts des Tools internes. »
Extensions« Ajoutez du code local ou installez une extension depuis Git ou npm. »
HôteL'état du processus qui exécute les extensions

Chaque section a son état vide écrit : « La suite officielle de plugins apparaîtra ici lorsqu'elle sera disponible. » pour les plugins, « Aucune extension personnalisée. » pour les extensions.

Les actions disponibles sur une extension : activer ou désactiver, afficher ou non dans le chat, ouvrir sa source, mettre à jour, supprimer, recharger, et pour celles qui ont échoué à se charger, réessayer ou rester désactivée. Certaines extensions sont protégées contre la suppression.

Deux mécanismes de reprise existent pour le cas — réel — d'une extension qui empêche l'application de fonctionner : une récupération de l'hôte et la restauration d'un instantané antérieur. Le détail est dans Centre d'extensions, et écrire la sienne dans Écrire une extension.

Ce que les quatre onglets ont en commun côté sécurité

Tout ce qui est secret dans ces quatre écrans va au même endroit : le coffre chiffré de Beaver. Clés API des fournisseurs, jetons des comptes web, jetons OAuth des connecteurs, variables d'environnement secrètes des connecteurs, jetons des canaux — chacun a son entrée dans le coffre, et aucune n'est relisible par l'interface. L'inventaire complet est dans Le coffre et les clés API.

Une exception, et elle est délibérée : une extension approuvée peut demander au coffre une clé de fournisseur, un jeton de connecteur ou un jeton de canal. Le coffre protège tes secrets du reste du système, pas du code que tu as toi-même autorisé. C'est pourquoi l'activation d'une extension demande une confirmation explicite — et c'est ce qui distingue l'onglet Extensions des trois autres.

Attention Une extension activée peut demander tes secrets. Clés de fournisseurs, jetons de connecteurs, jetons de canaux : le coffre les remet au code que tu as approuvé. C'est la raison de la confirmation demandée à l'activation, et la raison pour laquelle l'onglet Extensions ne peut jamais être retiré par une extension.
