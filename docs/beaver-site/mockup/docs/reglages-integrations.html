What Beaver plugs into

Four tabs, four distinct questions: what Beaver produces its answers with, which services the agent can talk to, where you can write to it from, and what third-party code runs inside. This page is a map: it says how the four screens are organised and which one to open for what.

The distinction between Connectors and Channels is the one that takes longest to grasp. It comes down to the direction of the conversation: a connector is a service the agent goes and consults — “Allow LLMs to connect to other apps and services” — whereas a channel is a messaging app you write to Beaver from — “Connect messaging bots to communicate with LLMs.”

Note Connector or channel? A connector is a service the agent goes and consults for you. A channel is a messaging app you write to Beaver from. Both are configured in this section, but they don't serve the same purpose at all.

One organisation shared by the four tabs

The four screens follow the same pattern, which makes the section predictable:

  • a list of what is already configured;
  • an add button at the top right of the panel, which opens a catalog to browse;
  • a detail card when an item is selected, with a link back to the list;
  • an empty-state message when nothing is configured.

The add buttons carry parallel labels: “API Connectors” for the providers, “Browse connectors”, “Browse channels”.

Note An empty list isn't a dead end. The add button is at the top right of the panel, present even when nothing is configured: that's how you browse the catalog.

Providers tab

The only tab in the section with two sub-tabs.

The two sub-tabs of the Providers tab
Label shownWhat you do there
API KeysSave a key with a provider
OAuthSign in with an existing web account

These are two ways of connecting to the same kind of service, and the choice between them is a real subject: see API providers and Account sign-in.

The API Keys sub-tab lists the providers already configured, each with its icon and its name. An “API Connectors” button opens the full catalog of available providers; choosing one opens a configuration window where you paste the key. A configured provider's card offers to edit the key or delete it.

The OAuth sub-tab lists the connected web accounts and lets you sign in or sign out of them.

Warning A saved API key can never be displayed again — including by Beaver. There is no command capable of reading it back. Note it down elsewhere if you need it, or generate a new one with the provider. The full demonstration is in The vault and API keys.

Connectors tab

The list of configured MCP connectors, with a “Browse connectors” button that opens a catalog. A connector's card offers three actions: connect or disconnect — disconnecting goes through a confirmation —, delete the connector, and go back to the list.

When the list is empty, the message depends on the cause: no connectors if all is well, a loading error message if the read failed. The distinction is useful: an empty list and an unreadable list don't call for the same action.

A configured connector is immediately available to the agent. The External connectors tool group is one of the five locked groups, always active — its description says so word for word: “Lets the agent use the external connectors you configured in the Connectors tab.”

The detail is in MCP connectors, their authorization in Connector authentication, and the way the agent uses them in External connectors.

Channels tab

Same structure: list of configured channels, “Browse channels” button, detail card with configuration and deletion.

One particularity compared with the two previous tabs: the card shows the channel's health state, monitored continuously. A channel can be configured and out of service — that's information neither the connectors nor the providers expose in the same way.

A channel is configured per account: several accounts on the same messaging app are therefore possible. The detail is in External channels.

Extensions tab

The richest of the four, and the only one protected by the extension contract: no extension can remove or replace it. The reasoning deserves writing down — you can't install an extension that would deprive you of the means to uninstall it.

The three sections of the Extensions tab
Label shownContent
Plugins“Official Beaver plugins, separate from internal Tools.”
Extensions“Add local code or install an extension from Git or npm.”
HostThe state of the process that runs the extensions

Each section has its empty state written: “The official plugin suite will appear here when it becomes available.” for the plugins, “No custom extensions.” for the extensions.

The actions available on an extension: enable or disable, show or hide in the chat, open its source, update, delete, reload, and for those that failed to load, try again or stay disabled. Some extensions are protected against deletion.

Two recovery mechanisms exist for the — real — case of an extension preventing the application from working: a recovery of the host and the restoration of an earlier snapshot. The detail is in Extension center, and writing your own in Writing an extension.

What the four tabs have in common on the security side

Everything secret in these four screens goes to the same place: Beaver's encrypted vault. Providers' API keys, web account tokens, connectors' OAuth tokens, connectors' secret environment variables, channel tokens — each has its entry in the vault, and none can be read back by the interface. The full inventory is in The vault and API keys.

One exception, and it is deliberate: an approved extension can ask the vault for a provider key, a connector token or a channel token. The vault protects your secrets from the rest of the system, not from code you authorized yourself. That's why enabling an extension asks for an explicit confirmation — and that's what sets the Extensions tab apart from the other three.

Warning An enabled extension can ask for your secrets. Provider keys, connector tokens, channel tokens: the vault hands them to the code you approved. That's the reason for the confirmation asked when enabling one, and the reason the Extensions tab can never be removed by an extension.
