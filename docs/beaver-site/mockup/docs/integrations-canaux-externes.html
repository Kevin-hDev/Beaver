Driving the agent from a messaging app

External channels let you send a message to your Beaver agent from Telegram, Slack or Discord, and receive its answer in the same place. The agent still runs on your machine — only the entry point changes. The typical use: starting a task from your phone, or checking on the progress of long-running work without being in front of the computer.

Warning Beaver must stay open on your machine. This is not a hosted service: it is your local application that listens. Closed, the channel no longer answers.

Up to 16 accounts per messaging app can be configured — several bots, several workspaces.

What you have to set up

  • Create the bot or the application at the messaging app.
  • Retrieve its token.
  • Enter it in Settings › Integrations › Channels.
  • Declare the allowed users — mandatory, see the next section.
  • Choose the provider and the model that will be used to answer.
  • Enable the account.

The token is checked with the messaging app before activation: that tells an invalid token apart from a network problem, before starting. Tokens are then protected like API keys — encrypted vault, master key in the system password manager, no reading possible from the interface. See The vault and API keys.

The allowlist is mandatory

This is the most important protection on this page, and there is no way around it. An active channel must declare at least one allowed user: a channel enabled with an empty list is refused when saved. And the wildcard is forbidden — there is no way to write "everyone". Every allowed user has to be named by their identifier.

Security A messaging bot can be reached by anyone who knows its name. Without an allowlist, opening a channel would amount to handing strangers an agent that runs commands on your machine. Beaver makes that configuration impossible.

Up to 100 allowed users per account. Duplicates are refused, and every identifier is validated.

How conversations are tied together

Each correspondent on a messaging app is associated with one Beaver conversation, in a stable way: writing twice from the same place continues the same conversation, with its history. That mapping is recorded on disk and survives a restart of the application.

It is bounded: beyond the maximum number configured, the oldest mapping is removed, and the correspondent concerned starts over on a fresh conversation. The limit is adjustable, up to 1,000. That file's format carries a version number, and an earlier version is not reused: it is ignored and starts from scratch rather than being misread.

The rate limits

Three independent caps, all adjustable, each protecting something different.

The three rate caps
CapWhat it protects
Per user per minuteA single user cannot saturate the service
Per channel per minuteAn active channel does not starve the others
Global per minuteThe machine stays usable

Each one accepts up to 10,000 messages per minute, but none can be zero: there is always an active limit. A message is otherwise limited to 12,000 characters at the maximum configurable value.

The audit log

All channel activity is recorded: who wrote, when, on which channel, and what was decided — message handled, user refused, limit reached. The retention period is adjustable, up to 365 days.

Note It is the only way to answer "who talked to my agent, and when". On a feature that exposes the agent to the outside, that log is not an accessory.

Monitoring the service

Channels run in the background and their operation is monitored: a supervisor restarts them if they stop, and a watchdog detects hangs. Two protections deserve a mention. A conversation is locked while it is being handled: two messages arriving at the same time from the same place are not handled in parallel, which would otherwise produce two answers tangled together in the same conversation. And the answer is captured then sent, rather than streamed word by word: a messaging app does not accept hundreds of successive edits to the same message.

What is not possible

  • Account sign-ins cannot serve as a channel's model. They assume a person in front of the screen to authenticate, which is not the case for a message arriving at night. You need an API key, or a local model.
  • Beaver has to be open. Closing the application cuts the channel off.
  • No wildcard in the allowlist, and an active channel with no allowed user is refused.
Security The agent has the same powers as in front of the screen. A message received through a messaging app starts an agent that reaches your files and runs commands. The permission mode and the disk access scope apply — and are worth reviewing before opening a channel. See Permission modes and Working directory.
