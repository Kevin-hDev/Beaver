System prompts

The instructions given to the model before your first message: its role, how to use the tools, the format expected of its answers. Beaver provides defaults, and they can be viewed, edited, replaced and disabled.

Not to be confused with your own instructions: the system prompt comes from Beaver, AGENTS.md comes from you. See Standing instructions.

Two modes, two formats

Two modes, depending on how you work: Chatbot for a conversation without tools, Agentic for work with tools. And two levels of detail for each mode: Compact, the tightened version, and Detailed, the full version.

That is four prompts per scope, each configurable independently.

The format is chosen automatically

A non-obvious point: the format depends on the model used, not on a manual setting. The choice is made from the size of the model — a small model gets the compact version, a large one the detailed version.

Why A long prompt takes up a large share of a small model's context: it drowns it rather than guiding it. The compact version leaves it room to work.

Two scopes: global or per model

Scope of a prompt setting

The per-model setting takes priority over the global setting. This per-model scope only exists for models served by the local engine: they are the only ones whose full lifecycle Beaver manages.

The text actually used can have three origins: Beaver's, the model's, or yours.

Warning Without a system prompt, the model knows neither how to use the tools nor what format to adopt. The Disabled state is usable for a specific purpose, not as an everyday setting.
An empty field disables Saving an empty custom prompt does not restore the original prompt: it disables the system prompt. This is deliberate — emptying the field is an explicit way of switching it off. To go back to the default, use “Restore”.

The native prompts of local models

An Ollama model can carry its own system prompt, defined by its author. Beaver preserves that native prompt before any customization, in dedicated storage, and indicates whether a native prompt is available for the current model.

You can therefore choose explicitly between the behavior intended by the model's author and Beaver's: customizing a model does not destroy what it carried.

Editing, disabling, restoring

Three operations, in Settings › System prompt: save custom content, disable the prompt, restore the original prompt.

Two guards accompany these operations: a warning before replacing an already customized prompt, and a one-click copy to the clipboard before the text is lost.
