Beaver from a terminal

A small companion command, beaver, ships with the application. It does not drive the agent and it does not open conversations: it answers the questions you ask when something is off. Where are my files? Is anything running? What is broken? What do the logs say? Is there a new version? What can be deleted safely?

It reads the same data folder as the application, and it never needs the application to be open — two of its commands actually require it to be closed.

Where it lives

It is bundled inside the application, beside the main executable. There is no separate installation, and nothing is added to your PATH: you call it by its full path, or you make a shortcut to it yourself.

Where the command sits on each system
SystemPath
macOS/Applications/Beaver.app/Contents/MacOS/beaver
Windowsbeaver.exe, in the Beaver installation folder
Making it shorter On macOS, one line in your shell's configuration file is enough: alias beaver="/Applications/Beaver.app/Contents/MacOS/beaver". Nothing in Beaver depends on it — it is purely for your own comfort.

The commands

Running beaver with no argument, or with --help, prints the list.

The seven commands, and what each one actually does
CommandWhat it does
beaver --versionPrints the installed version, then the full path of the binary that answered. Useful when you suspect you are calling an old copy.
beaver pathsLists ten places on disk — the data folder, the configuration, the vault, the conversations, the logs, the projects, the skills, the tool results, the MCP connectors and the Ollama engine — and marks the ones that do not exist yet.
beaver statusSays whether the application is open, whether an Ollama process is present, how many models are installed and how much they weigh, the total size of the data folder and its three largest subfolders.
beaver doctorRuns nine local checks and prints each one as passed or failed, with a one-line fix for every failure.
beaver logsPrints the end of one of the three log files. Defaults to the application log, last 50 lines.
beaver updateChecks for a new version and, if the application is closed and you confirm, downloads and installs it.
beaver cleanupLists what can be deleted without losing anything, then deletes it after you confirm. Requires the application to be closed.

paths

Everything Beaver writes lives under one folder, and this command tells you where, without you having to know the convention. Each line that points at something not yet created says so explicitly, which is the answer to “is my configuration missing, or have I simply never changed it?”

$ beaver paths
Data directory : /Users/you/.local/share/cl-go-dash
Configuration : /Users/you/.local/share/cl-go-dash/config.json
Vault : /Users/you/.local/share/cl-go-dash/secrets.enc (not created yet)

status

A snapshot of the machine, not of the servers. It looks at the processes actually running and at the folders actually on disk — it does not ask anything over the network, and it does not claim the Ollama service is answering, only that its process is there.

The three largest subfolders are listed because the answer to “why is Beaver taking so much room?” is almost always one of them.

doctor

Nine checks, in this order. A failed check prints an arrow and the thing to do.

What doctor checks, and what a failure means
CheckIt fails when
Data directoryThe folder cannot be written to
Configuration fileconfig.json exists but is not valid
API key vaultProviders are registered but the vault file has gone
Interrupted Ollama downloadA download was cut off partway
Ollama bundleThe engine is there but incomplete
Ollama stagingAbandoned preparation folders are left over
Active log limitsA log file has grown past its own cap
Root temporary files.tmp files are left at the top of the data folder
Free disk spaceLess than 2 GB is available

An absent file is not a failure: a machine where Beaver has never been launched passes. The command exits with 1 as soon as one check fails, which is what makes it usable in a script.

logs

beaver logs [app|gateway|reveils] [-n N]

The three log sources
SourceFileWhat is in it
applogs/beaver.logThe application's main log. This is the default.
gatewaylogs/gateway-audit.jsonlThe audit trail of the external channels
reveilslogs/wakeups.jsonlThe history of scheduled wake-up runs

-n takes a whole number between 1 and 5,000; without it, the last 50 lines are printed. A source that does not exist yet is not an error: the command says so and exits normally.

Control characters in the log are replaced with ? before printing, and a line is cut at 16,384 characters. The reason is not cosmetic: a log line can contain anything, and anything printed raw into a terminal can take control of it.

update

It checks the published version, tells you which one is available, and asks before doing anything. Three answers are possible: up to date, an update is available, or the check could not be made.

  • The application must be closed. If it is open, the command says so and stops. It also checks again after your answer: opening Beaver while it waits for your confirmation cancels the update rather than applying it underneath you.
  • The confirmation is explicit — y to go ahead, anything else cancels.
  • The download is verified against the signed manifest, its size and its SHA-256 fingerprint before being applied.
  • The install then continues in the background. Run beaver --version again a minute later to check it went through.

cleanup

The careful one. It never touches your conversations, your projects, your settings or your vault. It only lists four families of leftovers, all of which are debris rather than data.

What cleanup considers deletable
FamilyCriterion
Rotated application logsOlder than 30 days
Interrupted Ollama downloadsPartial files left behind by a cut-off transfer
Abandoned Ollama stagingPreparation folders no installation is using
Tool resultsOlder than 24 hours

It prints each item with its size and a total, then asks. beaver cleanup --dry-run stops right there: it shows the list and deletes nothing, which is the version to run first. Like update, it refuses to run while Beaver is open, and re-checks after your answer.

It is also the command doctor points you to when it finds abandoned staging folders or stray temporary files.

Language and exit codes

The command speaks French or English, and it decides on its own: it reads LC_ALL, then LC_MESSAGES, then LANG, and falls back to the system locale. Anything that is not French gives English. That is also how you force it in a script — LANG=en_US.UTF-8 beaver doctor.

What the exit code means
CodeMeaning
0Everything went as expected — including “nothing to clean” and “already up to date”
1A problem was found, or the operation failed
2The command line itself was wrong: unknown command, unknown source, bad line count
