Installing on Windows

Beaver is distributed as an NSIS installer for Windows x64. The PowerShell script checks every redirect, the size and the fingerprint of the file before starting the installation. Windows is going to react: this page says why and what to do.

The recommended method: the script

To paste into PowerShell, not into the classic command prompt:

> $installer = Join-Path ([IO.Path]::GetTempPath()) "beaver-install-$([Guid]::NewGuid().ToString('N')).ps1"
  try {
    Invoke-WebRequest https://raw.githubusercontent.com/Kevin-hDev/Beaver/main/install.ps1 -OutFile $installer -ErrorAction Stop
    & $installer
  } finally {
    Remove-Item -LiteralPath $installer -Force -ErrorAction SilentlyContinue
  }

What the script does

  • It checks that the processor architecture is AMD64. Any other value stops the installation.
  • It forces TLS 1.2 and disables automatic redirect following: every redirect is examined before being followed.
  • It queries the GitHub Releases API, with the response capped at 512 KiB.
  • It requires the asset named exactly Beaver_<version>_x64-setup.exe.
  • It downloads update-manifest.json, capped at 64 KiB, and checks that its size matches the announced one.
  • It checks that the manifest carries the expected version, and that every asset entry has a conforming name, a SHA-256 fingerprint of 64 hexadecimal characters and a size.
  • It downloads the installer, with a maximum delay of 1800 seconds, and checks that the received size matches the expected one exactly.
  • It computes the file's SHA-256 and compares it to the one in the manifest. On any mismatch, the installation stops.
  • It offers the installation folder, %LOCALAPPDATA%\Beaver by default.
  • It runs the NSIS installer in silent mode, window hidden.
  • It checks that cl-go-dash.exe exists in the installation folder and that it is not a reparse point — a protection against substitution by link.

The alternative method: the installer

The Beaver_X.Y.Z_x64-setup.exe installer is attached to every GitHub release: double-click and the usual flow. Its downside: SmartScreen steps in on an unsigned executable downloaded through a browser, and the fingerprint check is up to you.

SmartScreen and the missing signature

The application is not signed with a code-signing certificate. Windows SmartScreen therefore shows a blue “Windows protected your PC” screen when the installer runs. The workaround is to click “More info”, then “Run anyway”.

This behavior is normal for unsigned free software: a code-signing certificate is paid and issued to a named holder.

SmartScreen Windows will show “Windows protected your PC”. Click “More info”, then “Run anyway”.

Windows Defender and controlled folder access

If ransomware protection (“Controlled folder access”) is on, ollama.exe may be blocked on first launch, when it tries to write models to ~/.ollama/models/. A Windows notification appears and you need to click “Allow”. The request does not come back afterwards.

Without that explanation, the symptom you observe is “the model download fails for no reason”.

Allow Ollama If Windows shows a blocking notification on the first model download, click “Allow”. It is ransomware protection preventing Ollama from writing models to the disk. The request appears only once.

Choosing another installation folder

The default is %LOCALAPPDATA%\Beaver. Another path can be entered, with strict checks; a non-conforming path stops the installation.

Updating

Unlike macOS and Linux, where the script stops if an installation is detected, the Windows script does not perform that check: the NSIS installer handles the replacement itself. The normal route remains the built-in update in the application: Updating.

Uninstalling

The NSIS installer lays down an uninstaller: removal goes through Settings › Apps, or through the uninstaller in the installation folder. The data stays in C:\Users\<user>\.local\share\cl-go-dash\, and the vault's master key stays protected by DPAPI.
