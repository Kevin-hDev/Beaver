Installing on Windows

Beaver is distributed as an NSIS installer for Windows x64. The PowerShell script checks every redirect, the size and the fingerprint of the file, then opens the Beaver installer, which asks where to install and shows what it is doing. Windows is going to react: this page says why and what to do.

The recommended method: the script

To paste into PowerShell, not into the classic command prompt:

> $installer = Join-Path ([IO.Path]::GetTempPath()) "beaver-install-$([Guid]::NewGuid().ToString('N')).ps1"
  try {
    Invoke-WebRequest https://raw.githubusercontent.com/Kevin-hDev/Beaver/main/install.ps1 -OutFile $installer -ErrorAction Stop
    & $installer
  } finally {
    Remove-Item -LiteralPath $installer -Force -ErrorAction SilentlyContinue
  }

What the script does

The script goes as far as opening the Beaver installer, and no further. The installation itself happens in the window that appears.

  • It checks that the processor architecture is AMD64. Any other value stops the installation.
  • It forces TLS 1.2 and disables automatic redirect following: every redirect is examined before being followed.
  • It queries the GitHub Releases API, with the response capped at 512 KiB.
  • It requires three assets named exactly: the installer Beaver_<version>_installer-x64.exe, the application Beaver_<version>_x64-setup.exe, and update-manifest.json.
  • It downloads update-manifest.json, capped at 64 KiB, and checks that its size matches the announced one.
  • It checks that the manifest carries the expected version, and that every asset entry has a conforming name, a SHA-256 fingerprint of 64 hexadecimal characters and a size.
  • It downloads the installer, with a maximum delay of 1800 seconds, and checks that the received size matches the expected one exactly.
  • It computes the file's SHA-256 and compares it to the one in the manifest. On any mismatch, the installation stops.
  • It starts the installer and hands it the name, the size and the SHA-256 of Beaver_<version>_x64-setup.exe, read from the manifest. The installer will accept no other file.
  • It ends with “The Beaver installer has opened.” and gives PowerShell back to you.

The Beaver installer

One window, one screen at a time. At the top, the version about to be installed; underneath, the Installation folder, set to %LOCALAPPDATA%\Beaver, with a Browse button to change it.

If Beaver is running, the installer asks you to close it first and keeps the button disabled until you do. Once started, the installation shows five steps, each with its own bar and, once done, the time it took.

The five steps of the installation
StepWhat happens
Checking the systemThe folder is checked again, and Beaver must not be running
Downloading BeaverBeaver_X.Y.Z_x64-setup.exe is downloaded, with the percentage shown
Verifying integritySize and SHA-256 compared to the values handed over by the script
Installing in the chosen folderThe NSIS installer runs in silent mode, window hidden, into that folder
Finishingcl-go-dash.exe is checked in place, then temporary files are removed

That last check is the one that protects against substitution by link: cl-go-dash.exe must be present in the installation folder and must not be a reparse point.

Show details opens the log of what is happening. Cancel stays available until the silent installer is launched; after that the window says “The installation can no longer be cancelled”. At the end, “Beaver is ready” and a Launch Beaver button. On failure, “Installation interrupted”, the reason in plain words, and a Retry button; the previous installation remains intact. On cancellation, “Installation cancelled — Nothing was installed: the installation folder is unchanged.”

The alternative method: the setup file

The Beaver_X.Y.Z_x64-setup.exe installer is attached to every GitHub release: double-click and the usual flow. Its downside: SmartScreen steps in on an unsigned executable downloaded through a browser, and the fingerprint check is up to you.

SmartScreen and the missing signature

The application is not signed with a code-signing certificate. Windows SmartScreen therefore shows a blue “Windows protected your PC” screen when the installer runs. The workaround is to click “More info”, then “Run anyway”.

This behavior is normal for unsigned free software: a code-signing certificate is paid and issued to a named holder.

SmartScreen Windows will show “Windows protected your PC”. Click “More info”, then “Run anyway”.

Windows Defender and controlled folder access

If ransomware protection (“Controlled folder access”) is on, ollama.exe may be blocked on first launch, when it tries to write models to ~/.ollama/models/. A Windows notification appears and you need to click “Allow”. The request does not come back afterwards.

Without that explanation, the symptom you observe is “the model download fails for no reason”.

Allow Ollama If Windows shows a blocking notification on the first model download, click “Allow”. It is ransomware protection preventing Ollama from writing models to the disk. The request appears only once.

Choosing another installation folder

The default is %LOCALAPPDATA%\Beaver, and the Browse button lets you pick another one. The checks are strict; a non-conforming folder is refused instead of being installed into.

Updating

The Windows script never refused to run over an existing installation, and that has not changed: the NSIS installer handles the replacement itself, and your conversations, keys and settings are not touched. Unlike macOS, the window does not read the version already in place, so it says “Install” and not “Reinstall” — it will replace all the same.

The normal route remains the built-in update in the application: Updating. Going back through the script is the way out when that update cannot run.

Uninstalling

The NSIS installer lays down an uninstaller: removal goes through Settings › Apps, or through the uninstaller in the installation folder. The data stays in C:\Users\<user>\.local\share\cl-go-dash\, and the vault's master key stays protected by DPAPI.
