Install, configure, browse

Three tabs, three different natures: one installs what runs on your machine, another installs and tunes what forecasts, the third only documents what runs elsewhere. This page describes their structure and what you can do in them.

What the section contains — and what it doesn't

The three tabs of the Models section
TabNatureWhat you do there
OllamaManagementInstall, update, remove and customise local models
ForecastManagement and configurationInstall forecast models and set their parameters
LLMRead-onlyBrowse the catalog of remote models: context, costs, capabilities

Two things people often look for here that aren't here:

  • The Ollama engine settings — memory release, processor or graphics card, several models at once — are in Agent › Advanced. The Ollama tab manages the models, not the engine that runs them.
  • The API keys and accounts of remote model providers are in Integrations › Providers. The LLM tab shows what exists; it connects nothing.

Ollama tab

The tab splits into two sub-tabs.

The two sub-tabs of the Ollama tab
Sub-tabContent
ModelsBrowse the Ollama catalog by family, choose a variant, install it
ModelfileCustomise a model already installed

The Models sub-tab offers a search and a two-level navigation: first a model family, then a specific variant inside that family. A variant's detail screen shows its real characteristics before installation — Hardware and VRAM explains how to read them, and Local models describes the installation.

The Modelfile sub-tab lists the models already installed and lets you change their definition. When no model is installed, the screen shows “No model installed”. It's also where the system instructions specific to an Ollama model are set, distinct from the global instructions of Agent › System prompt — the detail is in Customisation.

Ollama tab — when the engine isn't ready

This tab is the only one in the settings whose content depends entirely on the state of an outside service. The screen changes completely depending on the situation.

What the tab shows depending on the local engine's state
Engine stateWhat the tab shows
Being readA waiting message
State unreadableAn error message with a button to try again
Ollama absentThe Ollama installation screen, not the list of models
Installation under wayA progress message
Repair neededAn error message with a button to try again
ReadyThe two sub-tabs described above

An information banner about the service's state is shown above the sub-tabs in every case where the engine is ready. The states it distinguishes belong to Local engine, which covers the engine's life cycle.

Note On a fresh installation, this tab offers to install Ollama. As long as the engine isn't there, it shows the installation screen instead of the list of models. This isn't a failure: it's one of the paths provided for installing the engine after skipping the step during onboarding.

Forecast tab

The tab splits into two sub-tabs.

The two sub-tabs of the Forecast tab
Label shownContent
ConfigThe parameters of the selected forecast model
ModelsThe forecast models available, to install or uninstall

The Models sub-tab is organised like Ollama's: families, then model. Each model shows its state — Installed, Not installed, Preparation required, Update required, or for a remote model Cloud (key required), or even API key not configured when the key is missing. The actions are Install, Prepare and Uninstall, the last one asking for a confirmation.

A model's card gives, as applicable: Disk size, RAM, CPU and GPU (supported or not), License, Library, Pipeline, Max horizon, Frequencies and its Model capabilities.

The Config sub-tab only concerns configurable models: it presents the parameters of the chosen model, with an Edit button, then Save or Cancel. Each parameter has its description in the application — maximum horizon, historical context, quantiles, precision, numeric type. When no configurable model is installed, the screen shows “No Forecast model is installed or configured.”

The effect of these parameters on a forecast is covered in Local forecast models and Model selection.

Warning Installing a Forecast model isn't enough for the agent to use it. The Forecast tool group is off at installation; it is turned on in Agent › Tools.

LLM tab

It's the only tab in the section that sets nothing. It's a reference catalog: you look up a remote model to know what it can do, how much it costs and what context size it accepts.

The screen presents a search bar — “Search a model…” — and a “Families” button that unfolds a grid of model families. A search or a family opens a list; a model from that list opens its card, with a “Back” link. The card gives the model's key at the top, then its provider and its mode, and then two cards.

The measurements — only those filled in appear:

The measurements shown on a remote model's card
LineWhat it givesFormat
Context (input)The size of the input windowIn thousands of tokens, for example 128K
Max outputThe maximum length of an answerSame
Input costThe price per million tokens sentIn dollars, $0.50/M
Output costThe price per million tokens producedSame

The capabilities — five lines, always present, each worth Yes or No:

The five capabilities listed for each remote model
LineWhat it says
VisionDoes the model accept images
ToolsCan it use tools — and therefore work as an agent
ReasoningDoes it produce a thinking phase
Prompt cachingCan it reuse a context already sent, which lowers the cost
Web searchDoes it have a provider-side web search

Two clarifications. The costs are those of the catalog embedded in Beaver, not a live reading from the provider: they age between two versions of the application — see Usage and costs. And the “Tools” capability is the most decisive: a model that can't call tools can't work as an agent, whatever its other qualities.

Note The LLM tab connects nothing. It doesn't say whether you have a key for a model or whether it's usable on your machine: Integrations › Providers is what answers that question. To choose a model day to day, see Catalog and favorites.

Three tabs, three natures

  • Ollama installs what runs on your machine;
  • Forecast installs and tunes what forecasts — the module itself is described in Forecast;
  • LLM only documents what runs elsewhere.
Warning The Ollama engine isn't set in the Ollama tab. That tab installs and customises the models; memory release, the processor or graphics card choice and loading several models at once are in Agent › Advanced.
