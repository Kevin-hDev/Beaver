The first launch

On first start, Beaver creates its data folder, possibly picks up the data from an earlier installation, walks you through an onboarding flow and offers to install Ollama — an offer you may decline. Here is what lands on your disk, and the state you start from.

The startup sequence

  • Splash screen — the application icon is shown while the interface loads. The background follows the light or dark theme kept from the previous launch, and disappears with no transition as soon as the application is ready.
  • Storage initialization — creation of the data folder and its structure if they do not exist, possible migration from an older location.
  • Onboarding flow — four to five steps depending on whether Ollama is already present, described in Onboarding flow.
  • Application — the main window.

The data folder

It is the same path on all three systems.

Where your data lives
SystemPath
macOS~/.local/share/cl-go-dash/
Linux~/.local/share/cl-go-dash/
WindowsC:\Users\<user>\.local\share\cl-go-dash\

Two things are surprising, so let us get them out of the way. The name cl-go-dash is a historical identifier: the application was called CL-GO before becoming Beaver, and changing the folder name would have forced a move of every existing user's data. Beaver moves, copies and recreates nothing. And on Windows, the location is unusual: you would rather look in %APPDATA%, where there is nothing.

Why this folder name The folder is called cl-go-dash, the project's former name. It is kept as is so that existing installations keep working without moving any data.

Folders: memory/core, inbox, skills, agent-sessions, tool-results, translations, logs.

Five files are created empty: AGENTS.md, memory/core/identity.md, memory/core/principles.md, memory/core/user.md and inbox/idea-discovery.md. The terminal-tabs.json file, for its part, appears only the first time you use the terminal. One additional component is installed at that moment too: the local forecasting engine.

The default permission mode On a fresh installation, Beaver is in Full access: the agent runs its tools without asking for confirmation. If you prefer to approve every action, switch to Ask permission before starting your first task — see Permission modes.

Migration from an earlier installation

Three automatic migrations exist, each marked by a witness file so it does not repeat.

Your existing data is kept If you were already using CL-GO, or an earlier version of Beaver storing its data elsewhere, your conversations and settings are picked up automatically on first start. There is nothing to do by hand.

The Ollama download

Ollama is not included in the application, and it is never downloaded behind your back: the onboarding flow shows you a button, and nothing leaves until you have clicked it. You can skip the step — Beaver then works with remote models, through an API key or a connected web account. If you change your mind later, the installation can be started from Settings › Ollama.

Beaver considers the engine available if port 11434 is open, or if the binary already exists in ~/.local/share/cl-go-dash/ollama-bundle/. If an Ollama daemon is already running — because Ollama is installed separately — Beaver uses it as is and offers no download.

What follows describes what happens if you accept the download.

Archive downloaded per system
SystemArchiveChoice depending on the GPU
macOSollama-darwin.tgzNo — Metal is built in
Windowsollama-windows-amd64.zipNo — single archive
Linuxollama-linux-amd64.tar.zst or the ROCm variantYes — GPU vendor detection

The download is checked end to end: the exact size is announced by a preliminary request then verified to the byte on receipt, with a cap of 3 GiB and a maximum delay of 1800 seconds; the SHA-256 fingerprint is compared in constant time against the one published by the Ollama project; the presence of the binary is checked after extraction; the temporary archive and the destination folder are cleaned up on failure.

Declining has no lasting consequence. The application stays fully usable with remote models, and the install button waits for you in Settings › Ollama the day you want a local one.

One instance at a time

Launching Beaver a second time does not create a second window: focus returns to the one already open. The behavior is identical on all three systems.

The macOS behavior follows the system's conventions, but surprises anyone coming from Windows: the application looks closed while it is still running.
