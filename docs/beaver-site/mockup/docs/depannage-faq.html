Frequently asked questions

The short questions that have no page of their own: where your files are, how to back them up, what works without the internet, what the app sends on its own, under which license it is published, how to uninstall it. The questions that have their own page are listed at the end, one line each.

Where is my data?

In a single folder, identical on macOS, Windows and Linux.

$ ~/.local/share/cl-go-dash/

On Windows, that corresponds to C:\Users\<your account>\.local\share\cl-go-dash\: an unusual location for that system, inherited from the choice of a single path across all three.

The shortcut from inside the app: Settings › Advanced › Beaver data › Open folder button, described as “Open the folder containing sessions, memory, and local settings”.

This folder does not move. No setting, no environment variable allows it to be changed.

Two things live outside this folder, and that is what makes the next question important: the key that opens your API keys, entrusted to your system's secret manager, and the interface language and theme, kept in the local storage of the display component. Ollama's local models are somewhere else again — see Local models.

How do I back everything up — and what does not restore?

There is no backup or restore function in the app. Nothing in the settings, nothing elsewhere: the only action provided is the button that opens the folder.

Note Backing up means copying a folder. Close Beaver, copy ~/.local/share/cl-go-dash/, and know that your API keys will not restore from it: they are encrypted by a key that stayed in the keychain of the original machine.

What the copy restores, on the same machine or on another: conversations, projects, memory, settings, forecast analyses, notes, configured connectors.

What the copy does not restore, and why
ItemWhy
Your API keysThe secrets.enc file is encrypted by a key that stayed in the old machine's keychain. Beaver deliberately refuses to make a new one: the keys must be entered again
The interface languageIt is in the local storage of the display component, not in the data folder: the app restarts in English
The themeSame reason: it goes back to “system”
The local modelsThey live outside this folder and weigh several gigabytes
Warning Emptying your system keychain makes your keys unreadable. Beaver deliberately refuses to make a new master key when the old one has disappeared: that would overwrite a still-valid vault. You then have to enter all your keys again.

One more reason to make that copy: several of the app's error messages ask you to restore a file “from a backup” — for example “The Ollama customization file is unreadable. Restore “ollama-custom-models.json” from a backup in Settings > Advanced > Beaver data.” The app therefore assumes a backup it never offered to make. Failing a copy, the second fallback these messages offer is the only one available: delete the named file and relaunch, to start again from the default values.

Why does Beaver ask for my keychain at startup?

Because your API keys are encrypted, and the key that decrypts them is entrusted to your system's secret manager — Keychain Access on macOS, Credential Manager on Windows, the desktop secret service on Linux.

This only happens once per launch. Reading that key happens in the initialization routine, at startup, and nowhere else: you are not asked on every request.

On the very first launch, there is nothing to read: Beaver draws 32 bytes at random and puts them in the keychain. That is when the system may ask for permission.

If you refuse, or if no secret service is running — a common case on a minimal Linux session — the app starts anyway, shows a banner, and refuses any operation on the API keys. Local models, which need no key, keep working. The detail is on The vault and API keys.

Does Beaver work without the internet?

Yes, for the most part — provided you have already installed what you use.

What works offline:

  • local models, once downloaded;
  • local forecasting models, once installed: their engine is started in forced offline mode on every launch, and a test locks that behavior in;
  • everything touching your files, the terminal, Git, and the conversations already saved.

What does not work:

  • remote models, whichever they are;
  • web search, external connectors, messaging channels;
  • installing anything at all: a local model has to be downloaded, and a forecasting model also downloads libraries.

The special case of the very first launch: Beaver needs the internet once, to fetch the Ollama engine. See Troubleshooting · Installation.

Does Beaver contact the internet on its own?

Yes, for one thing only: checking for updates.

The check goes out when the app launches, then every hour. It covers three things at once: the Beaver version, the Ollama engine version, and updates to your installed Ollama models.

For the app, the address queried is https://api.github.com/repos/Kevin-hDev/Beaver/releases/latest. No personal data is sent there: it is a public read of the latest published version.

On failure, nothing is displayed. The message “The update check failed. Try again shortly.” only appears if you started the check yourself. A Beaver that never announces an update is therefore not necessarily up to date: trigger the check by hand from the updates indicator.

Note A single automatic connection. At launch and then every hour, Beaver asks GitHub whether a newer version exists, and asks Ollama whether your models have moved.

On telemetry, what is established: Beaver disables the telemetry of the components it launches — the forecasting processes start with telemetry switched off. The detail of what leaves the machine and what does not is covered on Privacy, which is the authority on this point.

Does closing the window quit the app?

It depends on the system, and the difference is deliberate.

What the close button does, system by system
SystemWhat the close button does
macOSThe window is hidden, the app keeps running. It reopens by clicking the Dock icon
Windows and LinuxThe app closes

On all three systems, an icon in the system tray is shown by default, and the setting is in Settings › Advanced. On Mac, to actually quit, go through the app menu or the system tray icon.

Does Beaver start with my machine?

No, not by default. The Launch at startup setting exists but is off at installation, as is Start hidden, which launches the app in the background without opening the window. Both are in Settings › Advanced, described on Settings · Agent.

Where is the version number?

Settings › About. The screen shows the Beaver version, the version of its application framework, and the operating system detected, plus a View on GitHub button that opens https://github.com/Kevin-hDev/Beaver. That is the number to give when you report a problem.

How do I uninstall cleanly?

Removing the app is not enough: three things remain.

  • The data folder ~/.local/share/cl-go-dash/ — conversations, settings, forecasting models, encrypted vault.
  • The secret manager entry of your system, under the service name cl-go-dash, identifier master-key. As long as it is there, it is of no further use; deleted, the vault becomes permanently unreadable.
  • The Ollama models, which live in a folder shared with any other Ollama installation on the machine — not to be deleted without checking.

The procedure system by system is on Troubleshooting · Installation, which is the authority. This page does not duplicate it: it only recalls the three leftovers.
