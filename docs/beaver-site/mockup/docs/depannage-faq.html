Questions fréquentes

Les questions courtes qui n'ont pas de page à elles : où sont tes fichiers, comment sauvegarder, ce qui marche sans Internet, ce que l'application envoie toute seule, sous quelle licence elle est publiée, comment la désinstaller. Les questions qui ont leur propre page sont renvoyées en fin de page, en une ligne chacune.

Où sont mes données ?

Dans un seul dossier, identique sur macOS, Windows et Linux.

$ ~/.local/share/cl-go-dash/

Sous Windows, cela correspond à C:\Users\<ton compte>\.local\share\cl-go-dash\ : un emplacement inhabituel pour ce système, hérité du choix d'un chemin unique sur les trois.

Le raccourci depuis l'application : Réglages › Avancé › Données Beaver › bouton Ouvrir le dossier, décrit comme « Ouvrir le dossier qui contient les sessions, la mémoire et les réglages locaux ».

Ce dossier ne se déplace pas. Aucun réglage, aucune variable d'environnement ne permet de le changer.

Deux choses vivent en dehors de ce dossier, et c'est ce qui rend la question suivante importante : la clé qui ouvre tes clés API, confiée au gestionnaire de secrets de ton système, et la langue et le thème de l'interface, rangés dans le stockage local du composant d'affichage. Les modèles locaux d'Ollama, eux, sont ailleurs encore — voir Modèles locaux.

Comment je sauvegarde tout — et qu'est-ce qui ne se restaure pas ?

Il n'existe aucune fonction de sauvegarde ni de restauration dans l'application. Rien dans les réglages, rien ailleurs : la seule action prévue est le bouton qui ouvre le dossier.

Note Sauvegarder, c'est copier un dossier. Ferme Beaver, copie ~/.local/share/cl-go-dash/, et sache que tes clés API ne s'y restaureront pas : elles sont chiffrées par une clé restée dans le trousseau de la machine d'origine.

Ce que la copie restaure, sur la même machine ou sur une autre : les conversations, les projets, la mémoire, les réglages, les analyses de prévision, les notes, les connecteurs configurés.

Ce que la copie ne restaure pas, et pourquoi
ÉlémentPourquoi
Tes clés APILe fichier secrets.enc est chiffré par une clé restée dans le trousseau de l'ancienne machine. Beaver refuse volontairement d'en fabriquer une nouvelle : les clés sont à ressaisir

Attention Vider le trousseau de ton système rend tes clés illisibles. Beaver refuse volontairement de fabriquer une nouvelle clé maîtresse quand l'ancienne a disparu : cela écraserait un coffre encore valable. Il faut alors ressaisir toutes tes clés.

Une raison de plus de faire cette copie : plusieurs messages d'erreur de l'application te demandent de restaurer un fichier « depuis une sauvegarde » — par exemple « Le fichier de personnalisation Ollama est illisible. Restaure « ollama-custom-models.json » depuis une sauvegarde dans Réglages > Avancé > Données Beaver. » L'application suppose donc une sauvegarde qu'elle n'a jamais proposé de faire. À défaut de copie, le second recours proposé par ces messages est le seul disponible : supprimer le fichier nommé et relancer, pour repartir des valeurs par défaut.

Pourquoi Beaver demande-t-il mon trousseau au démarrage ?

Parce que tes clés API sont chiffrées, et que la clé qui les déchiffre est confiée au gestionnaire de secrets de ton système — Trousseau d'accès sur macOS, Gestionnaire d'identifiants sur Windows, service de secrets du bureau sur Linux.

Cela n'arrive qu'une fois par lancement. La lecture de cette clé a lieu dans la routine d'initialisation, au démarrage, et nulle part ailleurs : tu n'es pas sollicité à chaque requête.

Au tout premier lancement, il n'y a rien à lire : Beaver tire 32 octets au hasard et les dépose dans le trousseau. C'est à ce moment que le système peut demander une autorisation.

Si tu refuses, ou si aucun service de secrets ne tourne — cas courant sur une session Linux minimale — l'application démarre quand même, affiche un bandeau, et refuse toute opération sur les clés API. Les modèles locaux, qui n'ont besoin d'aucune clé, continuent de fonctionner. Le détail est sur Le coffre et les clés API.

Est-ce que Beaver fonctionne sans Internet ?

Oui, pour l'essentiel — à condition d'avoir déjà installé ce dont tu te sers.

Ce qui fonctionne hors ligne :

  • les modèles locaux, une fois téléchargés ;
  • les modèles de prévision locaux, une fois installés : leur moteur est démarré en mode hors ligne forcé à chaque lancement, et un test verrouille ce comportement ;
  • tout ce qui touche à tes fichiers, au terminal, à Git, et aux conversations déjà enregistrées.

Ce qui ne fonctionne pas :

  • les modèles distants, quels qu'ils soient ;
  • la recherche web, les connecteurs externes, les canaux de messagerie ;
  • l'installation de quoi que ce soit : un modèle local se télécharge, et un modèle de prévision télécharge aussi des bibliothèques.

Le cas particulier du tout premier lancement : Beaver a besoin d'Internet une fois, pour récupérer le moteur Ollama. Voir Dépannage · Installation.

Est-ce que Beaver contacte Internet tout seul ?

Oui, pour une seule chose : chercher les mises à jour.

La vérification part au lancement de l'application, puis toutes les heures. Elle porte sur trois choses à la fois : la version de Beaver, la version du moteur Ollama, et les mises à jour de tes modèles Ollama installés.

Pour l'application, l'adresse interrogée est https://api.github.com/repos/Kevin-hDev/Beaver/releases/latest. Aucune donnée personnelle n'y est envoyée : c'est une lecture publique de la dernière version publiée.

En cas d'échec, rien ne s'affiche. Le message « La recherche des mises à jour a échoué. Réessaie dans un instant. » n'apparaît que si tu as lancé la vérification toi-même. Un Beaver qui n'annonce jamais de mise à jour n'est donc pas forcément à jour : déclenche la vérification à la main depuis l'indicateur de mises à jour.

Note Une seule connexion automatique. Au lancement puis toutes les heures, Beaver demande à GitHub s'il existe une version plus récente, et à Ollama si tes modèles ont bougé.

Sur la télémétrie, ce qui est établi : Beaver désactive celle des composants qu'il lance — les processus de prévision partent avec la télémétrie coupée. Le détail de ce qui sort de la machine et de ce qui n'en sort pas est traité sur Confidentialité, qui fait autorité sur ce point.

Fermer la fenêtre, est-ce que ça quitte l'application ?

Ça dépend du système, et la différence est voulue.

Ce que fait la croix de fermeture, système par système
SystèmeCe que fait la croix de fermeture
macOSLa fenêtre est masquée, l'application continue de tourner. Elle se rouvre en cliquant sur l'icône du Dock
Windows et LinuxL'application se ferme

Sur les trois systèmes, une icône dans la barre système est affichée par défaut, et le réglage se trouve dans Réglages › Avancé. Sur Mac, pour quitter réellement, passe par le menu de l'application ou par l'icône de la barre système.

Est-ce que Beaver démarre avec ma machine ?

Non, pas par défaut. Le réglage Lancer au démarrage existe mais est désactivé à l'installation, tout comme Démarrage masqué, qui lance l'application en arrière-plan sans ouvrir la fenêtre. Les deux se trouvent dans Réglages › Avancé, décrits sur Réglages · Agent.

L'application est-elle gratuite ? libre ? puis-je m'en servir au travail ?

Beaver est publié sous la licence GNU Affero General Public License version 3, et le droit d'auteur appartient à Kevin Huynh.

  • Tu peux l'utiliser, l'étudier, le modifier et le redistribuer, y compris en entreprise, sans rien payer.
  • En contrepartie, toute version que tu distribues ou que tu mets à disposition sur un réseau — modifiée ou non — doit être publiée sous la même licence, avec son code source complet.
  • Une licence commerciale existe pour qui veut être dispensé de cette obligation ; elle s'obtient auprès de l'auteur.
  • Contribuer au projet demande de signer un accord de contribution, publié dans le dépôt.
  • Les versions jusqu'à la 1.1.2 incluse avaient été publiées sous licence Apache 2.0 ; elles ne sont plus distribuées.

Les composants tiers gardent leurs propres licences, listées dans le dépôt. L'écran À propos de l'application, lui, n'affiche pas la licence : elle se lit ici ou dans le dépôt.

Note Libre, et gratuit. La contrepartie de l'AGPL v3 ne concerne que ceux qui distribuent une version de Beaver : ils doivent publier leur code source. L'utiliser, même au travail, n'impose rien.

Où est le numéro de version ?

Réglages › À propos. L'écran affiche la version de Beaver, celle de son cadre applicatif, et le système d'exploitation détecté, plus un bouton Voir sur GitHub qui ouvre https://github.com/Kevin-hDev/Beaver. C'est le numéro à donner quand tu signales un problème.

Comment désinstaller proprement ?

Retirer l'application ne suffit pas : trois choses restent.

  • Le dossier de données ~/.local/share/cl-go-dash/ — conversations, réglages, modèles de prévision, coffre chiffré.
  • L'entrée du gestionnaire de secrets de ton système, au nom de service cl-go-dash, identifiant master-key. Tant qu'elle est là, elle ne sert plus à rien ; supprimée, le coffre devient définitivement illisible.
  • Les modèles Ollama, qui vivent dans un dossier partagé avec toute autre installation d'Ollama sur la machine — à ne pas supprimer sans vérifier.

La procédure système par système est sur Dépannage · Installation, qui fait autorité. Cette page ne la duplique pas : elle rappelle seulement les trois restes.
