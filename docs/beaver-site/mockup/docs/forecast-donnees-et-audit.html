What your file has to say

Before every calculation, Beaver re-reads your data and checks it. A blocking flaw stops the forecast, an alert accompanies it. This page says what the file should look like, what is checked, and how to read the result of that check.

The file in four rules One row per observation, a column of dates in year-month-day format, a numeric column to forecast, and the same time distance between two consecutive rows. The rest — series column, covariates, future rows — is optional.

The expected shape of the file

A table, one row per observation, a first row of headers. Six extensions are accepted: csv, tsv, xlsx, xls, ods, xlsm. Any other extension returns “Unsupported format”.

Two conveniences are applied automatically at read time. A column with no header receives a fallback name: column_1, column_2, and so on. A number written with a decimal comma is recognised as a number — 1234,5 becomes 1234.5. A thousands separator, on the other hand — 1 234,5 or 1.234,5 — makes the conversion fail: the value stays text, and will later trigger a “Target column is not numeric” refusal.

Two identical headers make the import fail. Renaming one of the two columns is enough.

The four column roles

At configuration time, each column receives a role. Two are required, two are optional.

The four column roles and their use
Label shownRequiredWhat it's for
TargetYesThis is the column being extended. It must be numeric
Date columnYesSets the order and the time step
Series columnNoLets you forecast several series at once — one product per store, for example
CovariatesNoExplanatory columns that some models can exploit

A column that is requested but absent from the file blocks the calculation, with a message that names the missing role: “Target column not found”, “Date column not found” or “Covariate not found”.

Without a series column, all rows form a single series. With a series column, the limit is 256 series, and the product number of series × horizon must not exceed 100,000 predicted points. A covariate whose values are neither numeric, nor boolean, nor empty triggers an alert, not a block. At most 64 covariates.

Two words, one thing The configuration screen says “Covariates”; the Data section of the Forecast workspace says “External variables”. They are the same columns.

Known future rows

This is the least obvious mechanism of the input file. The rule: a row that carries a date but no value in the target column is understood as a future row, not as missing data. It serves two purposes — setting the output dates, and supplying in advance the covariate values over the period to be forecast: a planned promotion, a forecast temperature, a known public holiday.

Three constraints, all checked:

  • Future rows come after the history. A row with a value appearing after a future row is blocking.
  • When there are future rows, each series must have exactly as many of them as the requested horizon. The configuration screen says so before launching: “Horizon mismatch — known future rows were detected, but the current horizon does not match them.”
  • The first future row must follow the last history row by exactly one time step.

A model that can't exploit the known future refuses the calculation rather than ignore it: “Future variables are not supported by this engine”. The configuration screen warns beforehand: “Future context unavailable — This model reads the main history, but does not use future-known covariate values.” And when no covariate is selected while future rows exist: “Future dates only — Known future rows will mostly be used to set output dates while no covariate is selected.”

Warning An empty target cell does not mean “missing value”. Beaver understands a dated row with no target value as a future row. A gap in the middle of your history will therefore be read as the start of the future, and any data that follows will trigger a refusal. Delete incomplete rows from the history.

A date read without a time is set to midnight. The dates of the predicted points take the form of the last input date: with a T if the input had one, with a time if the input had one, otherwise date only.

Warning The day/month/year format is not recognised. 23/07/2026 is refused, as are months written out in words, the American format 07/23/2026 and unconverted spreadsheet serial numbers. The accepted formats all start with the year. This is the most common cause of refusal and the easiest to fix: reformat the date column in your spreadsheet before importing.

Frequency, and why it matters so much

Frequency isn't decorative: it defines what a time step is, and therefore what a missing period, a misaligned date or a correctly placed future row is. Every sequence check depends on it.

The eight frequencies offered and the time step applied
Label shownTime step applied
Minute1 minute
Hour1 hour
Day1 day
Business dayThe next day, skipping Saturday and Sunday
Week7 days
Month1 calendar month
Quarter3 months
Year12 months
Note “Business day” only skips Saturdays and Sundays. Public holidays are unknown to Beaver and will create missing periods.

What Beaver checks before computing

The audit runs systematically, before any calculation, and its result is called the data profile. The agent can run it on its own with the forecast_data_audit tool.

The profile holds the columns kept for each role, the frequency, the horizon, the confidence level, the number of source rows, the number of history points in total and per series, the number of future rows, the number of series and their identifiers, the first and last date, the number of missing periods, the number of outliers, and the list of anomalies found with their severity and up to ten examples each.

Each anomaly carries one of two severities: Error, and the calculation is refused; Warning, and the calculation happens, the alert being saved with the result. At most 50 distinct anomalies are kept per profile; a repeating anomaly is counted, not duplicated.

The refusal names the first error encountered, not all of them. A file that piles up two flaws will therefore need two passes.

Two important reading points. “Insufficient history” means fewer than two points, not “not enough hindsight”: it's a technical floor, and a very low one. And the last four flaws in the table all fall into the same generic message “Invalid Forecast data”, which doesn't say which one occurred.

The checks that alert without blocking

Six alerts don't prevent the calculation but accompany the result.

The six alerts and how they are measured
What is detectedHow it's measured
Periods absent from the historyEvery gap of more than one step between two consecutive dates counts the missing steps
A history that is short relative to the horizonFewer than twice the horizon in history points
OutliersInterquartile range method, factor 3 — at least 8 values required
A regime changeThe mean of the second half departs from the first by more than 2.5 standard deviations — at least 12 values required
Covariates with no value on the future rowsCounts the empty or absent cells on the future rows
A textual covariateA value that is neither numeric, nor boolean, nor empty

How to read the outlier count. The factor of 3 is deliberately cautious — the common rule uses 1.5, which flags far more points. A non-zero count therefore designates values that are clearly apart, not mere dispersion.

Note Outliers are counted, never corrected. Beaver removes no point from your data: it flags what is clearly apart and leaves you to judge whether it is real or faulty.
Warning The absence of an alert is not a guarantee. Outlier detection needs at least eight points, regime-change detection at least twelve. Below that, no alert can appear, whatever the data.

Reading the data profile on screen

The profile appears in the Data section of the Forecast workspace window. Six counters at the top: Source rows, the number of rows in the file; Historical points, the rows carrying a target value; Future rows, the dated rows with no target value; Series; Missing periods, the absent time steps; Outliers.

Four mapping reminders follow — Target, Date, Frequency, External variables, the last showing “None” when no covariate is kept.

The three states of the summary box
Label shownWhen
Data validatedNo blocking error
Attention requiredAt least one blocking error recorded
Quality check unavailable for this legacy analysisThe analysis predates the data profile

Anomalies are listed under that box, one line each, in the form “Blocking error · 3” or “Warning · 12”. That list gives the count, not the nature of each anomaly: to know what was detected, you have to reread the checks described above against your file.

The data table under these blocks is limited to 200 rows and 32 columns, with the note “The preview is limited to the first 200 rows.” In the panel's main view, quality alerts also appear as a chart layer, filterable under the name “Data quality alerts”, positioned at the history's end date.

The lifetime of a profile

A validated profile is saved and reusable: it avoids resending the data at every forecast. That's what the agent does, receiving a profile identifier and passing it back to the calculation tool.

The retention rules for a data profile
RuleValue
An invalid profile is never saved—
Profiles kept per workspace20, the oldest deleted beyond that
FilingOne folder per project or per conversation
WritingTemporary file then rename

Every profile carries a fingerprint of its data. That is what makes it possible to refuse a model selection established on different data — see Model selection.
