Choosing your model

Running a model at home, paying a service by usage, or using an account you already have: three routes, with different consequences for privacy, cost and capability. This page helps you decide.

The three routes

First point, the one that takes the pressure off everything else: the choice is not permanent. It is made conversation by conversation, and can be changed along the way without losing the history.

Local model through Ollama — installed on your disk, run on the processor or the graphics card. Nothing leaves the machine.

Remote model through an API key — you create a key at the provider, you enter it once in Beaver, requests go to its servers, and billing happens by usage.

Remote model through a web account — for three providers only, you sign in with an existing account instead of a key. Consumption is charged to that account under its own rules.

When to choose local

  • your files contain data that must not be transmitted to anyone;
  • you work without a connection, or with an unreliable one;
  • you refuse usage-based billing;
  • your machine has a comfortable amount of video memory.

The real constraint is the hardware. A model that does not fit in video memory falls back to the processor, and response time gets noticeably longer. The mapping between model size and machine is in Hardware and VRAM.

When to choose a remote model

  • the task requires long reasoning or a large context window;
  • you want fast answers without tying up your machine;
  • your hardware is not enough for a capable enough model;
  • the content being handled can go to a provider without causing a problem.

Combining the two

An arrangement that works, rather than a rule: a local model for everyday tasks, sensitive files and offline work; a remote model for tasks that require reasoning, on non-sensitive content. On the web search side, SearXNG locally when you want to avoid sending queries to a third party, Brave, Exa or Firecrawl when you want better results. → Web search

Switching model mid-conversation

The model selector is in the input bar, below the message area — not at the top of the conversation. Switching model does not lose the history of the current conversation.

Three common misunderstandings

“Local” does not mean “free and equivalent”. A local model small enough to run on an ordinary machine is clearly less capable than a recent remote model.

An Ollama that is already installed does not need to be uninstalled. Quite the opposite: Beaver detects the existing daemon on localhost:11434, reuses it, and the models are shared.

Configuring an API key sends nothing. Nothing leaves until a conversation actually uses that provider.
