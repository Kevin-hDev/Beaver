Will it run on your machine

Beaver is distributed for a single architecture per system: no macOS Intel build, no Linux ARM build, no Windows ARM build. This page says what is supported, what hardware you need, and what the first launch requires.

macOS

Beaver works on Apple Silicon Macs (M1 and later) only. The install script accepts only Darwin:arm64 and Darwin:aarch64; there is no x86_64 asset.

There is no dependency to install: curl and hdiutil ship with the system. The application is not signed, and macOS Gatekeeper may block it if the .dmg is downloaded through a browser — that is the whole point of the install script, which goes through curl and avoids the quarantine flag.

Intel Macs Beaver is distributed only for Apple Silicon Macs (M1 and later). Macs with an Intel processor are not supported, and the install script stops with “Unsupported system”.

Windows

x64 only, no ARM build. Distribution goes through an NSIS installer.

One caveat to know about: the installer does not explicitly handle WebView2 and the Visual C++ runtime. If they are missing on a clean machine, the application may fail to start.

On first launch, if Windows Defender's ransomware protection (“Controlled folder access”) is on, ollama.exe may be blocked when it writes models to ~/.ollama/models/. A Windows notification appears: you need to click “Allow”. The request does not come back afterwards.

Linux

x64 only, in .deb format, for Debian and Ubuntu. The package is built on Ubuntu 22.04, which guarantees compatibility with 22.04, 24.04 and 25.04: since the standard C library is forward-compatible, building on the oldest target covers the later ones.

The install script uses only apt-get: distributions outside the Debian family are not supported. Two dependencies are installed automatically, libwebkit2gtk-4.1-0 — Tauri 2's web rendering engine — and libgtk-3-0, the graphics toolkit.

One display problem is known and unresolved: the window may appear with a transparent background instead of an opaque one. The cause has not been identified; the compositor (Wayland versus X11) or the GTK theme are the leads mentioned.

Beaver 1.2.3 is the last version that brings new features to Linux; after it, the Linux build moves to maintenance only, and everything that works today keeps working — the decision is explained in Linux installation.

Linux and the integrated browser The integrated browser is not available on Linux. Every other feature is. If that matters to you, better to know before installing.

Recommended hardware

With remote models only — API key or web account — any recent machine will do: the application only does display and networking.

With local models, video memory is what decides. A model that does not fit falls back to the processor and becomes very slow. The mapping between model size and machine is in Hardware and VRAM.

Two nuances about AMD GPUs. On Linux, detection works and the ROCm archive is indeed downloaded, but the result has not been validated on a machine actually fitted with one. On Windows, Vulkan works, but Ollama relies on a dated version of llama.cpp, with a significant performance loss: do not count on that combination for maximum performance.

Network

A connection is required if you choose to install Ollama on first launch: the engine weighs several hundred megabytes. The GitHub repository must then be reachable, since checking for updates and downloading Ollama go through the GitHub Releases API. This step can be skipped, and picked up later from Settings › Ollama.

After that, the application works offline with a local model already downloaded. Remote models and web search obviously require a connection.

First launch If you choose to install Ollama, the download comes from GitHub: plan for a connection and a few hundred megabytes. After that, the application works offline with a local model. If you skip the step, Beaver starts without downloading anything.
