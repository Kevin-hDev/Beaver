What is Beaver

Beaver is a desktop application that hosts an autonomous agent: you give it a goal, it decides on the steps, runs tools, checks the result and starts again until it is done. This page says what it does, who it is for, and what sets it apart.

In two sentences

Beaver is a desktop application — not a website, not a command-line tool. It runs an agent that works with cloud models, reached through an API key or an existing web account, or local models, served by Ollama on your machine. The application runs on your computer; the model runs wherever you decide. It works on macOS, Windows and Linux.

What Beaver is not

Three common expectations, and how things actually stand.

Three misconceptions and the reality
What people assumeThe reality
“It's a chat”A chat answers then waits. Beaver runs actions in a loop until the goal is reached.
“It's a command-line tool”Everything goes through a graphical interface: conversations, approvals, files, charts.
“It's a hosted service”The application runs on your computer. Conversations, memory, plans and keys stay in a local folder.

On that last point, the detail matters: what leaves the machine is only the requests sent to remote models and to search services, when you configure them. With a local model and no web search, nothing leaves.

Privacy With a local model and no web search configured, no data leaves your computer. Conversations, memory and files stay in a local folder.

Who it is for

Using the models you already have access to. A connected web account or an API key is enough: the agent works with the provider you choose, without leaving your workspace.

Working on local files. The agent opens them, edits them, runs the commands, checks, and shows you its changes.

Keeping data on the machine. With a local model, no conversation leaves the computer; neither an API key nor an account is required.

Automating recurring work. Scheduled wakeups start a conversation at a fixed time, and the result is waiting for you in the application.

What sets it apart

Cloud and local in the same workspace. Beaver is not dedicated to local AI: connected web accounts, API keys and Ollama models are all picked in the same interface, conversation by conversation.

The local engine is provided, never imposed. The onboarding flow offers to download Ollama, and this step can be skipped: Beaver works perfectly well with remote models alone. If you change your mind, the installation can be started later from Settings › Ollama. Once accepted, the engine is managed by the application: there is nothing to install apart from Beaver. If an Ollama daemon is already running on localhost:11434, Beaver reuses it instead of starting a second one, and the models are shared with the existing installation (~/.ollama/models/).

Control over actions stays with you. Three permission modes exist: Full access, Ask permission and Chatbot. Plan mode goes further — read-only exploration, a plan written in Markdown, no writes before you approve. The details are in Permission modes.

Secrets never pass through the interface. Keys live in an encrypted XChaCha20-Poly1305 vault, whose master key is stored in the operating system keyring. No application command lets the graphical layer read a key back: there is no get_api_key. The Rust core loads the key at the moment of the network call, then erases it from memory.

Everything is in the same window. Conversations, terminal, file tree, previews, web browser, Git history and forecasting workspace.

What the agent actually does

  • read, write and edit files, list folders
  • search by name or by content across a directory tree
  • run shell commands, including in the background
  • search the web and fetch the content of a page
  • create Git branches and switch between them
  • delegate part of the work to isolated subagents
  • keep a todo list and write a plan
  • read and write spreadsheets and office documents
  • resize, crop or convert images
  • run time-series forecasts
  • call the tools of external connectors

Some of these tools are on by default, others are enabled in the settings. The details are in Tools — overview.
