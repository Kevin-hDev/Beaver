Settings, screen by screen

This page answers a single question: where is a given thing set? It gives the complete map of the five sections and the seventeen tabs shipped with Beaver, then a reverse index that starts from what you want to do. The five other pages in this section say what each setting really does.

Note This is a table of contents, not a manual. If you already know where to go, the “I'm looking to set…” table further down answers in one line.

Opening the settings

Settings are one of Beaver's four main tabs, alongside Agent, Heartbeat and Personality. In the sidebar, the tab is named Settings.

Two ways to get there:

  • click the tab in the sidebar;
  • the shortcut Cmd + , on Mac, Ctrl + , elsewhere.

How the screen is organised

The screen reads in two columns: on the left the list of tabs, grouped under five section headers; on the right the content of the selected tab.

Three behaviors worth knowing:

  • Section headers aren't clickable. That isn't an oversight: they are deliberately given no button role and no tab order, so that keyboard navigation doesn't stop on a line that opens nothing.
  • The list is browsed with the arrow keys. The arrows move from one tab to the next across all sections at once, in display order.
  • The open tab is remembered, along with where exactly you were: selected provider, open connector, Ollama model displayed, remote model catalog view. Coming back to settings brings you back where you left off.

The five sections at a glance

The order of sections and tabs isn't a display accident: it is declared once and the whole screen follows from it. The grouping follows a simple principle — settings are grouped by the object being configured: the models, the connections, the agent's behavior, the preferences, the application's life cycle.

Warning Two settings aren't where you'd look for them. File Access — the folders opened to the agent — is in Agent › Advanced, not in Application. And everything about the Ollama engine — memory release, processor or graphics card, several models at once — is also in Agent › Advanced, not in Models › Ollama, which only handles the models themselves.

What an extension can change in this screen

The list of tabs isn't fixed: an installed extension can add its own settings tab in any of the five sections, and it appears in the left-hand list like the others. It can also remove, replace or move an existing tab — with two exceptions locked by the extension contract itself.

The two elements no extension can remove
Protected elementForbidden operations
The main Settings tabRemoval, replacement
The Extensions settings tabRemoval, replacement

The reasoning fits in one sentence: you can't install an extension that would take away your means of uninstalling it. An attempt to modify these two elements is rejected. A numeric limit exists as well: 128 occupants per slot at most.

Note An extra tab can appear in any of the five sections. It comes from the extension, not from Beaver, and disappears with it. What an extension is allowed to do is detailed in Extension center.

Common pitfalls

What surprises people most often in the settings screen
SymptomCauseFix
“I can't find where to limit the agent's folders”The setting is in Agent › Advanced, not in ApplicationSee Agent
“The Ollama tab offers no engine setting”That tab manages the models; the engine is set in Agent › AdvancedSee Agent
“A tab has disappeared from my settings”An installed extension can remove a tab, except Settings and ExtensionsDisable the extension from Integrations › Extensions
“A tab I don't recognise has appeared”It comes from an installed extensionSame screen
“Clicking a section title does nothing”Headers aren't destinations, deliberatelyExpected behavior
“I'm looking for an API Keys tab in the list”It isn't a top-level tab: it's a sub-tab of ProvidersOpen Providers, then API Keys
