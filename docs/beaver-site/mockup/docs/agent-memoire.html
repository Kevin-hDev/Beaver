Persistent memory

The agent can keep notes from one conversation to the next: your preferences, a project's conventions, decisions taken, useful references. Without memory, every conversation starts from scratch and you repeat the same instructions.

Disabled by default Memory is inactive on installation. If you expect the agent to remember something, start by enabling it in Settings › Memory, choosing the Manual or Automatic mode.

The three modes

What the agent does in each mode
ModeBehavior
DisabledNo memory is read or written
ManualThe agent reads memory, but writes only if you ask
AutomaticThe agent reads and writes on its own what it judges useful

In Automatic mode, the agent decides alone what deserves to be kept. That is convenient, but it will sometimes keep things you would not have written down. In Manual mode, nothing is written without your asking: you keep control over what accumulates.

The two scopes

Where a note goes
ScopeWhat it containsLocation
GlobalWhat holds everywhere: your preferences, your way of workingmemory/global/
Per projectWhat holds only for one folder: conventions, commands, constraintsmemory/projects/

The interface distinguishes three views: global memory, that of the active project, and that of other projects — useful for finding what was noted elsewhere.

What a note contains

Notes are filed by topic, in Markdown. Each carries structured attributes. The type says what it is about.

The four note types
TypeUse
preferenceA user preference
feedbackAn instruction about how to work
projectAn element of the current project
referenceA pointer to an external resource

The status takes four values: confirmed (confirmed by you), inferred (deduced by the agent), stale (probably out of date) and archived. The source likewise: user, parent, extractor and subagent-suggestion. Each note accepts eight tags at most.

Confirmed or inferred Every note says whether it comes from you or whether the agent assumed it. That is the distinction that matters in practice: when behavior is unexpected, start by rereading the inferred notes.

What is injected into the conversation

Memory does not enter the context in full: a budget limits what is injected.

Beyond what the budget allows, a summary takes over.

Reading and correcting

Everything can be read and edited from Settings › Memory: the notes, their content, their scope. That is the important point. A memory you cannot reread is a black box; a memory you do reread is a notes file you correct when the agent has misunderstood.

Your notes belong to you Memory is stored in Markdown in your data folder. You can reread it, correct it and delete it, from Beaver or with any editor.

Subagents and memory

Subagents have read-only access: they benefit from what has been kept, but do not write into the shared memory. One of the note sources is in fact called subagent-suggestion — a subagent can propose a note, without imposing it. See Subagents.
