Installing on macOS

Two methods: the install script, which verifies the file's fingerprint, avoids the Gatekeeper warning and opens the Beaver installer, or the .dmg downloaded by hand. The script is the recommended path.

Apple Silicon only Beaver is distributed for Apple Silicon Macs (M1 and later). On an Intel Mac, the script stops with “Unsupported system”.

The recommended method: the script

To paste into the Terminal:

$ (
    installer="$(mktemp /tmp/beaver-bootstrap.XXXXXXXX)" &&
    trap 'rm -f "$installer"' EXIT &&
    curl --proto '=https' --tlsv1.2 --fail --silent --show-error \
      --output "$installer" \
      https://raw.githubusercontent.com/Kevin-hDev/Beaver/main/install.sh &&
    bash "$installer"
  )

The command looks complicated for two precise reasons. It downloads the script into a temporary file instead of piping it straight to bash, and that file is deleted on exit no matter what. And it enforces HTTPS and TLS 1.2 as a minimum.

The script does not install anything by itself. It fetches the Beaver installer, verifies it, and opens it. The installer is the window that asks where to install and does the work. A first installation and a reinstallation both go through it.

What the script does

It runs with your own account and asks for no administrator password: the installer requests that authorization later, and only if the chosen folder needs it.

  • It detects the system and the architecture, and accepts only Darwin:arm64 or Darwin:aarch64. Everything else fails with “Unsupported system”.
  • It queries the GitHub Releases API, with the response capped at 512 KiB.
  • It requires three files in the release: the installer Beaver_X.Y.Z_installer-aarch64.tar.gz, the application Beaver_X.Y.Z_aarch64.dmg, and update-manifest.json.
  • It follows three redirects at most, and only towards release-assets.githubusercontent.com.
  • It downloads the installer archive with a 2 GiB cap, then checks its size and its SHA-256 against the manifest.
  • It inspects the archive before unpacking it: nothing outside Beaver Installer.app, no .. segment, no symbolic link, no file of an unusual kind.
  • It verifies the unpacked installer: identifier com.clgo.dash.installer, Contents/Info.plist present, declared executable present.
  • It opens the installer and hands it the name, the size and the SHA-256 of the .dmg, read from the manifest. The installer will accept no other file.
  • It ends with “The Beaver installer has opened.” and gives the Terminal back to you. The rest happens in the window.

The Beaver installer

One window, one screen at a time. At the top, the version about to be installed; underneath, the Installation folder, set to /Applications, with a Browse button to change it.

Two situations are announced before anything starts. If Beaver is already in that folder, the installer says so — “Beaver is already installed here”, and the version being replaced — the button reads Reinstall, and your conversations, keys and settings are not touched. If Beaver is running, the installer asks you to close it first and keeps the button disabled until you do: an application cannot be replaced while it is running.

Once started, the installation shows five steps, each with its own bar and, once done, the time it took.

The five steps of the installation
StepWhat happens
Checking the systemThe folder is checked again, and Beaver must not be running
Downloading BeaverThe .dmg is downloaded, with the percentage shown
Verifying integritySize and SHA-256 compared to the values handed over by the script
Installing in the chosen folderThe .dmg is mounted read-only, the bundle verified, the copy prepared, then swapped in
FinishingTemporary files are removed

The bundle checks are the same as before, they simply happen inside the installer now: identifier com.clgo.dash, executable cl-go-dash, no symbolic links. The previous version is kept aside until the swap has succeeded.

Show details opens the log of what is happening, for those who want to read it. Cancel stays available until the swap itself; after that the installer says “The installation can no longer be cancelled”, because stopping in the middle of a replacement is the one thing that could leave you without an application.

At the end, “Beaver is ready” and a Launch Beaver button. On failure, “Installation interrupted”, the reason in plain words, and a Retry button; the previous installation remains intact. On cancellation, “Installation cancelled — Nothing was installed: the installation folder is unchanged.”

An interrupted installation leaves nothing behind If the machine is shut down mid-installation, the next run puts the kept copy back in place and removes the leftovers before starting again.

The alternative method: the .dmg file

The .dmg is attached to every GitHub release, under the name Beaver_X.Y.Z_aarch64.dmg. Download, open, drag and drop into Applications: the usual macOS routine.

Its downside is real: a file downloaded through a browser gets the macOS quarantine attribute, and Gatekeeper blocks it. The script goes through curl, which avoids that flag. This method is a fallback, not the main path.

Gatekeeper and the missing signature

The application is not signed with an Apple developer certificate. macOS therefore shows a warning when opening a .dmg downloaded through a browser: application from an unidentified developer.

The standard workaround is a right-click on the application then “Open”, and a confirmation. Otherwise, System Settings › Privacy & Security › “Open Anyway”.

Unsigned application Going through the install script, you will get no warning. Downloading the .dmg from a browser, macOS will show one: right-click on the application, then “Open”.

Choosing another installation folder

The installer proposes /Applications and the Browse button opens the macOS folder picker. The folder is refused if it does not exist, if it is a symbolic link, or if it sits on anything other than a disk attached to this Mac.

One difference worth knowing: /Applications is the only folder for which the installer may ask macOS for an administrator authorization, and only when your account cannot write there. Any other folder must already be writable by you, otherwise it is refused straight away.

Updating

The normal route is the update built into the application: Updating. It is the one to use.

Running the script again is no longer refused, though. It opens the installer on the folder where Beaver already lives, announces the version being replaced, and the button reads Reinstall. This is the way back when the built-in update cannot run — a broken installation, for instance.

Uninstalling

The application is removed by throwing Beaver.app out of the installation folder. Two things do not go with it: the data, which stays in ~/.local/share/cl-go-dash/, and the vault's master key, which stays in the macOS Keychain.
