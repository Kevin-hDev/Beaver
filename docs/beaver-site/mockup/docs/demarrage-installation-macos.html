Installation sur macOS

Deux méthodes : le script d'installation, qui vérifie l'empreinte du fichier et évite l'avertissement de Gatekeeper, ou le .dmg téléchargé à la main. Le script est le chemin recommandé.

Apple Silicon uniquement Beaver est distribué pour les Mac à puce Apple Silicon (M1 et suivantes). Sur un Mac Intel, le script s'arrête avec « Système non pris en charge ».

La méthode recommandée : le script

À coller dans le Terminal :

$ (
    installer="$(mktemp /tmp/beaver-bootstrap.XXXXXXXX)" &&
    trap 'rm -f "$installer"' EXIT &&
    curl --proto '=https' --tlsv1.2 --fail --silent --show-error \
      --output "$installer" \
      https://raw.githubusercontent.com/Kevin-hDev/Beaver/main/install.sh &&
    bash "$installer"
  )

La commande a l'air compliquée pour deux raisons précises. Elle télécharge le script dans un fichier temporaire au lieu de le passer directement à bash, et ce fichier est supprimé à la sortie quoi qu'il arrive. Et elle impose HTTPS et TLS 1.2 au minimum.

Le script est réservé à une première installation. Il refuse de remplacer une installation existante.

Ce que fait le script

Il demande le mot de passe administrateur pour écrire dans /Applications : tu as le droit de savoir ce qu'il exécute.

  • Il détecte le système et l'architecture, et n'accepte que Darwin:arm64 ou Darwin:aarch64. Tout le reste échoue avec « Système non pris en charge ».
  • Il interroge l'API GitHub Releases, avec une réponse plafonnée à 512 Kio.
  • Il exige la présence de l'asset Beaver et du fichier update-manifest.json.
  • Il suit trois redirections au maximum, et uniquement vers release-assets.githubusercontent.com.
  • Il télécharge le .dmg avec un plafond de 2 Gio, puis vérifie sa taille et son SHA-256 contre le manifeste.
  • Il demande le dossier d'installation, /Applications par défaut.
  • Il monte le .dmg en lecture seule, sans l'afficher dans le Finder.
  • Il vérifie le contenu du bundle avant de l'installer : présence de Contents/Info.plist et de Contents/MacOS/cl-go-dash, absence de liens symboliques, identifiant com.clgo.dash, exécutable cl-go-dash.
  • Il copie vers un dossier temporaire à nom aléatoire, revérifie le bundle copié, puis le déplace en place. En cas d'échec à n'importe quelle étape, tout est nettoyé.
  • Il démonte le .dmg et lance l'application.

La méthode alternative : le fichier .dmg

Le .dmg est attaché à chaque release GitHub, sous le nom Beaver_X.Y.Z_aarch64.dmg. Téléchargement, ouverture, glisser-déposer vers Applications : la manipulation macOS habituelle.

Son inconvénient est réel : un fichier téléchargé par un navigateur reçoit l'attribut de quarantaine de macOS, et Gatekeeper le bloque. Le script passe par curl, ce qui évite ce marquage. Cette méthode est un repli, pas le chemin principal.

Gatekeeper et l'absence de signature

L'application n'est pas signée par un certificat de développeur Apple. macOS affiche donc un avertissement à l'ouverture d'un .dmg téléchargé par navigateur : application d'un développeur non identifié.

Le contournement standard est un clic droit sur l'application puis « Ouvrir », et une confirmation. Sinon, Réglages Système › Confidentialité et sécurité › « Ouvrir quand même ».

Application non signée En passant par le script d'installation, tu n'auras pas d'avertissement. En téléchargeant le .dmg depuis un navigateur, macOS en affichera un : fais un clic droit sur l'application, puis « Ouvrir ».

Choisir un autre dossier d'installation

Le script propose /Applications et attend une confirmation par Entrée. Tu peux saisir un autre chemin absolu ; ~ et ~/… sont acceptés et développés. Le chemin est refusé s'il dépasse 1024 caractères, s'il n'est pas absolu, s'il contient des caractères de contrôle ou un segment ...

Mettre à jour

Le script d'installation ne met pas à jour. Il échoue avec « Une application est déjà installée. Utilise sa mise à jour intégrée. » La détection couvre Beaver.app et CL-GO.app — l'ancien nom de l'application — y compris sous forme de lien symbolique.

Les mises à jour passent par la fonction intégrée à l'application : Mise à jour.

Désinstaller

L'application se supprime en jetant Beaver.app du dossier d'installation. Deux choses ne partent pas avec elle : les données, qui restent dans ~/.local/share/cl-go-dash/, et la clé maîtresse du coffre, qui reste dans le trousseau macOS.
