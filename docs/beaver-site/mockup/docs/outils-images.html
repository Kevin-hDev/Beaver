Transforming an image.

transform_image makes up the Images group on its own, optional and off by default. It handles image files: inspecting, resizing, cropping, converting. Attaching an image to a message to talk about it is a separate mechanism — see Attachments.

One tool, three uses

A single tool covers three intents, told apart by what the agent supplies.

The three call shapes
IntentWhat the agent suppliesWrites a file
InspectAn image, an empty operation list, no destinationNo
ConvertAn image and a destination with a different extension, no operationsYes
TransformAn image, a destination, and operationsYes

The combination "empty operation list and a destination" is refused as ambiguous, with a message explaining the two correct shapes. Rather than guessing the intent, the tool asks for it to be clarified.

Approval depends on the intent: inspecting requires nothing, transforming and converting trigger a request in Ask permission mode. That is consistent, since inspection touches nothing.

Inspecting an image

Returns the dimensions, the format and the file size, without writing anything. This is the operation that answers "how big is this image?", or that prepares a resize by knowing the original proportions.

Resizing

Three modes, three different results
ModeBehaviour
Fit (default)The image fits inside the requested dimensions keeping its proportions — the result may be smaller than requested
FillThe image fills the requested dimensions exactly, cropping whatever sticks out
ExactThe image takes exactly the requested dimensions, even if it distorts it

Resampling uses a high-quality filter: the result of a downscale is sharp, not jagged.

Cropping

The agent gives a starting point and a size. A crop that would fall outside the image is refused with an explicit message, rather than being silently clamped to the edges.

Converting

Output formats: JPEG, PNG, WebP, GIF, BMP. The format is determined by the destination file's extension — there is no separate format parameter. For a simple conversion, the agent supplies no operation at all: an input image, a destination with the right extension, and that is it.

Key point The output format comes from the extension. Writing to a .webp file produces WebP, and there is no other way to choose the format.

Quality

The quality setting ranges from 1 to 100 and applies only to JPEG.

  • on JPEG, the quality is applied;
  • on WebP, it is ignored — encoding is lossless — and the result carries a warning saying so;
  • on any other format, it is ignored, with a warning too.

So the agent does not find out after the fact that its setting made no difference: it is warned in the result itself. In the same vein, when Beaver cannot read back the size of the file produced, it says so instead of reporting a size of zero.

The limits

The bounds of the Images group
LimitValue
Source file size50 MB
Maximum dimension, in width as in height8,000 pixels
Total number of pixels after transformation50 million
Operations per call128
Quality1 to 100

The pixel-count limit is checked before the transformation. Without it, a resize asking for 8,000 × 8,000 pixels would allocate several hundred megabytes of memory.
