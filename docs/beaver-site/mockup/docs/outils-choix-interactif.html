When the agent asks.

ask_user_choice lets the agent interrupt its work to ask you a multiple-choice question, and wait for your answer before carrying on. It belongs to the User choices group, optional and on by default. The conversation is genuinely suspended: the agent does not guess, does not carry on in parallel. It waits.

When the agent is meant to use it

Use of the tool is framed fairly strictly, and that is what explains why questions are rare.

The agent must ask when:

  • several approaches are valid and the choice is yours;
  • your request is ambiguous and what follows depends on your preference;
  • in Plan mode, a design question is still open before proposing the plan.

The agent must not ask when:

  • a reasonable default option exists — it takes it, mentions it, and carries on;
  • it is merely looking for agreement on a plan, which is Plan mode's job;
  • the answer can be found by reading the code or the documentation.
Key point An interactive question means the decision really is yours. It is not a request for validation, and it is not an admission of ignorance: the agent is instructed to decide on its own as soon as a reasonable default option exists.

What a question looks like

The format is constrained, which guarantees a consistent presentation:

  • 1 to 5 questions at a time, 2 to 4 options per question;
  • a very short heading per question — 30 characters maximum — and the question itself, 500 characters maximum;
  • for each option, a short label (80 characters) and a sentence explaining what it entails (1,500 characters);
  • exactly one recommended option per question — not zero, not two. This is checked, and a question that has none is refused;
  • an option can carry a preview: a code snippet, a text mock-up, a configuration example, so you can compare visually;
  • a question can allow several answers at once when the options are not mutually exclusive.

The recommendation is flagged by the interface, not by the text: the agent is not allowed to write "(recommended)" in a label. An "Other" option is always available and lets you write a free-form answer, up to 1,500 characters.

Note A single option is recommended, always. The agent is required to have an opinion: it cannot present four options on an equal footing and leave you alone with the choice.

Answering, or not answering

Three outcomes, three different effects
What you doWhat happens
You answerThe answers are passed to the agent, which resumes its work
You close the question without answeringThe agent stops — it does not carry on with the task
You stop the answer in progressThe call is cancelled like any other tool

Answers are validated before being passed on: an incomplete answer, an unknown option, a multiple choice on a question that only accepts one, or a free-form answer without having picked "Other" are all refused.

Careful Closing the question stops the agent. It is not "decide for yourself", it is "do not go there". To let it decide, you have to pick an option — the recommended one will do.

Turning questions off

Switching off the User choices group in the settings has two effects, and the second one is not obvious:

  • the tool disappears — the agent can no longer ask a question;
  • the entire system prompt section describing interactive choices is removed. The model does not even know this mode of interaction exists.

Result: the agent always decides on its own, and mentions its choice in its answer rather than putting it to you. It is the right setting if you prefer an agent that moves forward without stopping — at the price of decisions taken on your behalf.
