Attachments

You can attach files to a message: the agent gets access to them for the conversation. This page describes the limits, the mechanism that protects each attached file, and the case where attaching serves no purpose.

The limits

Reference values
LimitValue
Attachments15
Size of an attachment20 MB
Length of a path4,096 bytes

A file over 20 MB is refused. If it sits in an allowed folder, leave it where it is: the agent will read it with its tools.

How access is authorized

Attaching a file does not make that file freely accessible. Each path receives a signed authorization:

  • it is computed with a key kept in the encrypted vault;
  • it is checked on every access;
  • the path is resolved — links and shortcuts included — before being authorized;
  • an authorization that does not match yields the error attachment_access_denied.
An attachment grants access to a single file Attaching a file authorizes access to that specific file, not to the folder containing it. A fabricated or altered path does not go through.

What happens on restart

Authorizations can be restored on the next launch, so that the attachments of a resumed conversation remain accessible.

Attachment or file read?

Attachments are for the isolated file, outside your working folders: a document you received, a screenshot, a downloaded export.

No need to attach a project file If the file sits in a folder the agent has access to, it can read it directly — with no 20 MB limit and no count limit. See Working folder.
