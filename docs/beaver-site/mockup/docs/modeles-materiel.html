What your machine can carry

Before downloading several gigabytes, only one question matters: does this model fit in your memory? This page gives the conversion table, explains how to read a model name, and says what to do when it does not fit.

The question to ask

A language model has to fit entirely in memory to work properly. On a graphics card, that is the video memory; on a recent Mac, it is the memory shared between the processor and the graphics part.

When a model does not fit, two things can happen: loading fails, or part of the model spills over into ordinary memory — and then generation becomes ten to fifty times slower. The second case is the more confusing one: nothing fails, everything is simply unusable.

Warning A model that overflows does not necessarily crash: it becomes ten to fifty times slower. That is the most common symptom, and the hardest to interpret when you are not expecting it.

The two numbers that matter

A local model's name almost always carries these two pieces of information.

The number of parameters, written in billions: 3B, 7B, 13B, 30B, 70B. That is the model's "size". The bigger it is, the better its answers, and the more memory it demands.

The compression level — written Q4, Q5, Q8, f16. A model is compressed to fit in less memory, at the cost of a slight loss of quality. It is the most effective lever: taking a 13-billion-parameter model from the uncompressed version to the Q4 version brings its consumption down from 28 GB to 8 GB.

How to read the compression

The four compression levels and when to choose them
NotationWhat it meansWhen to choose it
Q4_K_MStrong compressionThe default choice. The best trade-off in almost every case
Q5_K_MMedium compressionWhen memory allows and quality matters
Q8_0Light compressionRarely justified: doubles the memory for a barely perceptible gain
f16No compressionReserved for very well-equipped machines, or for comparative measurements
Note For a given amount of memory, a large heavily compressed model almost always beats a small lightly compressed one: 13 billion parameters in Q4 is better than 7 billion in Q8. That is a consensus in the field, not a measurement made on Beaver — but it holds in almost every case.

What Beaver detects on its own

At startup, Beaver identifies the graphics card and measures the available memory, then derives from it the context size granted to local models.

The context granted according to the memory detected
Memory detectedContext granted
24 GB or more32,768 tokens
12 to 24 GB24,576 tokens
Less than 12 GB, or undetectable8,192 tokens

When the measurement fails, Beaver takes the most cautious value rather than hoping for the best.

Beaver reserves no video memory for the system. The margin is therefore yours to take when choosing your variant — that is the reason for the one-to-two-gigabyte advice beyond the value in the table.

A model's detail screen shows its actual characteristics before installation: file size, number of parameters, context length, compression level, architecture, and whether it is a specialized-experts model. Hardware detection is detailed in Local engine.

The case of Apple silicon Macs

On an Apple silicon Mac, there is no separate video memory: the processor and the graphics part share the same memory. A 16 GB Mac therefore has roughly 16 GB available for a model — minus what the system and the open applications use.

That is a real advantage: a 32 GB Mac runs models that would require a high-end graphics card on a PC. Two caveats, though:

  • you have to leave room for the system — count on 4 to 6 GB taken by macOS and the usual applications;
  • on an Intel Mac, memory is not measured and Beaver falls back to the minimum context of 8,192 tokens.

When it does not fit

In order of preference:

  • Take a stronger compression of the same model — Q8 to Q4 halves the memory.
  • Drop one size — 13 billion to 7 billion.
  • Close the other applications, browsers above all, which are very hungry for video memory.
  • Check that a single model is loaded — multi-model is disabled in the advanced settings.
  • Switch to CPU-only mode — it works, it is very slow, but it unblocks a machine with no usable graphics card.
  • Use a remote model for that task — see Choosing your model.
