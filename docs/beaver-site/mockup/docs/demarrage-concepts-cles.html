Key concepts

The words used everywhere else in this documentation, defined once. Each term links to the page that covers it in detail when one exists.

The agent and its work

Agent — the language model augmented with tools. It receives a request, decides on the actions, runs them, and starts again until it is done. The difference with a chat: a chat answers, an agent acts.

Conversation (or session) — a discussion thread. Each one has its own history, model, working directory, active tools and permissions. You move from one to another through the sidebar; they do not open as tabs.

Clone — a copy of a conversation stopped at a specific message, opened in a tab next to the original. Two modes: drop what followed, or keep a summary of it. Tabs exist only for clones, three at most per group.

Tool — a concrete capability: read a file, run a command, search the web. The agent chooses on its own which one to call and with which arguments.

Tool group — tools are filed by family, and you enable or disable a whole group at once. There are eleven groups: four locked — core, web, mcp, extensions — and seven optional — workflow, automation, subagents, todo, git, forecast, office.

Locked tool — always available, cannot be disabled. The four locked groups carry fourteen tools: core provides eight of them for files, search and commands, web two, mcp one and extensions three.

Optional tool — enabled in the settings. 32 optional tools can be active at the same time, and the catalog currently contains exactly 32: the cap therefore rules nothing out. → Tools — overview

Controlling what the agent does

Permission mode — determines what the agent may do without asking. Three modes are offered to you: Full access, Ask permission and Chatbot. A fourth mode exists internally only, for child sessions; it is never offered.

Permission gate — the mechanism that intercepts an action before execution and asks for approval. It applies only to a specific list of tools, and under conditions for some of them. → Permission modes

Plan mode — the agent explores without modifying anything, writes a Markdown plan and submits it. No write happens before approval. Plans are kept in plans/<session_id>/*.md.

Todo list — the list the agent keeps for itself to break down a long job, visible live. Five tools are attached to it: todo_write, todo_history, todo_pause, todo_resume, todo_delete. → Todo list

Working directory — the folder a conversation is attached to. It determines what the agent can read and write. → Working directory

Project — a saved working directory, found again from one conversation to the next. It is stored in projects.json.

Delegating and remembering

Subagent — a child conversation started by the main agent to handle part of the work in isolation, with its own context. Nine tools are there to control it. → Subagents

Worktree — a separate Git working copy in which a subagent modifies files without touching the current folder. The changes are inspected before being applied or discarded. They live in subagent-worktrees/.

Memory — notes kept from one conversation to the next, in global or per-project scope, in manual or automatic mode. Stored in memory/global/ and memory/projects/. → Persistent memory

Context — the information the model keeps in front of it: your request, the history, tool results, memory, system instructions. It is limited, and monitored by the application. → Context

Compression — the automatic summary of older history when the context fills up, so the conversation can continue without being cut off.

Do not confuse Memory persists between conversations; context is what the model sees inside the current conversation. This is the most common confusion among agent users.

Permanent instructions

System prompt — the instructions given to the model before the first message. There are two sets, Chatbot and Agentic, each in a Compact and a Detailed variant. They can be viewed, edited, replaced and disabled. → System prompts

AGENTS.md — the permanent instruction file you write, read at every conversation: conventions to follow, project commands, things to avoid. → Permanent instructions

Personality — Markdown files describing the expected tone and behavior, injected into the instructions. They are stored in memory/core/.

Skill — a set of instructions filed in a folder, loaded on demand when the task matches. Folder skills/, tool load_skill. → Skills

The models

Local model — installed on your disk, served by Ollama. No data leaves the machine, no cost per request, and performance depends on your hardware.

Remote model — run at a provider, reached over the network. Generally faster and more capable, billed by usage. → Choosing your model

Provider — the service that hosts a remote model. Eleven providers are supported through an API key: Google Gemini, Mistral, Cerebras, OpenRouter, OpenAI, DeepSeek, xAI, Moonshot Kimi, Z.ai GLM, Anthropic Claude and Qwen. → API providers

API key — the secret credential that authenticates you with a provider. Stored encrypted, never exposed to the interface. → The vault and API keys

Web account — an alternative to the API key for three providers: OpenAI/Codex, Grok (xAI) and Kimi (Moonshot, experimental). → Account sign-in

Ollama — the software that runs local models. Beaver downloads it when you ask it to, then drives it for you. It is optional: without it, only remote models are available. → Local engine

Reasoning (thinking) — the phase in which some models think before answering. Beaver displays it, and lets you adjust its intensity when the model supports that. → Reasoning

The integrations

MCP (Model Context Protocol) — a standard that lets external programs expose tools to the model, and therefore add capabilities without modifying Beaver.

Connector — an MCP server instance configured in Beaver, local or remote. The configuration lives in mcp-connectors.json. → MCP connectors

Extension — an installable module that modifies the interface itself, distributed and updated from a Git source. An extension can contribute its own settings tab, navigation entries, a theme and skills, and three locked tools in the extensions group make it visible to the agent. That is what sets it apart from an MCP connector, which only adds tools. → Extension center

Channel — a gateway to Telegram, Slack or Discord.

Gateway — the background service that runs the channels, links each external conversation to a session, and logs the exchanges. The audit trail is written to logs/gateway-audit.jsonl. → External channels

Do not confuse A subagent is a child session, a connector exposes tools through MCP, an extension modifies the application. All three add capabilities, through unrelated mechanisms.

Automation, data, security

Wakeup — a scheduled instruction, of three kinds: once, daily, weekly. The result lands in a dedicated conversation.

Scheduler — the internal mechanism that fires the wakeups. It is internal to the application and does not use the system's scheduled tasks.

Forecast — the time-series forecasting workspace: audit, model selection, forecast, evaluation, comparison, export. → Forecast

Backtest — an evaluation that replays the past to measure the quality of a model on data whose continuation is known.

Vault — the encrypted file holding the API keys and tokens. XChaCha20-Poly1305 encryption, file secrets.enc.

Keyring — the operating system's secret store: macOS Keychain, Windows DPAPI, Linux Secret Service. It holds the vault's master key, and nothing else.

Zeroization — the deliberate erasure of a secret in memory after use, so it does not survive in a swap file or a memory image. → Security model
