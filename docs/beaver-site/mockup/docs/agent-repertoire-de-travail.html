Working folder and disk access

Two distinct notions, often confused: the working folder is the folder a conversation is about; the access scope is the list of folders the agent can reach, across all conversations.

A conversation's working folder

Each conversation is attached to a folder. That folder determines:

  • what the file tree shows;
  • where the terminal starts;
  • the Git repository the branch actions apply to;
  • the context the agent considers to be “the project”.

It is specific to each conversation: two open conversations can work on two different folders.

Projects

A project is a saved working folder, found again from one conversation to the next without having to reselect it. Projects are stored in projects.json.

A point to know: some operations — notably the Git actions tied to clones — require the folder to be a saved project. An arbitrary path is refused.

The disk access scope

A list of allowed folders is set in Settings › File Access. It bounds what the agent can reach, independently of the working folder. When access is refused, the app shows the “Folder not allowed” screen, which lists the permitted folders and points to the setting.

Two different things The working folder is the folder a conversation is about. The access scope is the list of folders the agent can reach, across all conversations.

How a path is validated

Before any read or write, a path is normalized — links and shortcuts are resolved down to the real path — then compared against the allowed roots, inside which it must sit.

It is this prior resolution that prevents leaving the allowed area through a roundabout path: a symbolic link pointing outside the roots is unmasked before access, not after.

The default setting

By default, the agent has access to the entire disk.

This is a deliberate choice, not an oversight: the agent is designed to work on any folder on the machine without prior configuration, and protection rests on the other mechanisms — the permission guard, the sensitive paths always subject to confirmation, and Plan mode.

Access is full by default Beaver can reach all your files. That is what lets it work on any project without prior setup. If you would rather restrict it to a few folders, the list is edited in Settings › File Access — and that restriction applies to all your conversations.

The setting applies as soon as a custom list is saved. An empty list falls back to the default: you cannot end up with no allowed root by accident.
