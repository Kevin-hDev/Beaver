Installing a model on your machine

A local model costs nothing and never leaves your computer. You still have to pick the right one: this page covers searching, variants, what a model's data sheet says before you download it, and what happens when you delete one.

Where to find models

Beaver queries Ollama's public catalog and lets you search it for a model by name, from inside the application — with no browser and no command line. It is Ollama's catalog: the same models, the same names.

Choosing a variant

A model does not exist in a single copy. It comes in variants, which combine a size and a level of quantization. Each variant has its own weight on disk and its own memory demand.

That is where the choice is made, and the conversion table is in Hardware and VRAM.

Note A variant is a size plus a quantization level. The same model exists in several versions whose memory demand ranges from one to ten times as much.

Warning Check the Capabilities line before downloading several gigabytes. A model that cannot use tools holds a conversation, but will read no file and run no command in Beaver.

Installing

Installing downloads the chosen variant. It takes a while — several gigabytes — and progress is displayed.

  • One installation at a time. A lock prevents two simultaneous downloads, which would fight over bandwidth and disk.
  • The installation can be cancelled. Cancellation is clean: if the engine was not yet installed and the first download is interrupted, the partial folder is deleted rather than left behind.
  • The engine restarts and waits until it is ready before the installation is declared successful.

Updating

Beaver can detect installed models for which a newer version exists. It groups the installed models by family, queries the catalog for each family, and compares. Up to 100 families are examined.

An updated model keeps its name: it is the version behind it that changes.

Deleting

Deleting a model frees the corresponding disk space. It is reversible at the price of another download — but read the next section first, because deletion does not stop at Beaver.

Models shared with Ollama

Model storage is shared, in both situations.

  • If the official Ollama application is running, Beaver reuses its engine — and therefore its models.
  • If Beaver starts its own engine, it points it at Ollama's usual models folder (~/.ollama/models, or the location given by the OLLAMA_MODELS environment variable if it is set on your machine).

In both cases, everything downloaded on one side is available on the other, with no copy and no second download. The full mechanism is described in Local engine.

Warning Deleting a model from Beaver also deletes it for the Ollama application: it is the same storage, not a copy.
