PDF and Word documents.

Two tools make up the Document / Word group, optional and off by default. Beaver reads both PDF and Word, but only writes Word: it does not produce PDFs.

A group to turn on

The Document / Word group
ToolRoleApproval
read_documentExtracts the text from a PDF or a .docxNo
write_documentCreates a Word documentYes
Careful As long as the group is off, the agent does not know it can read a PDF. It will try to open it as text and fail, without saying why. Turn it on in Settings › Agent › Tools.

Reading a PDF or a Word document

Accepted formats: .pdf and .docx — and nothing else. Not the old .doc format, not .odt, not .rtf, not .pages. The agent receives the extracted text, its original format and the character count.

What reading loses

Only the text is extracted. Lost, in both formats:

  • formatting — bold, italic, colours, sizes;
  • images and diagrams;
  • page layout — columns, headers, footers, numbering;
  • the content of tables as tables — their text may come out, but its row-and-column structure is lost.

For a Word document, extraction proceeds paragraph by paragraph, with particular care given to spaces: the Word format splits a paragraph into styled fragments, and a naive extraction glues the words together. Beaver preserves meaningful spaces and normalises the ones that come from the file's formatting.

For a PDF, extraction depends entirely on the file. A PDF that is nothing but a scanned image will yield no text: there is no optical character recognition in Beaver. The extracted text is capped at 1 million characters.

Key point A scanned PDF yields nothing. Without a text layer, a digitised document is unreadable for the agent — it has to go through character recognition first.

Creating a Word document

A single output format: .docx. The agent does not supply a file but a sequence of content blocks, in the order they should appear. This is close to the way one writes, and it produces a clean document rather than an assembly of raw text.

The four available blocks
BlockWhat it producesOptions
HeadingA heading from level 1 to 6Alignment
ParagraphA paragraph of textBold, italic, alignment, or styled segments
TableA table with headers and rows—
ListA bulleted or numbered listOrdered or not

The styled segments mechanism is worth a mention: rather than a paragraph entirely in bold, the agent can compose a paragraph out of several pieces, each with its own style — bold, italic, underlined, coloured. That is what makes it possible to write a sentence in which only two words are highlighted. Alignment accepts four values: left, centred, right, justified; colours are expressed in hexadecimal.

What does not exist: images, headers and footers, footnotes, automatic table of contents, page breaks, named styles, templates. The tool produces a structured, readable document, not an elaborate layout. A document is limited to 5,000 blocks.

The limits and the protections

A .docx file is a compressed archive, and an archive can be crafted to saturate memory once opened. The same protections as for spreadsheets apply.

The bounds of the Document / Word group
LimitValue
Source file size50 MB
Internal content of an uncompressed .docx10 MB
Extracted text1 million characters
Blocks per document created5,000
Entries in the archive4,096
Accepted compression ratio100 to 1
Total uncompressed size200 MB

A document with malformed content is refused with a clear message rather than producing a partial text presented as complete.
