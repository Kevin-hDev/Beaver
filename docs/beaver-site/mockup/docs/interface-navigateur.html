A browser held back, deliberately

A full web browser, in the conversation's side panel, built on an embedded Chromium engine. Several of its capabilities are refused outright — these are not gaps, they are choices, and this page says which ones.

Warning The integrated browser is available on macOS and Windows. It does not exist on Linux: it is the only major feature missing from a system.

What it is for

Three uses:

  • reading a page without leaving the application;
  • staying signed in to a service from one conversation to the next;
  • seeing what a local development server the agent has just started renders.

It shares the side panel with file preview and Forecast: opening it replaces whatever was there. See Side panel.

The tabs

  • Ten tabs at most per conversation.
  • Titles are truncated at 80 characters.
  • Tabs are attached to the conversation: each one has its own.

Signed-in sessions

  • Restored sessions are encrypted on disk.
  • The browser uses a separate profile, distinct from your usual browser.
  • Size of a session file: 128 KB at most.
Security A separate profile: the integrated browser has its own, independent of your usual browser. Your personal cookies and sessions are not accessible to it.

Development server detection

Beaver examines local ports to spot a development server that is running and offer it to you directly. The results are sorted by port number.

What is blocked

This is not an ordinary browser. A browser driven by an agent with access to the microphone and the camera would raise an obvious problem: those capabilities are refused.

  • Only http and https are accepted. Any other URL scheme is rejected.
  • A URL's length is capped at 2,048 characters.
  • Requests for device access — camera, microphone — are intercepted by a dedicated handler.
  • Downloads and cookies go through specific checks.
  • When a capability is refused, you are told about it.
