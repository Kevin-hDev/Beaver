Ce que l'agent sait, dit et a le droit de faire

Quatre onglets décident du comportement de l'agent : ce qu'il retient, les instructions qui le définissent, les outils dont il dispose, et l'accès qu'il a à ta machine. Cette page décrit les écrans : où est le champ, ce qu'il vaut, ce qu'il déclenche.

L'onglet Avancé est le plus chargé de toute l'application : il porte plusieurs blocs sans rapport direct entre eux. C'est là que vivent les deux réglages qu'on cherche le plus souvent ailleurs — l'accès aux dossiers et le comportement du moteur Ollama.

Onglet Mémoire

L'onglet s'ouvre sur une phrase de cadrage : « Gère ce que l'agent peut retenir durablement, sans charger tous les détails dans chaque conversation. »

Mode mémoire — « Le mode manuel exige une demande explicite. Le mode automatique retient seulement les faits durables. » Trois valeurs :

Les trois modes de mémoire
Libellé affichéComportement
DésactivéValeur par défaut. Rien n'est retenu ; les fichiers déjà écrits sont conservés
ManuelL'agent ne retient que sur demande explicite
AutomatiqueL'agent retient de lui-même ce qu'il juge durable

Budget de contexte — « Limite maximale réservée au résumé et aux lectures mémoire. » Six valeurs : 512, 1 000, 1 500, 2 000, 2 500 et 3 000 jetons. La valeur par défaut est 3 000, qui est aussi le maximum accepté par le moteur. Le sélecteur est grisé quand le mode est Désactivé. Ce budget est un plafond, pas une réservation : c'est la place maximale que la mémoire peut prendre dans la fenêtre de contexte d'une conversation.

Sous les réglages, une section « Mémoires enregistrées » liste ce que l'agent a retenu, avec un champ de recherche et deux filtres.

Les deux filtres de la liste des mémoires
FiltreValeurs
TypeTous les types, Préférence, Retour, Projet, Référence
StatutTous les statuts, Confirmé, Déduit, À vérifier

Les mémoires sont groupées par portée : Mémoire globale, puis Projet actif suivi du nom du projet s'il y en a un, puis les autres projets. Les mémoires des autres projets ne sont pas chargées d'emblée : un bouton « Afficher les mémoires » les demande à la demande. Sélectionner une mémoire ouvre son contenu, avec deux actions — Fermer et Archiver, l'archivage demandant une confirmation.

Deux bandeaux peuvent apparaître en haut de la liste. Quand le mode est éteint : « La mémoire est désactivée. Les fichiers existants sont conservés. » Et quand des fichiers d'une organisation antérieure sont trouvés, un bandeau « Ancien contenu détecté » précise : « Les anciens dossiers sont conservés mais ne sont pas injectés. »

L'onglet a ses quatre états écrits : « Chargement de la mémoire… », « Impossible de charger la mémoire » avec un bouton Réessayer, « Aucune mémoire pour cette portée », et la liste elle-même.

Note Éteindre la mémoire n'efface rien. Le mode Désactivé cesse d'injecter et d'écrire, mais les mémoires déjà enregistrées restent sur le disque. Les rallumer les rend à nouveau disponibles. Ce que la mémoire retient et comment est détaillé dans Mémoire persistante.

Onglet System prompt

L'onglet s'appelle « System prompt » dans la liste de gauche, et son titre à l'ouverture est « Instructions système » : les deux mots désignent la même chose.

Cet écran règle les instructions globales, celles qui s'appliquent à tous les modèles. Les modèles Ollama peuvent avoir leurs propres instructions, réglées ailleurs — voir Modèles.

Deux sélecteurs commandent ce qui est affiché :

Les deux sélecteurs qui choisissent le texte affiché
SélecteurValeurs
Mode du modèleChatbot, Agentique
Format des instructionsCompact, Détaillé

À l'ouverture, l'écran présente le mode Agentique au format Détaillé. Il y a donc quatre textes distincts à consulter et à personnaliser, un par combinaison. Trois provenances sont possibles pour le texte affiché — Beaver, Ollama, Custom — et les actions proposées sont Modifier, Utiliser Beaver, Utiliser Ollama, puis Enregistrer ou Annuler.

Deux garde-fous protègent d'une perte de travail :

  • Un avertissement avant la première modification, titré « Attention » : « Cette modification remplace les instructions système de Beaver pour toutes les IA, sauf les modèles Ollama qui possèdent leurs propres instructions personnalisées. » Une case « Ne plus afficher cet avertissement » permet de le taire.
  • Un avertissement de perte — « Le prompt personnalisé va être supprimé » — avec un bouton « Copier le prompt » pour le sauvegarder avant de continuer. Il s'affiche quand tu reviens aux instructions de Beaver ou d'Ollama après avoir écrit les tiennes.

Laisser le champ vide est un choix explicite, et le texte du champ le dit : « Laisser vide pour ne transmettre aucune instruction système. » Ce que contiennent ces instructions est détaillé dans Prompts système.

Onglet Outils

L'onglet s'ouvre sur une phrase qui pose tout le principe : « Ces outils définissent ce que l'agent peut faire pour toi. Les outils essentiels sont toujours actifs. Les outils optionnels s'activent ou se désactivent selon tes besoins : l'agent n'utilisera que ce qui est activé. »

Deux sections, « Tools essentiels » et « Tools optionnels ». Les outils ne se règlent pas un par un : ils sont groupés, et l'interrupteur agit sur tout le groupe.

Les cinq groupes toujours actifs. Ils portent la mention « Toujours actif » à la place d'un interrupteur, et le moteur refuse toute tentative de les éteindre, y compris par un appel direct — le message est alors « Ce groupe d'outils est verrouillé. »

Les cinq groupes d'outils verrouillés
GroupeCe qu'il permet
TerminalLancer des commandes directement sur ta machine. L'outil le plus puissant : tout ce que ton terminal peut faire, l'agent peut le faire
FichiersLire, créer et modifier les fichiers de ton projet : code, configurations, notes, documents
Recherche de fichiersFouiller ton projet pour retrouver un fichier ou chercher un mot précis dans le code
WebChercher des informations en ligne et ouvrir des pages web
Connecteurs externesUtiliser les connecteurs externes configurés dans l'onglet Connecteurs

Les groupes activables, avec leur état à l'installation :

Les groupes d'outils optionnels et leur état à l'installation
GroupeActif à l'installationCe qu'il permet
SkillsOuiSuivre des guides spécialisés pour certaines tâches
AutomatisationsOuiCréer et gérer des tâches planifiées
Choix utilisateurOuiTe demander ton avis quand l'agent hésite entre plusieurs options
Sous-agentsOuiDéléguer une sous-tâche à un agent secondaire
Todo listNonTenir une liste de tâches pendant un long travail
Branches GitNonCréer ou changer de branche Git

Un groupe est considéré comme activé seulement si tous ses outils le sont. Le cas d'un groupe à moitié activé ne se produit pas par l'interface ; il pourrait apparaître avec un fichier de réglages édité à la main, et l'interrupteur se présenterait alors éteint.

Attention Six groupes d'outils sont éteints à l'installation. Tableurs, documents Word, images, branches Git, listes de tâches et Forecast ne sont pas disponibles tant qu'ils ne sont pas activés ici. Un agent qui « refuse » d'ouvrir un fichier Excel n'a le plus souvent pas l'outil — ce n'est pas un problème de capacité du modèle.

Chaque outil est décrit dans Vue d'ensemble des outils. Les groupes d'outils ne sont pas les modes de permission, qui sont un mécanisme distinct : voir Modes de permission.

Avancé — importation depuis d'autres assistants

Le premier bloc de l'onglet, « Importation depuis d'autres assistants » : « Gère les règles, instructions et skills lus depuis tes autres outils. » Un bouton « Gérer » ouvre l'écran dédié.

C'est le chemin pour y revenir après le premier lancement — ce que l'application annonce d'ailleurs pendant l'accueil : « Tu pourras modifier ces choix plus tard dans Réglages > Avancé. » Le sujet est traité dans Importer d'un autre agent.

Avancé — comportement général

Une carte avec deux réglages.

Icône dans la barre — « Garder Beaver dans la barre système ». Activé par défaut.

Modèle par défaut — « Modèle utilisé par défaut pour les nouvelles conversations ». Une liste déroulante avec recherche, groupée par fournisseur, alimentée par les modèles réellement disponibles. Vide par défaut.

Avancé — la compression du contexte

Entre le comportement général et le moteur Ollama, une carte titrée « Compression » règle la façon dont Beaver résume les conversations trop longues : le profil global, son seuil de déclenchement et l'éditeur avancé des profils. Tout son fonctionnement — ce qui déclenche une compression, ce qui est gardé, ce qui est supprimé, et chaque réglage de cette carte — est décrit sur la page Compression du contexte.

Avancé — le moteur Ollama

Un bloc titré « Ollama », distinct de l'onglet Ollama de la section Modèles. La séparation est celle-ci : l'onglet Ollama gère les modèles ; ce bloc-ci gère le moteur qui les fait tourner.

Décharger le modèle — « Durée avant de libérer la mémoire du modèle ». Sept valeurs : Immédiatement, Après 2 min, Après 5 min, Après 10 min, Après 15 min, Après 30 min, À la fermeture. Par défaut : Après 5 min.

Accélération matérielle — « Moteur d'inférence pour les modèles locaux ». Deux valeurs, CPU et GPU, avec GPU par défaut. Ce réglage n'apparaît pas sur Mac, où la question ne se pose pas.

Charger plusieurs modèles — « Garder plusieurs modèles en VRAM simultanément (nécessite plus de mémoire GPU) ». Désactivé par défaut.

Afficher l'état GPU — « Afficher l'utilisation RAM/VRAM et l'exécution sur CPU dans le chat ». Désactivé par défaut.

Un redémarrage est nécessaire pour trois de ces réglages sur quatre. Changer le déchargement, l'accélération matérielle ou le multi-modèle fait apparaître une ligne supplémentaire — « Redémarrage nécessaire », « Les changements seront appliqués après le redémarrage d'Ollama » — avec un bouton « Restart Ollama ». Seul « Afficher l'état GPU » s'applique immédiatement.

Le redémarrage donne trois résultats possibles : « Ollama redémarré » en cas de succès, « Ollama externe réutilisé » quand Beaver a trouvé un moteur déjà lancé qu'il ne possède pas, ou un message d'erreur.

Sous ces réglages, une table de référence — « VRAM requise par modèle », « Estimation de la VRAM nécessaire selon la taille et la quantification ». Sa lecture est expliquée dans Matériel et VRAM, et le cycle de vie du moteur dans Moteur local.

Avancé — Accès fichiers

C'est le réglage le plus important de la page. Titre affiché : « Accès fichiers ». Description : « Dossiers de travail des sessions. Les composants nécessaires aux outils et l'accès réseau restent disponibles ».

L'écran présente une liste de dossiers, chacun avec une croix pour le retirer, et deux boutons : « + Ajouter un dossier » et « Réinitialiser ».

La valeur par défaut est la racine du disque — / sur macOS et Linux, C:\ sur Windows. L'interface ne l'affiche pas comme un chemin mais sous le libellé « Tout le disque ». C'est un choix assumé : l'agent démarre avec l'accès complet au disque, et c'est à toi de le restreindre si tu le souhaites. Le raisonnement est développé dans Modèle de sécurité.

Trois comportements à connaître :

  • La liste ne peut jamais être vide. La croix de suppression est désactivée dès qu'il ne reste qu'un dossier, et le moteur remet le défaut si une liste vide lui parvient malgré tout.
  • Le bouton « Réinitialiser » rend l'accès complet au disque. Il ne réduit pas les droits : il les remet à leur valeur d'origine, c'est-à-dire la plus large.
  • Restreindre l'accès interrompt le travail en cours. Quand la nouvelle liste est plus étroite que l'ancienne, le moteur annule toutes les requêtes de l'agent en cours et arrête tous les processus de terminal lancés. C'est délibéré : sans cela, une commande déjà partie continuerait de travailler dans un dossier qui vient d'être retiré. Élargir l'accès, au contraire, n'interrompt rien.
Attention « Réinitialiser » élargit l'accès, il ne le restreint pas : ce bouton remet la valeur d'origine, c'est-à-dire tout le disque. Pour restreindre, retire les dossiers un à un et n'ajoute que ceux dont l'agent a besoin.

Ce réglage a un propriétaire unique. Il ne passe pas par le même chemin que les autres réglages avancés : les deux commandes générales d'enregistrement refusent explicitement de toucher à la liste des dossiers, et seule la commande dédiée peut la changer. Conséquence concrète : aucun autre écran, aucun enregistrement automatique, aucune extension passant par les réglages généraux ne peut élargir tes droits d'accès par effet de bord.

Un lien depuis un message d'erreur peut ouvrir directement ce bloc : la zone est alors mise en évidence pendant 1,8 seconde et l'écran défile jusqu'à elle. Le dossier dans lequel une conversation travaille est décrit dans Répertoire de travail.

Avancé — les fichiers des sessions

Dernier bloc, titré « Fichiers des sessions », avec deux lignes.

Emplacement des livrables — « Beaver y crée un dossier séparé pour les livrables de chaque session ». Deux boutons : « Choisir » ouvre un sélecteur de dossier, « Par défaut » — visible seulement si un dossier a été choisi — revient à la valeur d'origine, affichée « Dossier Beaver par défaut ».

Le chemin est validé avant d'être accepté : il doit être absolu, faire moins de 4 096 caractères, ne contenir aucun caractère de contrôle et aucun ... Un chemin refusé produit le message « Dossier de sortie invalide. »

Données Beaver — « Ouvrir le dossier qui contient les sessions, la mémoire et les réglages locaux », avec un bouton « Ouvrir le dossier » qui ouvre l'explorateur de fichiers du système. C'est le chemin le plus court pour atteindre ~/.local/share/cl-go-dash/ sans le taper.
