Les skills

Un skill est un mode d'emploi rangé dans un dossier, que l'agent charge à la demande quand la tâche y correspond. C'est la façon d'apprendre à l'agent une procédure détaillée sans qu'elle occupe le contexte de toutes tes conversations.

Skill ou AGENTS.md ?

La différence qui décide où écrire quoi
AGENTS.mdSkill
ChargementÀ chaque conversation, toujoursÀ la demande, quand c'est pertinent
Coût en contextePermanentSeulement quand il est chargé
ContenuConventions courtes, interditsProcédures détaillées

Ce qui doit toujours être vrai va dans AGENTS.md ; ce qui ne sert que parfois va dans un skill. Une procédure de déploiement de trois pages n'a pas à occuper le contexte de toutes tes conversations.

Où les ranger

Un dossier par skill, dans le dossier skills/ du répertoire de données. Le dossier peut contenir d'autres fichiers que le manifeste — scripts, gabarits, références — auxquels le skill renvoie.

Le format d'un skill

Le dossier doit contenir un fichier nommé SKILL.md ou skill.md : les deux graphies sont acceptées. Il commence par un en-tête encadré de --- contenant deux champs.

$ cat skills/deploiement/SKILL.md
---
name: Déploiement
description: Publier une version en production. À employer avant chaque mise en ligne.
---

Le contenu du skill, en Markdown libre.

name est le nom affiché ; à défaut, le nom du dossier est employé. description fait 250 caractères au maximum : c'est ce que l'agent lit pour décider s'il doit charger le skill. Les valeurs entre guillemets simples ou doubles sont acceptées.

Sans en-tête, le fichier reste utilisable — le nom du dossier sert de nom. Mais l'absence de description prive l'agent de son seul critère de sélection.

Comment l'agent s'en sert

En deux temps. D'abord le catalogue : l'agent voit en permanence la liste des skills disponibles, avec leur nom et leur description, ce qui coûte peu de contexte. Ensuite le chargement : quand une tâche correspond à une description, l'agent charge le contenu complet avec l'outil load_skill, qui appartient au groupe Skills, actif par défaut.

La description décide de tout L'agent choisit de charger un skill à partir de sa description seule, limitée à 250 caractères. Précise ce que fait le skill et quand l'employer : une description vague donne un skill qui ne se déclenche jamais.

Appeler un skill toi-même

Chaque skill reçoit une commande construite depuis sa source et son nom. Dans la zone de saisie, taper / ouvre la liste d'autocomplétion des skills disponibles ; en choisir un insère sa commande dans ton message.

  • Un skill local s'invoque par /nom-du-skill.
  • Un skill importé s'invoque par /source:nom.
  • Quand deux skills aboutiraient à la même commande, un suffixe tiré de leur identifiant les distingue.

Les skills importés, et ceux qu'on ne voit pas

Les skills repris d'un autre assistant apparaissent dans le même catalogue, avec l'indication de leur source d'origine. Le tri se fait par nom, sans distinction de casse.

Une troisième source existe, invisible dans le catalogue : les skills fournis par une extension. Leur identifiant est préfixé par extension: et ils sont délibérément retirés du catalogue global — ils ne comptent donc pas dans les 2 048 skills locaux et n'apparaissent pas dans la liste permanente. Autrement dit, le catalogue affiché n'est pas la totalité des skills que l'agent peut charger.

Les sous-agents n'y ont presque pas accès

Seul un sous-agent de type codeur reçoit load_skill, et seulement si le groupe Skills est activé. Un sous-agent explorateur n'a jamais accès aux skills. Voir Sous-agents.

Un identifiant ne peut contenir ni .., ni /, ni \ : c'est une protection contre la lecture d'un fichier hors du dossier des skills. Trois erreurs sont possibles au chargement : identifiant invalide, skill introuvable, skill indisponible.

Écrire un bon skill

  • Soigner la description avant le contenu. C'est elle qui déclenche le chargement : écris à quoi sert le skill et quand l'employer, avec les mots que tu emploierais naturellement.
  • Écrire à l'impératif. « Tu vérifies X » plutôt que « il faudrait vérifier X » : une consigne à l'infinitif se lit comme une suggestion et se saute.
  • Donner la raison d'une règle quand elle n'est pas évidente. Une règle sans son pourquoi ne couvre que les cas prévus.
  • Un skill, une procédure. Deux procédures dans un même skill, et l'agent charge les deux pour n'en employer qu'une.
