Installation sur Windows

Beaver est distribué en installeur NSIS pour Windows x64. Le script PowerShell vérifie chaque redirection, la taille et l'empreinte du fichier avant de lancer l'installation. Windows va réagir : cette page dit pourquoi et quoi faire.

La méthode recommandée : le script

À coller dans PowerShell, pas dans l'invite de commandes classique :

> $installer = Join-Path ([IO.Path]::GetTempPath()) "beaver-install-$([Guid]::NewGuid().ToString('N')).ps1"
  try {
    Invoke-WebRequest https://raw.githubusercontent.com/Kevin-hDev/Beaver/main/install.ps1 -OutFile $installer -ErrorAction Stop
    & $installer
  } finally {
    Remove-Item -LiteralPath $installer -Force -ErrorAction SilentlyContinue
  }

Ce que fait le script

  • Il vérifie que l'architecture du processeur est AMD64. Toute autre valeur arrête l'installation.
  • Il force TLS 1.2 et désactive le suivi automatique des redirections : chaque redirection est examinée avant d'être suivie.
  • Il interroge l'API GitHub Releases, avec une réponse plafonnée à 512 Kio.
  • Il exige l'asset nommé exactement Beaver_<version>_x64-setup.exe.
  • Il télécharge update-manifest.json, plafonné à 64 Kio, et vérifie que sa taille correspond à celle annoncée.
  • Il vérifie que le manifeste porte bien la version attendue, et que chaque entrée d'asset a un nom conforme, une empreinte SHA-256 de 64 caractères hexadécimaux et une taille.
  • Il télécharge l'installeur, avec un délai maximum de 1800 secondes, et vérifie que la taille reçue correspond exactement à celle attendue.
  • Il calcule le SHA-256 du fichier et le compare à celui du manifeste. En cas d'écart, l'installation s'arrête.
  • Il propose le dossier d'installation, %LOCALAPPDATA%\Beaver par défaut.
  • Il lance l'installeur NSIS en mode silencieux, fenêtre masquée.
  • Il vérifie que cl-go-dash.exe existe dans le dossier d'installation et qu'il ne s'agit pas d'un point d'analyse — une protection contre la substitution par lien.

La méthode alternative : l'installeur

L'installeur Beaver_X.Y.Z_x64-setup.exe est attaché à chaque release GitHub : double-clic et parcours classique. Son inconvénient : SmartScreen s'interpose sur un exécutable non signé téléchargé par navigateur, et la vérification d'empreinte est à faire soi-même.

SmartScreen et l'absence de signature

L'application n'est pas signée par un certificat de signature de code. Windows SmartScreen affiche donc un écran bleu « Windows a protégé votre ordinateur » à l'exécution de l'installeur. Le contournement consiste à cliquer sur « Informations complémentaires », puis « Exécuter quand même ».

Ce comportement est normal pour un logiciel libre non signé : un certificat de signature de code est payant et nominatif.

Windows Defender et l'accès contrôlé aux dossiers

Si la protection anti-rançongiciel (« Accès contrôlé aux dossiers ») est active, ollama.exe peut être bloqué au premier lancement, quand il tente d'écrire les modèles dans ~/.ollama/models/. Une notification Windows apparaît et il faut cliquer « Autoriser ». La demande ne se répète pas ensuite.

Sans cette explication, le symptôme observé est « le téléchargement du modèle échoue sans raison ».

Autorise Ollama Si Windows affiche une notification de blocage au premier téléchargement de modèle, clique sur « Autoriser ». C'est la protection anti-rançongiciel qui empêche Ollama d'écrire les modèles sur le disque. La demande n'apparaît qu'une fois.

Choisir un autre dossier d'installation

Le défaut est %LOCALAPPDATA%\Beaver. Un autre chemin peut être saisi, avec des contrôles stricts ; un chemin non conforme arrête l'installation.

Mettre à jour

Contrairement à macOS et Linux, où le script s'arrête si une installation est détectée, le script Windows ne fait pas ce contrôle : l'installeur NSIS gère lui-même le remplacement. La voie normale reste la mise à jour intégrée à l'application : Mise à jour.

Désinstaller

L'installeur NSIS pose un désinstalleur : la suppression passe par Paramètres › Applications, ou par le désinstalleur du dossier d'installation. Les données restent dans C:\Users\<utilisateur>\.local\share\cl-go-dash\, et la clé maîtresse du coffre reste protégée par DPAPI.
