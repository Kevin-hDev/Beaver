Le centre d'extensions

Une extension ajoute des capacités à Beaver : des outils pour l'agent, des skills, des ressources, des éléments d'interface. Cette page couvre le cycle complet — trouver, ajouter, approuver, activer, mettre à jour, supprimer — et dit sans détour ce que tu engages en installant du code écrit par quelqu'un d'autre.

Ce qu'une extension peut faire à ta machine

Une extension, c'est du code écrit par quelqu'un d'autre, que Beaver exécute sur ton ordinateur avec les droits de ton compte. Il peut lire et écrire tes fichiers, lancer des programmes et utiliser le réseau, exactement comme un logiciel que tu installerais toi-même.

Attention Une extension n'est pas dans un bac à sable. Beaver isole chaque extension dans son propre processus : cela empêche l'une de faire tomber les autres, cela ne l'empêche pas de faire ce qu'elle veut de ta machine. La documentation technique de Beaver l'écrit elle-même — « une extension personnalisée est du code local de confiance, exécuté avec les droits du compte utilisateur. Ce n'est pas une sandbox » — et cette page ne l'adoucit pas.

Deux conséquences directes. Une extension approuvée peut demander tes clés d'API et tes jetons directement, par l'interface du kit de développement : l'approbation porte sur tout son code et toutes ses dépendances, et il n'existe pas d'autorisation clé par clé. Et Beaver ne vérifie pas ce que fait une extension : il valide le manifeste et le protocole, ce qui ne remplace pas un audit du comportement. Le manifeste d'une extension Node.js déclare d'ailleurs access: "full", et le code commente pourquoi : du code Node.js local ne constitue pas une frontière de sécurité.

Ce que l'isolation apporte malgré tout est réel : un processus séparé par extension tierce, donc le plantage de l'une n'arrête pas les autres ; une identité attribuée par Beaver et non déclarée par l'extension, donc aucune ne peut se faire passer pour une autre ; un environnement de processus minimal, donc tes variables d'environnement ne sont pas transmises ; une empreinte des fichiers, qui révoque l'approbation dès qu'un fichier change ; et un journal d'accès aux secrets, qui trace chaque remise sans écrire le secret.

Plugin officiel ou extension personnalisée

L'écran distingue deux choses qui n'ont ni la même origine ni le même niveau de confiance. C'est la distinction à tenir avant tout le reste.

Quatre plugins officiels sont livrés avec Beaver 1.2.2, tous activés et affichés dans le chat par défaut : Documents (beaver.office.documents) pour créer et modifier des DOCX éditables, PDF (beaver.office.pdf) pour lire, créer, fusionner et vérifier des PDF, Feuilles de calcul (beaver.office.spreadsheets) pour les classeurs XLSX, et Présentations (beaver.office.presentations) pour créer des PPTX et remplir des modèles. Dans l'application, le type est écrit en toutes lettres sous le nom : Plugin officiel ou Extension locale.

Où trouver une extension

Note Il n'existe pas de catalogue intégré ni de place de marché. Aucune extension ne t'est recommandée, et aucune n'est vérifiée à ta place. Tu apportes le code, tu en réponds. Trois questions valent d'être posées avant d'installer : sais-tu qui a écrit ce code et peux-tu le vérifier ? Peux-tu lire ce qu'il fait avant de l'approuver ? Cette extension a-t-elle une raison légitime de demander tes clés d'API ?
Les quatre sources acceptées
SourceCe que tu fournis
Fichier localUn fichier JavaScript, TypeScript ou un manifeste JSON
Dossier localUn dossier contenant un manifeste Beaver ou un package.json
Dépôt GitUne adresse HTTPS ou SSH, éventuellement suivie de #branche, #tag ou #commit
Package npmUn nom publié, par exemple @exemple/extension ou extension@latest

Le sélecteur de fichiers accepte js, mjs, cjs, jsx, ts, mts, cts, tsx, mtsx, ctsx et json. Côté Git, sont refusés le HTTP non chiffré et toute adresse contenant des identifiants. Un détail qui compte pour la suite : une extension ajoutée depuis un fichier ou un dossier local n'est pas copiée — Beaver charge la source là où elle se trouve chez toi. Une extension venue de Git ou de npm est copiée dans ~/.local/share/cl-go-dash/extension-installs/, et c'est cette copie que Beaver exécute.

Ajouter une extension

  • Ouvre l'écran. Réglages › Extensions. Trois onglets : Plugins, Extensions, Hôte — l'hôte étant le processus séparé qui exécute le code des extensions.
  • Place-toi sur l'onglet Extensions. Le bouton Ajouter n'apparaît que là : les plugins officiels ne s'ajoutent pas, ils sont livrés.
  • Clique sur Ajouter. La fenêtre affiche d'abord un avertissement, avant toute option : « Le code sélectionné s'exécutera avec les droits de votre compte utilisateur. Installez uniquement une extension à laquelle vous choisissez de faire confiance. »
  • Choisis la source parmi Choisir un fichier, Choisir un dossier, Installer depuis Git, Installer depuis npm.
  • Laisse l'installation travailler. Elle s'exécute en arrière-plan : tu peux fermer la fenêtre et continuer, fermer le suivi n'annule rien. Le suivi apparaît sur la page Extensions et dans le panneau de notifications. Les étapes affichées : Recherche de la source, Téléchargement, Installation des dépendances, Vérification, Préparation de l'interface, Finalisation, Nettoyage. Une seule installation travaille à la fois ; la ligne en attente indique laquelle la bloque.
  • Réponds à la demande de volume, si elle apparaît. Au-delà de 1 Gio occupé par l'installation, Beaver arrête les écritures et propose Continuer l'installation ou Annuler. Il conserve une réserve de 1 Gio d'espace libre. Aucun délai ne vaut accord : une demande sans réponse reste en attente indéfiniment.
  • Ouvre la fiche créée. L'extension apparaît dans la liste — et elle ne fait rien. Son état est Désactivée, elle n'est pas approuvée. C'est voulu. La fiche affiche l'état, le niveau d'API (Stable ou Avancé), le runtime, l'auteur, le mode d'installation, la source, et le bouton Ouvrir la source qui montre le code réellement chargé.

Installer, puis faire confiance

C'est le point le plus important de cette page. Installer ne donne aucun droit. Le code refuse formellement d'activer une extension non approuvée si la confirmation n'accompagne pas la demande ; côté interface, basculer l'interrupteur d'une extension non approuvée n'active rien, cela ouvre une fenêtre de confirmation. Elle affiche le titre « Activer {nom} ? », le texte « Cette extension aura un accès total aux données, secrets et fonctions de votre compte. Beaver ne l'a pas auditée. », et deux boutons : Annuler et Faire confiance et activer.

Attention Approuver, c'est tout approuver d'un coup. L'approbation porte sur tout le code de l'extension et sur toutes ses dépendances. Il n'existe pas d'autorisation par clé, par fichier ou par dossier. Une extension approuvée peut demander tes clés d'API et tes jetons directement, sans nouvelle question.

Si le manifeste déclare un module d'interface en mode advanced, la fenêtre ajoute un paragraphe — « Son module d'interface avancé s'exécute directement dans Beaver et peut modifier, consulter ou casser toute l'interface. » — et une case à cocher obligatoire. Le bouton de confirmation reste inactif tant qu'elle n'est pas cochée. Une interface avancée partage la même page que celle de Beaver, avec les mêmes droits : si tu ne sais pas pourquoi une extension a besoin de ce niveau, ne l'active pas.

Au moment où tu confirmes, Beaver calcule l'empreinte des fichiers, la stocke et note la date d'approbation, affichée ensuite sous Approuvée depuis. Elle couvre les sources JavaScript et TypeScript, le manifeste et l'artefact d'interface ; les liens symboliques sont refusés, la comparaison se fait en temps constant, et les limites sont de 2 000 fichiers, 4 Mio par fichier, 32 Mio au total, profondeur 16.

Note L'empreinte ne couvre pas node_modules ni .git. Une dépendance modifiée localement ne redéclenche donc pas de demande d'approbation. Le raccourci du menu + du champ de saisie, lui, mène exactement à la même fenêtre de confirmation : ce n'est pas une porte dérobée.

Activer, désactiver, afficher dans le chat

Activer rend les outils de l'extension disponibles à l'agent et lance son processus. Désactiver marque l'extension désactivée dans le registre — ce changement est écrit sur le disque avant l'arrêt du processus —, efface les permissions accordées pendant les conversations, puis arrête le processus. L'approbation survit à la désactivation : réactiver ensuite ne redemande rien, tant que les fichiers n'ont pas changé.

Sécurité Désactiver ne récupère pas ce qui est déjà parti. Si une extension a obtenu une de tes clés, la désactiver ou la supprimer ne l'annule pas : elle a pu en garder une copie. Beaver te le rappelle — « Par précaution, changez auprès de leur fournisseur les accès utilisés par cette extension. » La seule action efficace est de révoquer la clé chez le service concerné.

Chaque extension porte un second interrupteur, Afficher dans le chat, indépendant de l'activation. Il ne change rien aux capacités du modèle : il ajoute un raccourci d'activation dans le menu + du champ de saisie, qui n'existe qu'en mode Agent. Ce menu affiche huit lignes avant de devenir défilable — c'est une hauteur d'affichage, pas une limite d'extensions. Par défaut : activé pour les quatre plugins officiels, désactivé pour toute extension ajoutée.

Mettre à jour et recharger

Seules les extensions installées depuis Git ou npm ont un bouton Mettre à jour. Une extension venue d'un fichier ou d'un dossier local n'en a pas : c'est toi qui possèdes la source. Le bouton demande une confirmation en deux temps, sous un avertissement permanent : « La mise à jour désactivera l'extension. Examinez sa nouvelle version avant de lui refaire confiance. » Beaver prépare alors une nouvelle copie à côté de l'ancienne et ne remplace qu'après validation ; l'empreinte change, donc l'approbation est révoquée, l'extension passe en Erreur avec le message « Les fichiers de l'extension ont changé et doivent être vérifiés à nouveau ». Une mise à jour qui change l'identité de l'extension est refusée. Aucune mise à jour automatique n'existe.

Pour une extension liée à un fichier ou à un dossier de ta machine, Recharger applique tes modifications. Deux conséquences surprennent : Recharger redémarre l'hôte entier, donc toutes les extensions s'arrêtent et se rechargent ensemble ; et tes modifications font changer l'empreinte, donc les extensions locales modifiées sont révoquées, désactivées, et redemandent une approbation.

Note Développer une extension te fait repasser par la confiance à chaque rechargement. Ce n'est pas un défaut : c'est exactement la garantie qui protège les utilisateurs qui, eux, ne modifient jamais leur code.

Supprimer

Le bouton Supprimer demande une confirmation en deux temps. Beaver efface les permissions de conversation, écrit la désactivation sur le disque avant d'arrêter quoi que ce soit — ainsi un processus dont l'arrêt n'est pas confirmé ne peut jamais redevenir actif au redémarrage suivant —, arrête le processus et attend la confirmation de cet arrêt, retire l'extension du registre, supprime son artefact d'interface, puis la copie gérée si l'installation venait de Git ou npm.

Ce que la suppression ne fait pas : elle ne touche pas à ton fichier ou à ton dossier si l'extension était locale ; elle ne récupère aucun secret déjà remis ; elle ne supprime pas les fichiers que l'extension aurait écrits ailleurs pendant qu'elle tournait. Les copies gérées devenues orphelines sont nettoyées au démarrage suivant.

Attention La suppression n'est pas annulable. Beaver ne propose pas de restaurer une extension supprimée. Pour une installation Git ou npm, il faudra la réinstaller depuis sa source ; pour une extension locale, ton fichier ou ton dossier est intact.

Quand une extension plante

L'ordre de dépannage, du moins engageant au plus radical : lire le diagnostic dans Réglages › Extensions › Hôte ; ouvrir la fiche pour voir l'état, la source et la dernière erreur ; Ouvrir la source pour auditer le code réellement chargé ; Recharger après une correction locale, ou Mettre à jour pour une installation Git ou npm ; Désactiver l'extension ; Redémarrer l'hôte si le runtime lui-même est en erreur ; Supprimer si tu ne lui fais plus confiance.

L'onglet Hôte affiche l'état (Arrêté, Démarrage, En cours, Erreur), les versions de Node.js, de Jiti et de l'API Beaver, le nombre d'extensions actives, et les Dernières erreurs de chargement avec l'identifiant de l'extension fautive et le fichier concerné. Deux boutons y vivent : Redémarrer l'hôte et un Mode de récupération qui « désactive les plugins Beaver et les extensions locales afin de retrouver un Beaver fonctionnel ».

Un plantage n'entraîne pas les autres. Beaver redémarre automatiquement un hôte au plus 3 fois sur une fenêtre de 5 minutes, puis cesse d'essayer. Si Beaver s'est arrêté pendant le chargement d'une extension, un parcours de récupération apparaît au démarrage suivant, avec quatre issues : Ouvrir la fiche, Garder désactivée, Réessayer le chargement, Restaurer le registre précédent. Si une interface avancée empêche Beaver de s'ouvrir, quitte complètement l'application puis maintiens Maj pendant le redémarrage — sous Linux avec Wayland, la touche est demandée après l'apparition de la fenêtre. L'exécutable accepte aussi un argument dédié.

$ beaver --safe-mode

Ce lancement n'affiche aucune interface tierce et laisse l'écran Extensions accessible pour désactiver le module fautif. Si le registre lui-même est illisible ou vient d'une version plus récente de Beaver, l'application refuse le registre entier plutôt que de le remplacer par une liste vide : tes fichiers sont conservés, toute modification d'extension est bloquée, et les conversations continuent avec les seuls outils internes et un avertissement. Enfin, les sorties brutes d'une extension ne sont jamais conservées, parce qu'elles peuvent contenir des secrets : les diagnostics donnent l'étape, la catégorie et la position, pas le contenu.

Ce que l'écran Outils ne montre pas

Sur la fiche d'une extension, la section Contributions enregistrées liste chaque outil déclaré avec son nom technique, sa classe d'effet traduite — Lecture seule, Écriture locale, Lecture externe, Écriture externe, Processus, Accès aux secrets, Effet inconnu — et, le cas échéant, la mention Remplace un outil intégré. Une section Skills et ressources liste les skills et ressources déclarés.

Note L'écran Réglages › Outils ne dit pas tout : aucun outil d'extension n'y figure. Ces outils sont dynamiques et se pilotent uniquement depuis la fiche de leur extension. Et les trois outils internes par lesquels l'agent découvre les extensions — list_extensions, inspect_extensions, load_extension_resource — sont toujours actifs et n'apparaissent dans aucun écran. Ce n'est pas un trou de sécurité, ils ne font que lister et lire ce que tu as approuvé, mais mieux vaut le savoir. Voir Vue d'ensemble des outils.

Un dernier réglage à connaître : Plugins prioritaires. Quand les définitions des extensions dépassent 10 % de la fenêtre de contexte du modèle, Beaver ne les envoie plus toutes et bascule en découverte progressive. Tu peux désigner jusqu'à 15 plugins à garder disponibles en priorité.
