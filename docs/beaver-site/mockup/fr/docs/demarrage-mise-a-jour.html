Mettre à jour Beaver

Beaver se met à jour depuis les releases de son dépôt GitHub, après avoir vérifié quatre éléments du fichier téléchargé. Cette page dit comment ça se déclenche, ce qui est contrôlé, et ce qui reste intact.

Comment les mises à jour sont détectées

Beaver interroge la dernière release publiée du dépôt GitHub officiel, au lancement puis toutes les heures, et compare ta version locale au tag de la release. Quand une mise à jour existe, une notification apparaît, avec une barre de progression pendant le téléchargement.

Cette vérification fonctionne sans authentification parce que le dépôt est public : c'est une contrainte assumée du projet.

Ce qui est vérifié avant installation

C'est ce qui explique qu'une mise à jour puisse être refusée. L'asset attendu dépend du système : .dmg sur macOS, .deb sur Linux, -setup.exe sur Windows. Beaver exige que le fichier update-manifest.json de la release confirme quatre éléments :

  • la même version que celle annoncée ;
  • le même nom de fichier ;
  • la même taille ;
  • l'empreinte SHA-256 attendue.

Si un seul de ces éléments ne correspond pas, la mise à jour n'est pas proposée. Le téléchargement est plafonné en taille, et l'empreinte est revérifiée après réception. Le principe : en cas de doute, Beaver refuse de se mettre à jour plutôt que d'installer un fichier non vérifié.

L'installation selon le système

Un point commun aux trois systèmes : Beaver copie un programme d'assistance autonome dans un fichier temporaire, se ferme, et laisse ce programme faire le travail. L'assistance attend la fermeture complète de l'application avant de toucher quoi que ce soit, et n'utilise aucun shell intermédiaire.

Point important si tu as installé Beaver ailleurs que dans le dossier proposé : la mise à jour remplace l'installation réellement lancée, pas un chemin par défaut. Tu ne te retrouves pas avec deux copies.

Sous Linux, les mises à jour continuent — sécurité, stabilité et dépendances — mais la 1.2.3 est la dernière version qui apporte de nouvelles fonctionnalités à ce système : Installation Linux.

Si l'installation échoue

Si l'application ne redémarre pas après une mise à jour, réinstalle manuellement la dernière version que tu savais fonctionnelle, depuis sa release GitHub. Tes données ne sont pas touchées et sont reprises par la version réinstallée.

Ne pas utiliser le script d'installation Le script de première installation refuse de remplacer une installation existante. Passe par la mise à jour intégrée.

Les mises à jour des modèles Ollama

C'est un mécanisme distinct de celui de l'application, à ne pas confondre avec lui. Beaver liste les modèles installés et interroge le registre pour chaque famille ; la comparaison porte sur les empreintes, pas sur un numéro de version. Les modèles ayant une mise à jour disponible sont signalés, et la vérification est relancée après chaque téléchargement de modèle.

Ce qui n'est jamais touché

C'est la question qu'on se pose avant de cliquer. Une mise à jour ne touche ni tes conversations, ni ta mémoire, ni tes clés API et ton coffre, ni tes réglages, ni tes modèles Ollama téléchargés. Le dossier de données est indépendant de l'application installée.

Tes données sont conservées Une mise à jour ne touche ni tes conversations, ni ta mémoire, ni tes clés, ni tes modèles. Elles vivent dans un dossier séparé de l'application.
