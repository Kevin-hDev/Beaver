Choisir son modèle

Faire tourner un modèle chez toi, payer un service à l'usage, ou utiliser un compte que tu as déjà : trois voies, avec des conséquences différentes sur la confidentialité, le coût et la capacité. Cette page t'aide à trancher.

Les trois voies

Premier point, celui qui dédramatise tout le reste : le choix n'est pas définitif. Il se fait conversation par conversation, et se change en cours de route sans perdre l'historique.

Modèle local via Ollama — installé sur ton disque, exécuté sur le processeur ou la carte graphique. Rien ne sort de la machine.

Modèle distant via clé API — tu crées une clé chez le fournisseur, tu la saisis une fois dans Beaver, les requêtes partent vers ses serveurs, et la facturation se fait à l'usage.

Modèle distant via compte web — pour trois fournisseurs seulement, tu te connectes avec un compte existant au lieu d'une clé. La consommation est imputée à ce compte selon ses propres règles.

Quand choisir le local

  • tes fichiers contiennent des données qui ne doivent être transmises à personne ;
  • tu travailles sans connexion, ou avec une connexion incertaine ;
  • tu refuses une facturation à l'usage ;
  • ta machine dispose d'une mémoire vidéo confortable.

La contrainte réelle est le matériel. Un modèle qui ne tient pas en mémoire vidéo bascule sur le processeur, et le temps de réponse s'allonge nettement. Les correspondances entre taille de modèle et machine sont dans Matériel et VRAM.

Quand choisir un modèle distant

  • la tâche demande un raisonnement long ou une grande fenêtre de contexte ;
  • tu veux des réponses rapides sans immobiliser ta machine ;
  • ton matériel ne suffit pas pour un modèle assez capable ;
  • le contenu traité peut passer chez un fournisseur sans que ça pose problème.

Deux réserves à garder en tête. Les modèles proposés, les quotas et les tarifs sont décidés par le fournisseur et changent sans préavis : réfère-toi à ses propres pages. Et Beaver affiche les informations de compte que le fournisseur accepte de communiquer — la couverture varie de l'un à l'autre.

Expérimental Parmi les trois connexions par compte web, seule celle de Kimi (Moonshot) est marquée expérimentale. Les comptes OpenAI/Codex et xAI ne le sont pas : ne place pas les trois au même niveau de fiabilité.

Combiner les deux

Une organisation qui fonctionne, plutôt qu'une règle : un modèle local pour les tâches courantes, les fichiers sensibles et le travail hors ligne ; un modèle distant pour les tâches qui demandent du raisonnement, sur du contenu non sensible. Côté recherche web, SearXNG en local quand tu veux éviter d'envoyer les requêtes à un tiers, Brave, Exa ou Firecrawl quand tu veux de meilleurs résultats. → Recherche web

Changer de modèle en cours de conversation

Le sélecteur de modèle se trouve dans la barre de saisie, sous la zone de message — pas en haut de la conversation. Changer de modèle ne perd pas l'historique de la conversation en cours.

Trois malentendus fréquents

« Local » ne veut pas dire « gratuit et équivalent ». Un modèle local assez petit pour tourner sur une machine ordinaire est nettement moins capable qu'un modèle distant récent.

Un Ollama déjà installé n'est pas à désinstaller. C'est l'inverse : Beaver détecte le démon existant sur localhost:11434, le réutilise, et les modèles sont partagés.

Configurer une clé API n'envoie rien. Rien ne part tant qu'une conversation n'utilise pas ce fournisseur.

Pour aller plus loin

La procédure de configuration détaillée est dans Fournisseurs API et Connexion par compte. L'installation et la gestion du moteur local sont dans Moteur local. Ce que voit exactement un fournisseur est décrit dans Confidentialité.
